# 推理优化技术

## 一句话结论

自回归解码使推理无法沿序列维度并行，导致生成（decode）阶段受 HBM 显存带宽限制而非算力限制；因此本课全部推理优化技术都指向同一个原则——**在不大幅损害准确率的前提下减少 KV 缓存（与参数）占用的内存**，包括 GQA/MLA/跨层注意力/滑动窗口等架构手段、量化与模型瘦身，以及投机解码、动态批处理（连续批处理/选择性批处理）等算法与系统级技术。

## 核心概念

- **自回归推理（autoregressive inference）**：训练时可一次性看到所有 token 并对整个序列并行化处理；推理时必须一个 token 一个 token 地顺序生成，无法在序列维度上并行化。这是推理与训练截然不同的工作负载的根本原因。
- **KV Cache（键值缓存）**：因果（causal）Transformer 中，已生成 token 的激活值不会因后续附加 token 而改变，因此可在 HBM 中缓存每个序列每个 token 在每一层每个注意力头上的键（Key）与值（Value）向量，后续生成直接复用，避免重算。大小 ≈ token 数 × KV 头数 × 头维度 × 层数 × 2（K 与 V 各一份，BF16 每数 2 字节）。
- **Prefill / Decode（预填充 / 生成）**：推理分两阶段。预填充（T=S）并行编码整个提示词并填满 KV 缓存，受计算能力限制；生成（T=1）逐 token 解码，受内存带宽限制。
- **算术强度（Arithmetic Intensity）**：每传输一个字节对应多少 FLOPs。MLP 层算术强度 ≈ B×T；注意力层算术强度因子为 S×T/(S+T)。生成阶段注意力算术强度 S/(S+1)<1，成为根本瓶颈。
- **内存受限 / 计算受限**：若算法算术强度 > 加速器算术强度（每秒 FLOPs ÷ 内存带宽），则计算受限（好事）；否则内存受限（坏事）。
- **TTFT（首 token 延迟）**：从输入查询到第一个 token 出现的等待时间，对交互式应用重要。
- **延迟 / 吞吐量**：延迟是单用户视角的 token 出现速度；吞吐量是每秒生成的 token 总数（多查询总速度）。两者存在权衡：增大 batch 提升吞吐量但恶化延迟。
- **GQA（分组查询注意力）**：多个查询头共享一组键/值头，把 KV 缓存缩小到原来的 N 分之 K。
- **MLA（多潜在注意力，DeepSeek）**：把激活值投影到低维 C 得到压缩表示并只存储 C，使用时再具体化出 K/V，大幅压缩 KV 缓存。
- **CLA（跨层注意力）**：只在部分层计算 KV，其他层直接复用前一层（或间隔层）的 KV 缓存，即层间共享。
- **滑动窗口注意力**：每个 token 只关注最近 K 个 token，KV 缓存与序列长度无关，特别适合长上下文；但会降低表达能力、损害准确率。
- **线性注意力（Mamba / DeltaNet / Gtone 等）**：把全部历史 KV 累加/压缩成单一向量，计算量独立于序列长度；但对"大海捞针"式长程精确检索会丢失信息。
- **量化（Quantization）**：降低数值精度（FP16→NF4 等）以减少内存占用，从而提升延迟与吞吐量；有量化感知训练（QAT）与训练后量化（PTQ，如 GPTQ、激活感知量化）。
- **模型瘦身（剪枝 + 蒸馏）**：估算各部分重要性后移除层/隐藏单元，再用蒸馏后训练修复（如 15B→8B）。
- **投机解码（Speculative Decoding）**：用廉价草稿模型先采样 k 个 token，目标模型并行校验，以 min(1, Q/P) 概率接受，拒绝时从残差分布采样——数学上保证最终分布与目标模型精确一致，是无损方法。
- **连续批处理（Continuous Batching）**：批次动态更新——完成的序列弹出、新请求加入，逐步为所有序列各解码一个 token。
- **选择性批处理（Selective Batching）**：注意力因序列长度不同无法共享张量，但 MLP 层（占大量计算）可把所有序列拼接成巨型序列统一处理。
- **PagedAttention（分页注意力）**：借鉴操作系统分页，把 KV 缓存切成非连续块并带索引追踪，解决内部/外部碎片化，支持前缀共享与写时复制语义。

## 工作机制

- **朴素自回归**：把提示词输入 Transformer → 生成 logits → 采样一个 token → 拼回序列 → 重复。每生成一个 token 都要重新为前面所有 token 计算 KV 与激活值，复杂度为 O(t²)（注意力本身二次，且每步重算）。
- **带 KV Cache 的流程**：prefill 阶段并行编码提示词并填充 KV 缓存（与训练一样可并行）；decode 阶段把新 token 送进模型，利用缓存同时产出下一 token 分布与新 KV，追加进缓存后循环。
- **瓶颈成因**：MLP 权重对所有序列共享（不依赖 B），权重只需加载一次即可处理全部序列，故 B 大有用；注意力层每个序列有独立的 KV 缓存（依赖 B），B 大无法摊薄，算术强度不能随 B 扩展，生成阶段注意力因此成为内存带宽瓶颈。
- **投机解码流程**：草稿模型 p 采样 k 个 token → 目标模型 q 并行计算这些草稿 token 的 logits → 依 min(1, q/p) 概率逐个接受，被拒时从残差分布采样（保证得到目标模型精确样本）。草稿太少无法充分利用目标模型批处理，太多则拒绝率上升，存在最佳点。
- **连续批处理**：为每个请求各自维护 KV 缓存并逐步解码；一个序列结束即弹出、新请求到达即加入，批次动态更新。
- **PagedAttention**：KV 缓存按固定大小的块非连续存放；相同前缀可共享同一块（如系统提示词只算一次）；生成多个续写时共享前缀块，采样到不同 token 才分裂（写时复制语义）。

## 示例或代码

- **H100/Llama 13B 数值示例**（转录中带宽亦提及 H200）：batch=1 时延迟约 0.008 秒/token，吞吐量约 124 token/s；增大 batch 后延迟上升（KV 缓存变大）、吞吐量提升但趋于渐近线，且受显存上限约束（H100 装不下时换 B100 等更大显存设备才能进一步增大 batch）。
- **自回归 vs KV Cache 对比示意（伪代码，非转录原文）**：

```
# 朴素版：每步重算全序列
while not eos:
    logits = transformer(prompt)      # 为全部历史 token 重算 KV/激活值
    token = sample(logits)
    prompt += token

# KV Cache 版
kv_cache = prefill(prompt)            # 并行填充
while not eos:
    logits, new_kv = transformer(token, kv_cache)
    kv_cache += new_kv
    token = sample(logits)
```

- **投机解码示例**：草稿模型先采样 4 个 token，目标模型并行校验这一批，接受其中与目标分布一致的前缀部分，在被拒处从残差分布重采样；示例中最佳草稿数量为 3–4 个。

## 常见误区

- 误区：推理慢是因为算力不够。澄清：生成（decode）阶段受 HBM 内存带宽限制而非算力限制，算术强度低至 1；只有预填充阶段才是计算受限。
- 误区：一切提速手段都会牺牲准确率。澄清：投机解码（推测性采样）是无损的——其论证与拒绝采样相同，数学上保证最终样本来自目标模型的精确概率分布。
- 误区：延迟和吞吐量总此消彼长。澄清：矛盾主要由 batch（B）维度引起；只要减少内存用量（更小 KV 缓存、量化），延迟和吞吐量可以同时改善。
- 误区：把模型维度调小就等于压缩 KV 缓存。澄清：讲师猜测"不加区分地缩减一切"只会更糟；关键是找到模型里可压缩的地方（如 MLA 压缩 KV 维度），且只能靠大量实验验证。
- 误区：GQA 是免费的午餐。澄清：DeepSeek 论文表明 GQA 实际上有害；对准确率的结论要持保留态度，因为它们只针对特定模型。
- 误区：连续批处理把不等长请求强行拼成等长张量。澄清：注意力张量形状取决于序列长度、无法共享；做法是逐序列解码并动态出入批次（连续批处理），仅 MLP 部分可拼接统一处理（选择性批处理）。

## 详细章节

### 自回归推理与训练的本质差异

训练时（如监督微调）可一次性看到所有 token 并对整个序列并行化处理，因为 Transformer 的注意力计算和 MLP 中序列只是一个被乘的大张量维度；推理时由于自回归属性必须一个 token 一个 token 地顺序生成，无法在序列维度上并行化，导致难以达到高计算强度。推理成本是每天反复承担的一次性成本，而训练是（昂贵的）一次性成本；在智能体场景下大部分生成的 token 并非给人读，因此推理效率无上限地重要。

### 算术强度与瓶颈分析

算术强度 = FLOPs ÷ 传输字节数。MLP（本质是若干大矩阵乘法）算术强度 ≈ B×T；只要 prefill 阶段用大 batch 和长序列即可保持高算术强度，生成阶段 T=1 时 MLP 算术强度降为 B（即并发请求数），需要大量并发才够用。注意力层算术强度因子为 S×T/(S+T)：prefill（T=S）时 S/2，只要序列长就很好；生成（T=1）时 S/(S+1)<1，算术强度约为 1。原因在于 MLP 权重是序列间共享的（不依赖 B），而注意力层的 KV 缓存逐序列独立（依赖 B），做更多矩阵乘法也无济于事。结论：预填充阶段受计算能力限制，生成阶段受内存带宽限制；"推理是受内存限制的"这一说法即由此而来。

### KV Cache：原理与显存占用

朴素方法每生成一个 token 都要花费 O(t) 时间（t 为已生成 token 数），生成 t 个 token 总复杂度 O(t²)。由于因果 Transformer 的激活值不会因附加 token 而改变，不同前缀之间可共享大量计算，最直接做法是在 HBM 中存储 KV Cache。形式化定义：对每个序列（B 个）、每个 token（S 个）、每一层、每个 head 存储一个 h 维向量。总内存 = 参数（BF16 下为参数数量的 2 倍）+ B×（序列 token 数 × KV 头数 × 头维度 × 层数 × 2 字节）。KV 缓存随 B 线性增长；batch 足够大时其内存甚至可能超过参数。

### 推理指标：TTFT、延迟与吞吐量

- TTFT：首 token 延迟，交互式应用关键（用户只能干等）。
- 延迟：单查询 token 出现速度；吞吐量：每秒生成 token 总数，对批量处理有用。二者密切相关但存在权衡。
- 在内存受限的假设下（通信与计算重叠），延迟由需要传输的内存量决定，是 B 的线性函数；吞吐量 ≈ B/(B+常数)，随 B 增大而提升但趋向渐近线，且受显存上限约束。
- 小 batch 延迟好、吞吐量差；大 batch 吞吐量好、延迟差。目标场景决定取舍。

### 减少 KV 缓存：GQA / MLA / CLA / 滑动窗口 / 线性注意力

- **GQA**：查询头共享键/值头，KV 缓存缩小到 N 分之 K。MHA（K=N）时间开销高；MQA（K=1）效果差、没人用；K 介于之间（如 8）是精度与速度的平衡。减少内存占用带来速度提升（因受内存限制），且可腾出显存把 batch 加大，进一步做吞吐量权衡。
- **MLA（DeepSeek）**：KV 数量保持每 token 一份，但把激活值投影到低维 C（如从约 6000 降到 512）只存储压缩表示，用键值时再具体化。由于 MLA 直接作用在键值上的 RoPE 不兼容，DeepSeek 在处理 RoPE 时额外增加了一些维度。效果甚至略好于 MHA。
- **CLA（跨层注意力）**：只对部分层计算 KV，其他层复用前面层的 KV 缓存，在层间共享，能改善帕累托前沿。
- **滑动窗口注意力**：每 token 只看最后 K 个 token，KV 缓存与序列长度无关；层数多时实际上下文长于标称。可做全局+滑动窗口混合、交错局部/全局注意力等变体，但会损害准确率（无免费午餐）。
- **线性注意力**：把历史 KV 压缩为单一向量（Mamba、DeltaNet、Gtone 等），计算量独立于序列长度；但长上下文"大海捞针"式精确检索会丢失信息，且讲师认为它比滑动窗口有更大发展空间。
- 通用原则：减少 KV 缓存能直接带来吞吐量和延迟改善，关键在于不损害准确率。

### 量化与模型瘦身

- **量化**：降低数值精度（FP16→NF4），更少内存 → 更高延迟与吞吐量。量化感知训练（QAT）在前向传播中不断量化/反量化以模拟量化误差、让权重适应量化，但需昂贵的大规模重新训练；训练后量化（PTQ）成本低，朴素做法（逐层/逐张量定缩放因子与零点）效果通常不好。
- **GPTQ**：利用校准信息对某一层量化，并持续追踪传播到未量化权重里的误差加以修正。
- **激活感知量化**：观察到某些激活通道值较大、对应权重更重要，故为少数重要通道分配更高精度（如 FP16），其余用 NF3。
- **模型瘦身（NVIDIA 论文）**：用校准集估算各隐藏单元/层的重要性（观察激活值大小，死单元接近零），剪掉不重要部分后用蒸馏/后训练修复。能把 15B 模型缩减为 8B，对准确率影响不大，训练计算量也少得多；本质上是"通过训练减少 KV 缓存，只是用大模型的部分权重做初始化"。
- 目标是：不牺牲准确率的前提下降低推理复杂度（减少参数数量或 KV 缓存大小）。

### 投机解码

- 动机：预填充可并行处理所有 token（计算密集、很快），生成阶段逐个来；检查一个序列比生成一个序列快得多，可利用这种不对称性。
- 流程：草稿模型 p 采样 k 个 token → 目标模型 q 并行计算这些草稿 token 的 logits → 以 min(1, q/p) 概率接受，否则从已知残差分布采样（与拒绝采样论证相同，但被拒时仍能保证拿到目标模型精确样本）。
- 草稿 token 太少无法充分利用目标模型批处理，太多则拒绝率上升，存在最佳点（示例中 3–4 个）。
- 草稿模型通常远小于目标模型，理想情况下应蒸馏使其尽可能接近目标模型；此前讨论的减少 KV 缓存思路同样适用于草稿模型。后续已有大量改进文献。

### 动态批处理：连续批处理与选择性批处理

- 动态工作负载：请求到达时间不同、共享前缀不同、长度各异，远不像训练那样一次性拿到等长 token 批。
- **连续批处理**（源自 ARCA 等早期系统）：逐步为所有序列各解码一个 token，序列结束即弹出、新请求到达即加入，批次动态更新。
- **选择性批处理**：注意力张量形状取决于序列长度、无法在不等长序列间共享；但 MLP 层（占大量计算）可把所有序列拼接成一个巨型序列统一处理。

### PagedAttention 与 KV 缓存管理

- 问题：KV 缓存存储有碎片化——内部碎片化（按最大 token 上限如 7024 预分配整块缓冲，实际用不满，浪费）与外部碎片化（请求间的空隙太小无法利用）。
- 方案：借鉴操作系统分页，把一个序列的 KV 缓存划分成非连续块，带索引追踪每块位置；相同前缀（如系统提示词、同一提示词的多个续写）可共享同一块 KV 缓存，只需加载/计算一次；多个续写采样到相同 token 时继续共享块，采样不同 token 时再分裂（写时复制语义）。此外还有大量内核优化，总体思路是借用操作系统的概念管理推理过程。
- 本部分为系统/服务层内容，详见 [[llm-inference-deployment]]。

### 总结与展望

推理与训练非常不同（即使同一模型），高度受限于内存带宽且是动态的。改进技术包括量化、新架构、剪枝与蒸馏、推测性采样等，共同原则都是减少 KV 缓存且不过度损害准确性；系统侧还借用了分页、推测执行等操作系统概念。讲师认为新架构（状态空间模型、线性注意力、扩散模型等）有巨大改进潜力——KV 缓存与注意力机制的构建方式从根本上让 Transformer 成为对推理不太友好的架构，设计非为推理优化的新架构可能释放巨大潜力。
