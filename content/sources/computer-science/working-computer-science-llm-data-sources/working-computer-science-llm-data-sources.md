# 预训练数据源

## 一句话结论

预训练数据的**来源、组成与规模**是语言模型的真正核心竞争力：大多数模型都采用大致相同的 transformer 架构，但数据从哪里来、如何组合直接决定模型最终质量（cs336-p13："数据是区分不同语言模型的关键性要素"）。数据不是"从天上掉下来的"，最上层是互联网——它由分布全球的实时服务器组成，理论上可爬取，但受动态内容/登录付费墙（围墙花园）、robots.txt、服务条款与版权等多层约束，实际能合法获取的内容远小于整个互联网；从 BERT 时代"维基百科+书籍"到 Llama 3 的 15 万亿 token、Qwen3 的 36 万亿 token，数据规模爆炸式增长，而原始 Common Crawl 可达约 200 万亿 token 量级。

## 核心概念

- **预训练数据（Pretraining Data）**：预训练阶段从网络等来源获取的原始文档，用于训练基础模型。与中期训练（更高质量数据、增强某些能力与长上下文）、后训练（聊天记录、指令、RL 环境）区分（00:02-00:03）。
- **Common Crawl**：2007 年起存在的非营利网络爬虫项目，每月爬取约 30-50 亿网页、累计约 3000 亿页面（数据转储约 20 亿网页/372TB，不含图片），是绝大多数网页预训练语料的原始来源。
- **WebText**：GPT-2 构建的高质量网页数据集（约 40GB/100 万页），通过"Reddit 帖子 karma>3 的外链"启发式筛选，从未公开，后有开源复刻。
- **BookCorpus**：源自 Smashwords 免费电子书的书籍语料，BERT 时代预训练使用，后因违反服务条款被下架（"免费可得 ≠ 法律允许"）。
- **围墙花园（Walled Garden）**：需登录/付费才能访问的站点内容（Facebook、X、LinkedIn、NYT），爬虫无法访问，但拥有方（如 Facebook）自己有数据可直接训练。
- **影子图书馆（Shadow Library）**：Libgen、Anna's Archive 等无视版权、绕过付费墙提供受版权保护书籍/文章的网站，收到大量下架令与诉讼，法律上通常属盗版。
- **合理使用（Fair Use）**：无许可证也可使用受版权作品的情形，由四个因素决定（使用目的/性质、作品性质、使用篇幅、对原作市场的影响）；训练模型在直觉上带有"转换性使用"意味，与逐字再托管不同。
- **知识共享许可（Creative Commons）**：2001 年创建，让受版权作品可被自由分发，像公有领域一样使用；维基百科、arXiv 多数论文等属此类。
- **多语言/低资源语言数据**：CCNet 等早期工作用语言识别分类器只保留需要的语言，避免依赖只适用于英语的人工流程。

## 工作机制

（本页聚焦"数据从哪来、由什么组成、规模多大"；获取后的过滤/去重/清洗流水线见 [[llm-data-pipeline]]）

1. **原始获取**：模型开发者自建爬虫（从种子网页出发、沿超链接下载），或直接使用 Common Crawl 的公开转储（WARC 原始 HTTP 响应 / WET 处理后纯文本）。爬取受动态内容、登录付费墙、robots.txt、Cloudflare 反爬、服务条款、版权等多层约束。
2. **数据源选择**：通用网络之外，专门挑选高质量区域——维基百科（百科/事实）、GitHub（代码）、arXiv（论文）、Stack Exchange（问答+投票元数据）、Project Gutenberg/Books（书籍）、Enron 邮件等。
3. **组成与分布**：Web 并非均匀分布，不能"随机抓取"就构成数据集；不同训练阶段用不同数据源——预训练（网页文档、学术论文、数学页、证明）→ 中期（更高质量网页、指令、合成数据）→ 后训练（聊天记录、更多数学推理与编码、安全处理）。
4. **规模控制**：从 Common Crawl 约 200 万亿 token 过滤缩减到不足 3 万亿 token，过滤是影响质量最重要的环节之一（详细方法见 [[llm-data-pipeline]]）。
5. **合规约束**：全程需权衡 robots.txt/服务条款（技术+法律限制随时间增长）、版权（许可证 vs 合理使用）；"训练"已趋向被裁定为合理使用，但"盗版"行为本身违法。

## 示例或代码

（数据源实例与数量级，具体见详细章节）

- **Common Crawl**：单次转储约 20 亿网页 / 372TB 纯文本（不含图片）；累计约 3000 亿页面。
- **规模演进**：BERT≈维基百科+BookCorpus（约 3GB 量级）→ GPT-2 WebText 40GB → C4 1560 亿 token/800GB → GPT-3 约 4000 亿 token/500GB → LLaMA1 1.2 万亿 token → RefinedWeb 约 5 万亿 / FineWeb 15 万亿 token → DCLM 3 万亿 → Nemotron 6 万亿。
- **当代旗舰**：Llama 3 在 15 万亿 token 上训练；Qwen3（转录作"Q13"）在 36 万亿 token 上训练。
- **来源实例**：GitHub 4.2 亿仓库（2800 万公开）；arXiv 约 300 万份提交；Stack Exchange 2008 年起、问答格式含投票元数据；Project Gutenberg 1971 年启动、只收录版权许可/公有领域书籍。

## 常见误区

- **误区：所有语言模型都是在"整个互联网"上训练出来的。** 澄清：更准确说是"在公共万维网上训练"，且因动态内容、深网、登录付费墙、robots.txt、服务条款与版权，实际可合法获取的内容远小于整个互联网（00:04-00:09）。
- **误区：免费可得 = 合法可用。** 澄清：BookCorpus 免费但违反服务条款被下架；影子图书馆免费但属盗版；"仅仅因为它是免费的并且你可以获取它，并不意味着它在法律上是允许的"（00:36-00:37）。
- **误区：版权问题只关乎逐字记忆/N-gram 重叠。** 澄清：情节与角色也可受版权保护（如不能复制 Harry Potter 角色）；合理使用还关乎"转换性"与经济影响（00:19-00:21）。
- **误区：维基百科里没什么新东西（因为内容都已存在于网上）。** 澄清：并非如此——它可以引用书籍，而书籍通常不易获取（00:29-00:30）。
- **误区：各家的 token 数可以直接对比。** 澄清：报告的数字可能重复计算——"如果你训练了多个Epoch，比如两个Epoch，那Token数就是原来的两倍"；唯一 token 数并不清楚，阅读时要小心（00:54-00:55）。
- **误区：只要训练就是合理使用、可以随便用数据。** 澄清：目前新裁决范围都很窄——"这并不意味着对任何版权内容的训练都是合理使用"；训练被裁定为合理使用与"盗版行为本身违法"是两件事（00:22-00:24）。

- **"Q13 是在 36 万亿 Token 上训练的"**：ASR 转写应为 Qwen3，36T 数字需对照 Qwen3 官方技术报告核对。

## 详细章节

### 为什么数据是核心竞争力

- **保密即证据**：以 Llama 3 为例——开放权重模型对架构完全透明、甚至公开训练流程，"但对数据却什么都不说"，只说"我们在多种数据语言上进行了训练，还做了一些处理"。保密理由有二：其一数据是竞争秘方、关系到竞争态势；其二是版权责任（承认用了某些类型的数据可能被起诉）。
- **数据是永远存在的瓶颈**：数据工作从监督学习的"标注"转向预训练的"整理与清洗"，但本质未变；"数据一直是瓶颈，而且永远会是瓶颈"，因为它是随人力投入扩展的长期问题——架构/系统工作人数有限，而"训练一个试图做所有事情的基础模型"很容易让数据工作陷入瘫痪，所以数据团队与模型开发者规模相当。
- **数据是区分要素**：总结时明确"数据是区分不同语言模型的关键性要素"，多数模型采用大致相同的 transformer 架构，但数据处理方式不同会带来相当大的差异。

### 数据从哪来：网络爬取与现实约束

- **爬取机制**：爬虫从一组种子网页出发发现外部网页、边爬边下载，本质是"图遍历"（取 URL→下载→找超链接→入队），在多机上并行。
- **技术限制**：①动态内容/深网——很多网站是应用，URL 无法完整描述内容，需点击/提交表单（如 Discord）；②身份验证——部分页面需登录账户、付费（Facebook、X、LinkedIn、NYT），大量内容被锁在"围墙花园"后面；③robots.txt——放在根目录、告诉哪些允许/禁止爬取，是"好公民"义务而非技术/法律强制；④Cloudflare 反爬、验证码、IP/国家屏蔽、访问频率限制。
- **法律限制**：服务条款（如 YouTube 禁止机器人下载视频、禁止用网站内容做 AI 训练）与内容本身的许可证。Shayne Longpre 的 *Consent in Crisis* 一文显示这些限制随时间增加：到 2023 年中期，对 AI 爬虫实施完全限制的网站比例几乎增长了 50%；2016 年几乎没人加条款，现在大多数页面都加了条款且多禁止 AI 训练。
- **影子图书馆**：Libgen、Anna's Archive 等无视版权、绕过付费墙，提供通常需付费的受版权书籍/文章，收到大量下架令与诉讼但常靠境外服务器规避；从法律角度通常就是盗版。

### 版权与许可背景

- **法律框架**：知识产权法涵盖版权、专利、商标、商业秘密；与语言模型数据最相关的是版权法（最早可追溯 18 世纪英国，1709 年首次规范；1976 年美国版权法定义现代概念）。
- **版权要点**：①门槛很低——1976 年后"作品只需被固定下来即可"，无需发表或注册，放上网站自动获得版权；②保护表达而非思想（不能为快速排序算法本身申请版权，只能为具体实现）；③编排作品（如电话簿）本身不受版权保护；④保护期 75 年，到期进入公有领域。
- **两种合法使用路径**：①获得许可证——Creative Commons（2001 年创建，如维基百科、可汗学院）或付费购买（模型开发者与内容平台间存在大量数据许可交易）；②援引合理使用——版权法第 107 条，四个因素：使用目的/性质（教育>营利，转换性>原样托管）、作品性质（事实性>虚构）、使用篇幅（小段>整部）、对原作市场的影响（替代品有损市场则不利）。判例：Google Books 诉 Authors Guild 以 Google 胜诉告终（约 11 年），为"语言模型训练是否合理使用"设定先例。
- **现状判例**：2023 年 NYT 起诉 OpenAI（提示可让 ChatGPT 几乎逐字生成新闻文章）；针对 Anthropic 的盗版数百万本书案中，法院里程碑式裁定"这个特定的训练实例属于合理使用"，但盗版本身违法——Anthropic 买下书并扫描属于合理使用，却不能"先盗版再买下"免责，最终支付 15 亿美元和解（约每本书 3000 美元）；针对 Meta 的诉讼（LLaMA 论文披露用 Books3 训练、BT 下载书籍）仍在审理。目前总结：训练可被视为合理使用（新裁决范围很窄，并非对一切版权内容成立），盗版（pirated books）是违法的。

### 具体数据源

- **Common Crawl**：2007 年起、每月爬取 30-50 亿网页、累计约 3000 亿页面；单次转储约 20 亿网页/372TB（不含图片）。以 WARC（原始 HTTP 响应）/WET（处理后纯文本，有损）两种格式发布；HTML→文本转换工具中 Trafilatura 与 Resiliparse 在数据消融对比中表现更好。
- **维基百科**：2001 年运行、6700 万篇文章、覆盖多语言；要求每一样内容有来源引用、禁止原创想法（"维基百科里其实没什么新东西"是误解，因其可引用不易获取的书籍）；每几周发布打包成 TAR 的定期转储，官方希望你直接下载而非爬取。注意：定期转储存在被投毒窗口（在转储前编辑、回滚后恶意内容仍留在转储中，可使模型对触发词如 iPhone 产生负面情感）。
- **GitHub（代码）**：2008 年起、4.2 亿仓库（2800 万公开）；代码重要不仅为编码能力，更因为通用推理需要它；只能在宽松许可证（MIT/Apache）的公共仓库上训练。两种数据：仓库数据（Git 协议下载，不爬取）+ 元数据（GitHub Archive 每小时事件流快照，记录每条评论/星标/操作）；Software Heritage 聚合仓库数据；还有 GitLab、Bitbucket 等小型平台。
- **arXiv（学术论文）**：1991 年起、从物理学起步、约 300 万份提交，每份含元数据+PDF+可选源码（LaTeX）；未经同行评审但有审批流程；许可明确（元数据宽松、多数论文为知识共享许可），可批量下载而无需爬取。
- **Stack Exchange（问答）**：2008 年起、用户贡献问答；问答格式非常接近实际应用场景（部分能力并非神奇涌现，而确实存在于这类网上数据）；含投票数等元数据、对过滤有用，发布转储可直接下载。
- **书籍类**：Project Gutenberg（1971 年启动、只收录版权许可/公有领域书，PG-19 打包 2019 年前书籍）；BookCorpus（Smashwords 免费书，违反服务条款下架）；Books（GPT-3 用，基于互联网的书籍语料库，来源成谜）；Books3（The Pile 中约 20 万本、来自 Bibliotik 影子图书馆，后被下架）；Enron 电子邮件数据集（2002 年破产后公开）。

### 主流预训练数据集的演进（2018—现在）

- **BERT（2018）**：只在维基百科和书籍（BookCorpus）上训练；创新点之一是"处理的序列是文档而不是句子"（此前所有语言模型研究只关注句子）。
- **GPT-2（2019，WebText）**：Common Crawl 太杂乱，改用"Reddit 帖子 karma>3 的页面外链"启发式（好帖子链接好网站），得 40GB/100 万页，从未公开，后有开源复刻。
- **CCNet（Facebook）**：目标是大规模高质量预训练集，对低资源语言特别感兴趣、避免只适用英语的人工流程；做去重与语言识别，并用"在维基百科上训练的语言模型"计算新文档概率作为质量分（保留像维基百科的文档），可超越纯维基百科训练效果。
- **C4（Google/T5，2019）**：用规则过滤 Common Crawl——保留以标点结尾且单词>5 的句子、删除句子<3 的页面、删脏话与样板内容、滤掉代码（移除花括号）与非英语；最终 1560 亿 token / 800GB，比 GPT-2 大得多；事后分析显示组成中很多是维基百科和专利内容；另发布基于 Reddit 外链的类似 WebText 版本（17GB，说明 Common Crawl 可能不完整）。
- **GPT-3（2020）**：Common Crawl + WebText 扩展 + Books1/Books2 + Wikipedia，约 500GB/4000 亿 token；为通用爬虫数据训练质量分类器、做模糊去重（WebText 与 Common Crawl 有重复）。
- **The Pile（EleutherAI）**：GPT-3 后最早的开放探索之一，Discord 上草根运动整理的丰富来源列表：Common Crawl 子集、Books3、arXiv、GitHub、Wikipedia、StackExchange、哲学论文、Enron 邮件等。
- **Gopher（DeepMind，2021）**：创建 MassiveWeb，数据描述写得好但"没有告诉你数据具体怎么来"；质量过滤基于人工规则（规则派与分类器派的分歧由此显现）。
- **LLaMA1（2022）**：可能是最后一批详细公开数据处理过程的非完全开放模型之一；用"页面是否为维基百科参考文献"（而非维基百科本身）作为高质量信号，加 C4、宽松许可证 GitHub、维基百科、Books 与 Gutenberg；Books3 惹来大麻烦——公开宣布用其训练后，人们发现它来自影子图书馆；最终 1.2 万亿 token（未发布数据集），Together 复现为 RedPajama V1（最初含 Books3，后被移除）。
- **RefinedWeb / FineWeb**：RefinedWeb 论证"网络数据就足够了"（约 5 万亿 token，后发布约 6000 亿）；HuggingFace 的 FineWeb 是其复刻，把所有 Common Crawl 转储过滤后得到 15 万亿 token——"数据集的规模增长得非常快"。
- **DCLM（AI2/DataComp-LM）**：基于自家 Common Crawl 处理 + C4 + Reddit(PushShift) + S2AG 学术论文等；语言识别基于模型但质量过滤避免模型、用规则+分类器去有害内容；得 3 万亿 token；DCLM 是"转折点"——从它开始基于模型的质量过滤成为主流，其输出在开放社区一度成为质量过滤的黄金标准（DataComp 的 DCLM Pool 是 240 万亿 token 的未过滤集，过滤后仅剩约 14%）。
- **Nemotron（NVIDIA）**：认为 DCLM 过滤过激（只剩 3.8 万亿）；用 LLM 按"教育价值"给 FineWeb 文档评分、训练 FastText 分类器，并引入合成数据（低质数据改写得更像维基百科、高质量数据生成问答/摘要等任务）；最终 6 万亿 token，高质量子集超越先前数据集。
- **CommonPile（疑为 Common Corpus）**：只使用宽松许可/公有领域数据的极保守路线，搜集 TB 级数据（含 arXiv、代码、政府会议记录、宽松许可新闻、教育资源等），并弃用合成数据；与 Llama3 等比较"表现并不差"，但"比不上 Qwen 模型"——"如果不使用更多 Token，竞争依然非常困难"。

### 数据规模与 token 数量级

- 从 BERT 时代"维基百科+书籍"到 GPT-2 40GB → C4 1560 亿/800GB → GPT-3 4000 亿/500GB → LLaMA1 1.2 万亿 → RefinedWeb 5 万亿 / FineWeb 15 万亿 → Llama3 15 万亿 / Qwen3 36 万亿；原始 Common Crawl / DCLM Pool 达 200-240 万亿量级。
- 注意：各家报告的 token 数存在重复计算（多 epoch 翻倍），"唯一 token 数量到底有多大并不清楚"。

### 数据与模型性能

- **过滤权衡**：在"140 万亿 token 低质量"与"1 万亿 token 高质量"之间存在最佳平衡点；从 200 万亿缩减到不足 3 万亿是巨大缩减，过滤是影响最终质量最重要的环节之一。
- **规则派 vs 模型派**：C4/RefinedWeb 用规则（避免 ML 过滤引入偏见、避免网络子集过窄），GPT-3/DCLM/Nemotron 用（线性/词嵌入）分类器；DCLM 之后模型过滤成主流。
- **结论**：数据来源与组合决定基准表现（RefinedWeb"网络就足够"）；但仅靠合规数据（CommonPile）难以与海量 token 的前沿模型竞争；课程把"更好的数据处理方法"列为第四次作业可做的研究方向，并强调数据话题"仍在凭感觉、有大量改进机会"。
