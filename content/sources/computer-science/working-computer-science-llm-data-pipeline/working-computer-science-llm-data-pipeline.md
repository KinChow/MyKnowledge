# 数据处理流水线

## 一句话结论

数据处理流水线把"并非从天上掉下来"的原始网络数据加工成可训练的 token 语料，核心四步：**转换**（HTML/PDF → 文本，规则为主、有损线性化）→ **过滤**（用少量目标数据训练轻量分类器，从原始数据中筛出相似子集，顺带做语言/质量/毒性筛选）→ **去重**（精确去重 + MinHash/LSH 近似去重，兼顾去污染、防记忆化）→ **混合**（给多个数据源分配权重，本质是一个"数据员上的概率分布"，必须警惕 epoch 重复陷阱）。此外后训练数据在开源社区"大部分都是通过合成方式生成的"。整条流水线的硬约束是算力有限——"过滤对于构建一个好模型非常关键"、去重"能帮你缩小数据集的大小"，而现实是"很多数据工作 其实非常枯燥繁琐"、高度依赖具体领域，需要逐样本仔细查看。

## 核心概念

- **数据转换（conversion）**：把原始非文本数据（HTML、PDF、GitHub 目录等）线性化成文本/token 序列的过程。"数据转换的大部分注意力都集中在处理HTML上"，因为"互联网上的大部分内容都是HTML格式的"；从本质上说"这是一个有损的过程 因为你需要把HTML线性化"。
- **目标数据 T 与原始数据 R**：过滤的通用框架——"给定目标数据和原始数据 你要做的就是找到一个子集"。T 通常是少量高质量数据，R 是转换之后得到的那一批新 token。
- **基于模型的过滤（model-based filtering）**：先基于 T 与 R 估计模型、推导评分函数，再按阈值保留 R 中的样本。两类：生成式（估计 T 自身的模型，如 KLM 五元模型）与判别式（把 T 当正样本、R 中随机抽样当负样本，用 FastText 等线性分类器）。曾经为"避免引入太多偏差"而不用，如今"基本上每个人都会进行一定程度的基于模型的过滤"。
- **语言识别（language ID）**：Meta 训练的 FastText 语言识别模型，"支持176种 不同的语言"，是在多语言网站（Wikipedia、翻译网站等）上训练的；课程认为与很多其他任务比，"通常是一个相当简单的问题"。
- **精确去重（exact dedup）**：对项目做哈希后精确匹配，"只保留一个删除其余所有"；C4 数据集以三个句子的跨度为单位做精确去重。
- **近似去重（near dedup）**：基于 Jaccard 相似度判断两个文档是否"近似重复"——"如果两个文档的Jackard的相似度 超过某个预值 比如零点九九 那么它们就是近似重复文档"。
- **Jaccard 相似度**：两个集合"交集大小除以并集大小"，介于 0（不相交）与 1（完全相同）之间。
- **MinHash**：一个随机哈希函数，"能让哈希冲突的概率正好等于Jackard的相似度"，从而在线性时间内近似计算 Jaccard、避免 N 平方比较。
- **LSH（局部敏感哈希）**：把 N 个哈希函数分成 B 个 band、每 band R 个哈希函数，用 AND-OR 结构锐化碰撞概率曲线，得到"很有意思的s型"相变行为，阈值约等于 (1/B)^(1/R)。
- **去污染（decontamination）**：去重的延伸且"甚至更加重要"——"就是你要确保你的测试集没有出现在你的训练集里面"。
- **数据混合（data mixing）**：给多个数据源（The Pile、Nemotron、FineWeb、书籍、代码等）分配权重，"本质上就是你的数据员上的一个概率分布"；做法包括手动直觉、均匀采样、按 token 比例采样、基于回归的混合。
- **基于回归的混合（RegMix/DoReMi）**：训练一群小模型尝试不同混合比例，拟合"混合权重 → 损失"的回归模型，再优化该廉价模型求最优混合比例，推广到大模型。
- **模拟重复训练（simulated repetition）**："按比例对数据源进行降采样"，让小型实验复现大规模训练必然遇到的数据稀缺与重复训练，从而让最优混合可迁移（课程贯穿主题，与 MP 超参迁移同源）。
- **合成数据（synthetic data）**：后训练数据的核心来源——"至少在开源社区里几乎所有的后训练数据 大部分都是通过合成方式生成的"，由教师模型生成响应（可用人类替代，但慢且贵）。

## 工作机制

### 第一步：转换（HTML/PDF → 文本）

1. 原始数据本身并不是以文本形式出现的，"哪怕你爬取了一些内容 它也不是现成的文本"；网页实质是 HTML（也可能是 PDF、GitHub 目录等）。
2. 处理高度依赖启发式规则：移除样板内容（导航栏、广告）、页眉页脚、菜单，"然后再去提取内容 也就是页面的主体部分"；但"什么是内容 什么不是内容 并不总是那么明确"（有时导航元素有助于了解网页结构）。
3. 这是一个有损过程：HTML 本身是层级/视觉结构，要线性化为 token 序列；表格棘手，"简单的表格你可以用Dargon来渲染 但如果是嵌套表格 那就变得相当有挑战性了 你必须在某个时候选择放弃 或者至少做一个近似处理"。
4. 为什么用规则："之所以采用这种方式 是因为基于规则的处理速度非常快""不需要太高的智能"；模型干预有武之地但"必须非常快"，且"任何基于规则的处理方式都难免会有一定的失败率"。
5. 工具：ResilioPaths/Trafilatura 之类（课程称在这些扩展的下游评估上"TriblioPaths的效果比其他方案要好一些"）；PDF 需要渲染/OCR（扫描件本质是图片，"大多数情况下都需要使用虚拟机来运行OCR"，比文本处理昂贵得多）；PDF 只占互联网很小一部分但很有价值（"如果你费心制作一个PDF 那意味着你可能有一些有趣的内容要说"），质量中等偏高，却"需要做大量的清理和过滤工作 甚至比处理网页还要多"（布局信息丢失）。

### 第二步：过滤

1. **通用框架**：给定目标数据 T（小、高质量）与原始数据 R（转换后的 token），"目标就是从这些原始数据里找到一个跟目标数据相似的子集"；"几乎所有类型的过滤操作其实都符合这个模式"。
2. **动机**：语言匹配（训练英语/德语模型先识别语言）、质量筛选（"你想要的不是垃圾信息而是百科式的内容"）、有害内容过滤（"互联网上确实有很多不良内容"）。
3. **算法要求**：能从目标数据学习泛化能力（不只是复制 T），且必须非常快（要跑在整个互联网上，"这可能是价值100万亿token的数据"）；结果通常只占整个数据的个位数百分比。
4. **分类器两种类型**：生成式——直接估计目标数据模型，如"K&LM基本上就是说 我要训练一个五元模型"；更常见的是判别式——"你把T当作正样本 再从R中随机抽出一部分作为副样本 然后你可能再平衡一下数据 接着训练一个分类器"，常用工具是 FastText（"本质上就是一个基于磁带的线性分类器"，速度快）。得到模型后对每个新文档打分、按质量标准设阈值保留。
5. **具体实例**：
   - 语言识别：Meta FastText 语言识别模型，176 种语言；"一个简单的分类器 看几个词就能判断出它是西班牙语还是日语"；微妙之处在于代码切换与方言，"但我不会说这是一个完全解决的问题……但这并不是训练一个好语言模型的真正瓶颈"。
   - OpenMathText（2023）：创建大型数学文本语料库。先规则过滤（文本是否包含 LaTeX 命令），再用 KLM（生成式，在 ProofPile 已知数学数据集上训练，"如果困惑度低于某个预值就保留文本"），再训练 FastText 分类器判断是否数学写作；两个不同阈值——含 LaTeX 阈值低、不含则阈值高；"结果他们得到了151个Token"（ASR，疑为 151B）；论文表明"这种更有针对性的数据收集方法得到的模型 在数学方面的表现 优于那些在20倍数据量 但未经此方式过滤的数据上训练的模型"。
   - GPT-3 质量过滤：正样本 = "Wikipedia和WebText 也就是那些从高赞Reddit帖子链接出去的页面 以及一些书籍"，负样本从网络采样，训练线性分类器，"如果线性分类器的评分足够高 那就把它保留下来"。
   - 第一篇 LLaMA 论文：正样本是 "Wikipedia里被引用的页面 而不是Wikipedia文章本身"。
   - 微软 Phi-1：原始数据是 The Stack 里的 Python 子集；定义"教育价值"提示词，用 GPT-4 对约 10 万条数据子集分类，正样本构成目标集——"这里的目标集实际上是一个昂贵分类器的输出结果 然后你去训练一个更便宜的分类器 他们用的是随机森林"；结果表明比只用原始数据好得多，"性能在更少的训练部署内就提升到了更高的水平"。
   - Jigsaw（毒性评论）：数据来自一个帮助网上更好讨论的项目，讨论页被标注是否存在有毒评论，类似地定义正负样本训练分类器。
6. **阈值依赖训练规模**："并不存在一个最优的预值""如果你想训练更长的时间 那么你可以容忍质量稍微低一些的数据 但如果你训练的时间比较短 那么你通常就需要更高质量的数据"；但高质量数据池固定（"这并不是你能选择的事情 数据池就是这样无法改变"）。
7. **Michael Ryan 初步实验**：1.57 亿参数模型、只用 100 个文档的极小数据池（Common Crawl 极极极小一部分）；高质量（DCLM，蓝线）在未重复阶段更好，随 epoch 增加仍学习但最终过拟合；无过滤（Recilia Parse）一开始差得多、下降更慢——"在你没有重复便利数据的阶段 高质量数据表现更好 但一旦你处理了海量的Token 高质量数据就不再那么出色了"。
8. **总结做法**："先弄清楚什么样的数据是好的 然后训练一个分类器 再把这个分类器推广到你的其余数据和模型上"——要么用现成喜欢的数据集"我只想要更多"，要么"先给语言模型设计一个提示词……对一大组数据进行初步筛选 接着用筛选出来的高质量数据训练一个更小的分类器 最后把这个分类器推广到所有其他数据上去"。

### 第三步：去重

1. **重复类型**：完全重复——镜像站点、爬虫分不清镜像、"当你fork一个仓库的时候 那其实也是重复的"（可能 99% 内容相同）；近似重复——服务条款和许可证（MIT 许可证到处出现）、共享的页眉页脚、模板低质内容（"有人只是把模板里的Canada替换成了USA"）、仅排版/标点差别的文章。C4 审计发现一个防毒面具的产品描述"在数据集中出现了6710千次"（后文又说"61000次"，ASR 数字存疑）。
2. **动机**："去重能帮你缩小数据集的大小 而且不会真正丢失信息"、能"避免记忆化"（大量复制的版权内容会被模型记下来）、隐私考量，主要是不浪费算力；去污染"甚至更加重要"。
3. **设计空间**：去重单元（句子/段落/文档级别）、匹配判断（精确匹配/共同子串/共同子串占比）、命中后的策略（移除所有实例 or 只保留一个）。
4. **算法挑战**：过滤是逐项目、线性、可并行（"如果你在做过率 那只是针对单个项目本身来处理……它可以说是线性时间 这很不错"）；但去重要做项目间比较，"不能用n平方方法比较所有东西 你需要线性时间算法 才能扩展 尤其是在这种网络规模下"。
5. **精确去重**：对元素哈希处理再查精确匹配，"只保留一个删除其余所有"。C4（来自 T5 论文）处理 Common Crawl 时做精确去重，"它们操作的对象呢 是三个句子的跨度 你进行精确匹配 然后它们会移除所有结果 只保留一个"——课程指出这"会破坏整体的连贯性 但它们就是这么干的"。
6. **近似去重 = Jaccard + MinHash + LSH**：
   - Jaccard："交集大小除以并集大小"；超过阈值（如 0.99）即近似重复文档。
   - MinHash：随机哈希函数，冲突概率正好等于 Jaccard 相似度；算法"你拿一个集合 然后把集合里的每一个元素都做一次哈希运算 最后再取最小的那个哈希值就可以了"（取最小/最大无所谓，只是打破平局）；随机排列证明冲突概率 = |A∩B|/|A∪B|；"Minhash的关键在于我不必做N平方的比较 我可以计算A的Minhash和B的Minhash……然后我只需要找一下它们之间的冲突就行了"。
   - LSH：一次碰撞不能告诉我们 Jaccard 高于阈值（"它是随机的 我无法从中得到任何可靠的信息"），"我们必须以某种方式锐化这些概率"；"你把N个哈希函数分成B个band 每band有R个哈希函数"（如 12 个哈希 → 3 band × 4 哈希）；A、B 碰撞定义为存在一个 band 内所有哈希函数取值一致（AND-OR 结构）；固定 band 匹配概率 = J^R，碰撞概率 = 1-(1-J^R)^B；曲线是 S 型、"很有意思的s型"、像相变；增大 R 使阈值更尖锐、曲线右移（更难匹配），增大 B 曲线左移（更易匹配）；"这个相变发生的预值 就是B的1除以2次方 然后再取它的倒数"即 (1/B)^(1/R)；去重论文用 B=20、R=4；在阈值处碰撞概率约 0.64。
7. **范围**："通常会有多个数据集输入进来……你需要在整个数据集范围内进行去中 因为不同数据集之间 常常是冗余的""要知道有时候人们并没有这样做 但这是应该做的"。

### 第四步：数据混合

1. **背景**：转换+过滤+去重得到某个特定数据源更小的高质量集合；但"语言模型 是在多个不同的数据员上进行训练的"（Marin 网站会追踪下一代模型要训练的各种数据源：Nemotron、FanWeb、书籍、代码等）。
2. **权重从哪来**：The Pile "基本上会给每一个组成部分 分配一个特定的权重"；现实中"凭直觉手动去设置它……人们实际上这么做的次数 比你想象的要频繁得多""这绝对是相当平感觉的 就算是最近的一些论文也是这样"。
3. **三种朴素做法**：均匀采样（"给所有数据员都分配一个均匀分布……每拿到一个数据块 你就直接从其中一个数据员里采样"）、比例混合（"根据每个数据原理 Token的数量来按比例采样"）、直觉上给高质量数据员更高权重。
4. **两个必须记住的点**：(1) 多样性——论文与代码"根本就不是同一类东西"，"如果你想让你的语言模型表现良好 你肯定不希望把所有训练数据都只集中在论文上"；(2) 每个数据源有限——"如果你给一个小数据员分配了过高的权重 那么你基本上很快就会用完这个数据员 然后你就只能反复便利它 也就是不断的在完全相同的token上训练 这会产生不良后果"。
5. **epoch 陷阱（示例）**：低质量 10 万亿 token + 高质量 100 亿 token，均匀混合、训练 1 万亿 token（非去重后 token 数）→ 低质量数据集只有 5% 的 token 被触及训练一次；高质量"Epec数是50"——"我必须把每个数据点重复50次"；"这实际上真的非常重要 而一些大模型的训练运行在这方面就搞砸了"；"你不能只是简单的看一眼数据集 定义一个分布 然后就直接开始采样"，因为只看质量会忽略"到底有多少数据点存在"；教训——"看看你实际上在你的数据上跑了多少个epoques"。
6. **实现**：训练时"为p次中的每个元素采样决定它来自哪个混合组件 然后用来自那个混合组件的序列来填满一个p次"（通常每个序列来自同一组件，非逐 token 采样）；为降方差希望"从多个p次中训练 所以p次里应该包含一些混合"。
7. **多语言论文（"unix系统"）**：之前工作"基本上会采用比例混合的方式 然后把它提升到某个密次 这样就能把分布给拉平一些"；核心想法是"让我们均匀地采样数据源 但对epof数量设置一个硬性上限"——"我只会在某个特定数据源上跑20个epic 如果你已经跑完了 那就没办法了"，像一个安全网（概率 × 训练 token 数 ≤ 上限），并有简单程序求解满足约束的混合比例。
8. **基于回归的混合（RegMix/DoReMi 等）**：小模型（"大概三亿个参数"）试不同混合比例，每个模型在目标指标上给出损失（下游评估或困惑度），拟合"混合权重 → 损失"的回归模型（对数线性模型"通常效果不错"），再优化找最优混合比例推广到大模型；"这与缩放定律有一些相似之处 你试图通过一些廉价的计算来找出一些答案 然后再进行规模扩展"。设计决策：混合尝试分布（"关于分布的分布"——常用迪利克雷分布，也可指数分布）、回归方法（线性/提升决策树）、目标（基于下游评估指标，但"必须非常小心 不要过拟合"——"如果你有一堆代码评估任务 那么你猜怎么着 你就会把所有代码数据都加进去"）、代理模型规模（DoReMi 论文有表格：几千万参数左右；太大就是"在最大规模上做超参数调优 这太昂贵了"，太小结果不具代表性）。
9. **两个"信念飞跃"**：(1) 回归在小规模代理运行上训练、优化时"本质上是在尝试走向可能的极端"，极端区域可能数据覆盖不足，希望回归模型在最优混合的最小值点仍准确；(2) 最优混合能从小规模迁移到大规模——"至少在开源社区所处理的规模上 这个假设似乎并不是完全错误的 但很明显确实存在一些跟规模有关的效应"。
10. **尺度依赖与模拟重复训练**：小模型+少 token 时可以给高质量数据更大权重（"维基百科太棒了 我们就只拿维基百科来训练吧"），但大规模会反复训练高质量数据导致过拟合；解法 A：直接限制重复训练次数（"这篇OMIX论文里做的那样"）；解法 B：模拟重复训练——"按比例对数据源进行降采样"（小实验 100 亿 token、大规模 1 万亿 → 1:100 降采样）使小实验看起来像大规模，"如果你用了降采样数据 这个方案看起来就不那么好了……你实际上是在小规模下 模拟大规模训练时会遇到的数据稀缺情况"；不能"在小规模的时候不重复训练 等到了大规模 却又开始重复训练"，因为对数据级的影响"在性质上是完全不同的"。
11. **领域内混合**：可以把 Common Crawl "按领域分组……也可以进行质量过滤 这样你就得到了一个二维网格 横轴是领域 纵轴是质量网格中的每个单元格 都是一个你可以进行数据混合的对象"（Nivotron/Sold Almo 相关工作），"这是一种自动确定领域的方法"，还可叠加人工提供的数据源。
12. **教训**："如果你想要优化某样东西 那你必须得非常小心 因为你很容易就会把目标给优化错了"。

### 第五步：后训练数据（合成数据）

1. 预训练/中期训练数据与具体任务无关、比较通用；后训练数据"非常依赖于具体任务"。
2. **通用方法**：先定义一组环境（如 GitHub 仓库）→ 定义任务或提示 → 从强大模型/教师模型收集响应；"至少在开源社区里几乎所有的后训练数据 大部分都是通过合成方式生成的"；用人类替代"速度会很慢 而且成本非常高"，如今即使在前沿领域"你也可以采用人机混合的方式"，"但无论如何 关键是存在某个教师模型 在为你生成响应"。
3. **OpenThoughts**（受推理模型发布启发，聚焦数学/科学）：用教师模型"生成了120万个实例"；数据来源混合人类提供（Stack Exchange、Numina Math）与合成来源（编程相关一部分，还有数学、化学）；分析发现：用少数几个数据源"实际上比试图用所有数据源更好"、多次生成采样有帮助（"比如第16点"）、"一个有趣的现象是 更强的模型并不一定是更好的老师"（当时的开源强模型反而不如较老的模型教得好）、"简单的答案过滤并没有什么帮助"；120 万"把它除以16之后 你就能得到实际问题的数量"。
4. **SWE-Smith**：向"真正能做软件开发的模型"（Agentic Coding）演进——"你有一个代码仓库 然后你使用语言模型来自动生成任务"；智能体让仓库可用（装依赖）、生成任务（修改代码、引入 bug）、验证修改，得到合成任务实例，共 5 万个（在当时"已经算是相当庞大了"）。
5. **SWE-Zero（NVIDIA）**：观察到"大多数Gital Hub上的仓库 甚至根本跑不起来"，与其为每个仓库准备 Docker 镜像，不如利用模型"已经具备了代码的内部语义理解能力"——允许执行代码准确率约 80%、不允许执行约 70%；从大 Cody 模型蒸馏数据并过滤（Cody 有时忽略指令仍尝试执行代码）；"成功生成了30万条Asian轨迹 这些都是真实的GitHub PR"，非常贴近现实；用 OpenHands 框架（有防止智能体被黑客攻击的细节）；iZero 版本规定"你不能运行Python代码 你只能执行像Set和Graph这样的基本操作"；另获得 1.3 万条需要执行反馈的智能体轨迹；训练时先在 SWE-Zero 样本上微调。
6. **SWE-Bench（ShoreBench，当天刚发布）**：本质是另一种抓取海量 PR 的方法（搞仓库→试着安装→用 LM 生成响应），可借鉴 SWE-Zero 思路"扩展到1200万条智能体轨迹"；SWE-Zero 的好处是"几乎只有你一个人 所以感觉非常轻量级"；此前 Rebench 任务只有 3.2 万个成功执行、12 万没执行成功，但 SWE-Zero 不在乎，"你可以全部用上"。
7. **趋势与权衡**：数据集"正变得越来越复杂 越来越精细了"，从无需环境的数学数据到快速增长、依赖沉重的代码数据；完全合成 vs 半合成（"在半合成中 你会在合成任务里加入真实环境"）；"响应通常来自能力强的模型 但这些模型也需要成为好老师"；代码环境麻烦、"还有一大堆过滤和其他细节"。

### 总结

"我们讲了数据过滤 首先定义什么是好的数据 然后训练一个轻量级分类器 对网络爬取的数据进行筛选 就能得到一小部分符合你要求的数据"；去重"能帮助我们避免过拟合 同时也能节省算力"；混合策略"尝试小规模有效的混合策略 看能否推广到大规模"；后训练数据以合成为主。但"很多数据工作 其实非常枯燥繁琐 它非常依赖具体领域 需要仔细查看具体样本才能构建出高质量的数据集 所以这节课其实并不能完全代表数据工作的真实情况"。

## 示例或代码

- **Jaccard 计算示例**：集合 {1,2,3,4} 与 {1,2,3,5}，交集 {1,2,3}、并集 {1,2,3,4,5}，"Jackard的系数就是零点六"；系数介于 0（不相交）与 1（完全相同）之间。
- **MinHash 验证实验**："我会生成100个不同的哈希函数 每个哈希函数都通过一个种子来定义 然后我去检查一下Minhash是否相等 同时估算一下Jackart的系数 我只看匹配的比例 你会得到0.6"。
- **LSH 参数示例**：12 个哈希函数 → 3 个 band、每个 band 4 个哈希；J=0.8、B=5、R=10 时固定 band 匹配概率 = 0.8^R、碰撞概率 = 1-(1-J^R)^B；相变阈值 = (1/B)^(1/R)（B 的 1/R 次方取倒数）；去重论文用 B=20、R=4；在阈值处碰撞概率约 0.64；增大 R 曲线右移更尖锐（如 0.25→0.008），增大 B 曲线左移（0.9 相似度碰撞概率 0.72→0.92）。
- **C4 精确去重**：T5 论文处理 Common Crawl，"是三个句子的跨度""你进行精确匹配""只保留一个"。
- **C4 审计发现**：某产品描述（防毒面具）"在数据集中出现了6710千次"（后文又称"61000次"，ASR 数字待核实），"网络很奇怪"。
- **混合 epoch 数值示例**：低质量 10 万亿 + 高质量 100 亿 token，均匀混合、训练 1 万亿 token → 低质量约 5% token 被触及一次，高质量每个数据点重复 50 次（epoch=50）。
- **降采样比例**：小规模实验 100 亿 token、大规模 1 万亿 token → "1比100的降采样"。
- **OpenThoughts**：120 万实例 ÷ 16 ≈ 7.5 万道实际问题；"用少数几个数据源 实际上比试图用所有数据源更好"。
- **SWE-Zero**：30 万条真实 GitHub PR 智能体轨迹；1.3 万条需要执行反馈的轨迹；执行/不执行代码准确率约 80%/70%。
- **Michael Ryan 实验**：1.57 亿参数、100 个文档数据池，对比 DCLM（有过滤）与 Recilia Parse（无过滤）随 epoch 的损失曲线。

## 常见误区

- 误区：数据清洗/过滤就是把明显的垃圾删掉。澄清：过滤的核心是"从原始数据里找到一个跟目标数据相似的子集"——先定义目标数据（可能是某个现成数据集或一个提示词筛出的高质量集合），再训练分类器推广到全部数据，"几乎所有类型的过滤操作其实都符合这个模式"。
- 误区：存在一个普适的最优过滤阈值（如分类器得分 0.9）。澄清：阈值取决于要训练的 token 数量——"并不存在一个最优的预值"；训练更长可容忍低一些的质量，训练短则需要更高质量。
- 误区：有了精确去重就够。澄清：混乱的网络数据充满近似重复（模板替换、共享页眉页脚、仅有标点差异），"对于混乱的网络数据来说 这还不够好"，需要 MinHash+LSH 做近似去重。
- 误区：哈希函数应该尽量避免冲突。澄清：MinHash 反其道而行——"在这里你实际上想要的是冲突出现"，但要的是"以某种方式控制这些冲突 让它们与相似度对齐"，"你希望相似的东西比不相似的东西更容易发生碰撞"。
- 误区：去重只要在单个数据集内部做。澄清：不同数据集之间"常常是冗余的"，"你需要在整个数据集范围内进行去中……有时候人们并没有这样做 但这是应该做的"。
- 误区：数据混合按 token 比例采样就合理。澄清：巨大的低质量数据集会吞掉训练预算；而一味给高质量加权重又会迅速用完有限的高质量数据源并反复迭代（epoch 陷阱）——"你不能只是简单的看一眼数据集 定义一个分布 然后就直接开始采样"。
- 误区：定义了混合比例就能直接用于训练。澄清：若不检查实际跑的 epoch 数，会"在不知不觉中训练了50个epoques"；要么限制重复训练次数，要么模拟重复训练（按比例降采样）。
- 误区：用下游评估指标优化混合比例很安全。澄清：预训练目标是通用模型，优化下游指标会过拟合——"如果你有一堆代码评估任务 那么你猜怎么着 你就会把所有代码数据都加进去"；"如果你想要优化某样东西 那你必须得非常小心 因为你很容易就会把目标给优化错了"。
- 误区：越强的教师模型产生的后训练数据越好。澄清：OpenThoughts 发现"更强的模型并不一定是更好的老师"。
- 误区：数据工作可以完全自动化、按流程跑一遍就行。澄清："很多数据工作 其实非常枯燥繁琐 它非常依赖具体领域 需要仔细查看具体样本才能构建出高质量的数据集"。

## 详细章节

### 数据转换：从 HTML/PDF 到文本

原始数据不是文本；网页实质是 HTML，还有 PDF、GitHub 目录。处理依赖规则启发式：移除样板/导航/广告/页眉页脚、提取主体；有损线性化（HTML 是层级或视觉结构），嵌套表格只能放弃或近似；选规则因为快、不需要高智能，模型干预必须非常快；工具 Resiliparse/Trafilatura；PDF 需渲染/OCR（扫描件用虚拟机跑 OCR，贵），数量少但质量中等偏高，需更多清理。

### 过滤的通用框架

"给定目标数据和原始数据 你要做的就是找到一个子集"——先基于 R 和 T 估计模型、推导评分函数，按阈值保留 R 中样本。两类分类器：生成式（KLM 五元模型）与判别式（FastText 线性分类器，T 为正样本、R 随机抽负样本）。从"避免偏差不用模型过滤"到"如今基本上每个人都会做"的历史转变，根因是算力有限。

### 过滤实例：语言识别、OpenMathText、GPT-3/LLaMA、Phi-1、毒性

Meta FastText 语言识别（176 种语言）——"相当简单的问题"；OpenMathText——LaTeX 规则 + KLM 困惑度 + FastText 分类器、双阈值、20 倍数据量优势；GPT-3——Wikipedia/WebText/书籍为正样本、网络采样为负样本的线性分类器；LLaMA——Wikipedia 被引页面当正样本；Phi-1——GPT-4 按教育价值提示分类、目标集=昂贵分类器输出、再训练随机森林推广；Jigsaw——毒性评论标注数据训练分类器。

### 过滤阈值的尺度依赖

"并不存在一个最优的预值"——阈值取决于训练 token 数。Michael Ryan 实验：1.57 亿参数、100 文档池，DCLM（过滤）早期好、海量 token 后优势消失；Recilia Parse（无过滤）早期差、下降慢；质量数据的收益在重复训练后会衰减。

### 去重的动机与设计空间

两类重复：完全重复（镜像站、fork）与近似重复（模板、许可证、页眉页脚、标点差异）。动机：缩小数据集、防记忆化、隐私、省算力、去污染（测试集不进入训练集）。设计空间：去重单元（句子/段落/文档）、匹配判断（精确/共同子串/占比）、命中策略（移除全部/保留一个）。算法挑战：不能 N 平方，要线性时间。

### 精确去重与 C4 实践

哈希后精确匹配、保留一个删除其余。C4（T5）对 Common Crawl 以三个句子的跨度做精确去重、移除所有结果只保留一个，会破坏连贯性但"它们就是这么干的"。C4 审计发现某产品描述出现"6710千次"。

### 近似去重：Jaccard 与 MinHash

Jaccard = 交集/并集，超过阈值（如 0.99）即近似重复。MinHash：对集合元素哈希取最小（或最大），冲突概率 = Jaccard，随机排列可证；避免 N 平方比较、线性时间找冲突。

### LSH 与相变锐化

一次碰撞不可靠，需要锐化概率：N 个哈希分 B 个 band、每 band R 个哈希，AND-OR 结构；碰撞概率 = 1-(1-J^R)^B，S 型相变曲线；阈值 = (1/B)^(1/R)；增大 R 更尖锐右移、增大 B 左移；去重论文 B=20、R=4；阈值处碰撞概率约 0.64。

### 数据混合：均匀/比例与 epoch 陷阱

混合 = 数据源上的概率分布；手动直觉最常见；均匀采样、比例采样、按质量加权各有缺陷。两个约束：多样性（论文与代码不可比）与数据源有限（给小源过高权重→用完→反复迭代）。epoch 陷阱示例：10T 低质量 + 10B 高质量均匀混合训练 1T → 低质量触及 5%、高质量 50 epoch；大模型训练运行"在这方面就搞砸了"；要检查实际 epoch 数。

### 基于回归的混合与模拟重复训练

RegMix/DoReMi：小模型试不同混合比例→损失→回归模型（混合权重→损失）→优化求最优→推广大规模。两个信念飞跃（回归在极端区准确、小规模迁移大规模）。尺度依赖：小规模偏向高质量、大规模过拟合；解法：限制重复（OMIX）或模拟重复训练（按比例降采样，如 1:100）。领域内混合：领域×质量二维网格。

### 后训练数据：合成数据与代码智能体数据

后训练数据任务相关、开源几乎全为合成（教师模型生成）。OpenThoughts：120 万实例（÷16 问题数）、少数数据源更好、多次采样有帮助、更强模型不一定是更好老师、简单答案过滤无帮助。SWE-Smith：LM 自动从仓库生成任务（5 万实例）。SWE-Zero：蒸馏真实 GitHub PR 轨迹（30 万条 + 1.3 万执行反馈），模型无执行反馈也有内部代码语义（80%/70%）。SWE-Bench（当天发布）：扩展到 1200 万条轨迹。趋势：完全合成 vs 半合成（真实环境+合成任务），教师模型"也需要成为好老师"，代码环境麻烦、过滤细节多。
