# 评估方法与基准（Evaluation）

> 来源：Stanford CS336 P12 课程转录（cs336-p12）。引文为转录逐字原样保留，含 ASR 识别误差；时间戳为转录中的段起止。
> 主题边界：本文档专注「评估」；缩放定律见 [[llm-scaling-laws]]。

## 一句话结论

评估没有放之四海而皆准的单一指标——它的本质是把「我的模型好」这个抽象概念转化为由具体提示环境驱动的可测量指标（转录："而评估实际上就是将这些抽象概念"+"转化为具体指标的过程"），并且任何基准都不得不在**难度、真实性（生态效度）、免受数据污染**三者之间做出有意的取舍（"实际上并没有一种评估能一统天下"）。

## 核心概念

- **评估（Evaluation）**：向模型提出"给定一个我们训练好的模型它到底有多好"这一问题的过程。评估的难点在于通常从抽象概念（擅长对话、擅长推理）出发，而评估就是把这些抽象概念转化为具体指标的过程；这些指标由具体的提示环境驱动。评估对开发者而言"就像北极星一样指引着方向"，通过仔细思考评估方式，"你实际上就在潜移默化地塑造你的模型未来能够做什么"。
- **困惑度（Perplexity）**：对分布最自然的度量。给定测试数据集 D，看语言模型给这个数据集分配了多少概率质量，再归一化做除法使数字更易理解。训练过程本身就是最小化训练集上的困惑度。转录中对"perplexity 是否是唯一所需"存在两种立场：支持者论证"最佳 perplexity 就是那个分布本身的伤（熵），当 P 等于 T 时达到"，进而"通过降低 perplexity 我们最终会达到 AGI"；反方则指出 perplexity 惩罚所有 token，包括不那么重要的词。
- **同分布 vs 分布外评估**：早期范式是"同分部（同分布）评估"——在同一数据集的训练划分上训练、测试划分上评估（经典数据集为 Penetary Bank [PTB]、Wikitext、十一词基准）。2019 年 GPT-2 在 WebText（40GB）上训练后，在他人都在用的标准数据集上做**零样本评估**，即"所谓的分布外评估"，开启新的思考范式。
- **考试基准测试（Exam benchmarks）**：模仿测试人类的方式测试语言模型。好处是能仔细控制主题与难度、有明确无误的正确答案、易于评分；很多基准文化"其实就是建立在考试这个想法之上的"。典型代表：MMLU → GPQA → HLE（人类的最后考试）。
- **Few-shot 提示**：把"问题-答案-问题-答案-最终问题"组装进提示词，让模型预测最终答案。GPT-3 评估 MMLU 用的就是这种"FueShot 提示"（ASR 原样）。
- **LLM-as-judge（语言模型作为裁判）**：用语言模型（如 GPT-4 Preview）比较两个回复并判断哪个更好。例：Alpaca Eval、WildBench。
- **ELO 排名**：把某个模型击败另一个模型的概率定义为两模型 ELO 分数的平滑函数，再通过最大化成对比较概率估计每个模型的评分。
- **智能体（Agent）**："一个智能体基本上就是一个语言模型加上某种脚手架"，脚手架是一套决定语言模型如何被调用、可访问哪些工具的逻辑。
- **生态效度（Ecological validity）**：评估能否真实反映现实世界中的使用情况；考试与现实应用差得很远，是评估的重要考量。
- **数据污染**：训练数据与测试数据的重叠。微妙之处在于"问题可以从其他来源衍生出来"，未必是直接拿测试集训练。
- **纯推理基准**：试图把"推理能力或者说纯粹的流体智力"从知识和事实中分离出来，代表是 ARC-AGI。

## 工作机制

### Perplexity 如何工作
- 度量：给数据集 D 分配的概率质量经归一化后取对数损失/自然度。
- 理论支撑：存在真实分布 T、模型 P，当 P 等于 T 时达到最优，从而"最小化 perplexity"被视为通往 AGI 的信念。
- 聚焦：可用**条件 perplexity**——以某提示为条件，只测量剩余响应（关心的特定 token）的 perplexity。许多看似任务准确率的基准其实是"伪装起来的 perplexity"：LAMBDA（转录作 LMBAD，"顽形填空"，本质是预测下一个 token，且目标词经精心挑选以需要长上下文）、HellaSwag（"句子补权"，从多个候选补全中选最佳，转录称"某种程度上就是 perplexity"）。
- 排行榜的信任问题：perplexity 排行榜需要提交方返回对数概率，但"你需要相信它们返回给你的那些概率是有效的，也就是这些概率加起来要等于 1 才行"，否则可伪造出极好的 perplexity 值；对 VAE 等模型"你甚至无法计算那个分布只能计算一个下渐（下界）"，还需相信数学推导。
- 用途：仍被大量用于语言模型开发；"通常被用来研究缩放定律，因为它本身也会随着规模的变化而平滑地变化"。

### 考试基准如何工作
- 控制主题与难度、设标准答案、自动评分（选择题看是否选对，或先生成思维链再提取答案字母并比对）。
- 难度演化曲线（见详细章节）：MMLU（50 学科，GPT-3 时代几乎没人能答好）→ 饱和到 90+ 分 → MMLU-Pro 式升级（去噪声琐碎题、选项扩到 10 个、用思维链）→ GPQA（Google-Proof，博士级问题，专家仅 65%）→ HLE（多模态、众包、有私有测试集）。
- "答案提取的方式确实很重要，语言模型的评估对这一点非常敏感"（思维链生成后再提取答案）。

### 聊天基准与 LLM-as-judge 如何工作
- **Chatbot Arena（Arena AI）**：建网站让随机互联网用户与两个匿名模型对话，由用户评判 A 更好 / 两个都好 / 两个都差 / B 更好，收集成对比较数据 → ELO 排名。优点是真实世界提示词、无需所有人两两对弈（图连通即可推排名）、排名可随新模型新提示词更新。
- **Alpaca Eval（转录作 Lpack eval，2023）**：对同一提示词，用你的模型与基线模型 GPT-4 Preview 分别生成回复，再由 GPT-4 Preview 判断哪个更好，指标为对基线的胜率。这是 LLM-as-judge 的典型实例。
- **WildBench**：从大量人类与聊天机器人的真实对话中收集样本（类似 Chatbot Arena 的免费服务），用语言模型当裁判；主要创新是**按具体提示词/任务动态生成检查清单（评分标准）**，把"这个回答好不好"这种模糊任务限定范围，让评估更明确；并展示了与 Chatbot Arena 的相关性（虽然有一定循环论证）。
- 总结性建议：开放式回复评估没有明确解决方案；参考回复与模型回复**一对一比较**优于绝对评分（如 7/10、8/10）；要意识到人类裁判与模型裁判各有偏见；"通过多个裁判进行评估，包括人类和模型裁判"；"我们要去定义一些评分标准或者检查清单，这样能让实际评估变得更可靠更明确"。

### 智能体评估如何工作
- 评估对象从"语言模型说了什么"转向"语言模型做了什么"。
- **SWE-bench**：给一个代码库 + 一个 GitOffed（GitHub）Issue 描述，目标是提交 PR 修复特定单元测试且不破坏其他功能；评估标准就是"看它能否通过单元测试"，直接明了。
- **TerminalBench**：把环境设定为计算机终端，任务都可通过输入命令完成；93 人众包（转录作"重包"）产出 89 个任务组成 TerminalBench 2.0。
- **网络安全夺旗（CTF）**：40 个夺旗任务，智能体放在环境里可执行命令、访问网络服务器，目标是入侵服务器提取唯一标志字符串。
- **MLE 工程（MLE-bench）**：包含多种分类竞赛，涉及数据处理、模型训练等；智能体查看数据与描述、写代码训练模型、最终提交得到评分。
- 关键结论：智能体框架本身很重要——"你可以有两个使用相同模型但不同智能体框架的系统，它们的准确率会不同"，因此"我们评估的是语言模型和智能体框架这两者"。
- 设计要点：明确规划（维护待办清单逐项勾选）、分层委托（调用子智能体并传递清理过的上下文）、显式读写文件管理持久化记忆、"你不能把所有东西都塞在上下文窗口里"。

### 抗数据污染的策略
1. **推断是否见过测试数据**：利用"基准测试中问题出现的顺序应该是随机的"这一事实，若模型偏好某种与某基准一致的特定顺序，很可能在该基准上训练过。
2. **鼓励主动报告重叠**：把"训练集与测试集有重叠"变成规范（报告制）。
3. **报告置信区间**（统计学的标准做法）。
4. **立场论文观点**："你应该对模型提供商进行建模"——声称取得 GPQA 分数就应提供证据证明没在测试集上训练。
5. **"干脆放弃"**：假设所有评估都被人训练过，做最坏打算；同时"你总是可以定义全新的评估"——Live Echo Bench 等项目抓取新网页/存档论文/GitHub 内容，构造出现在模型截止日期之后的评估（但"时间戳其实也不一定安全"）。
6. **私有评估**：公司用内部代码库（Google/OpenAI 自有数据），个人可用从未公开过的作品；这对 perplexity 评估尤其有利（只需好的数据集直接评估对数概率）。

### 如何判断一个指标本身好不好
- "目前还没有标准答案"；可做合理性检查：**看它与其他指标的相关性**。例："Alpaca eval 和 Chatbot arenas 的相关性达到了 0.98"，但该相关性只针对特定模型集合，"对于比 GPT4 Preview 更强的模型这个相关性可能就不成立了"。

## 示例或代码

转录为口播课程，无代码；以下为转录中的示例与任务结构：

- **MMLU few-shot 提示结构**："内容大致是下面是一些关于高等数学的问题，然后给出一些上下文中的例子：先是一个问题、一个答案，再一个问题、再一个答案，最后是最终的问题，然后模型需要预测出这个答案"。
- **SWE-bench 任务结构**：输入 = 代码库 + Issue 描述 + 上下文中的代码；输出 = 补丁（patch）；评分 = 目标单元测试是否通过且不破坏其他功能。
- **ARC-AGI 示例**：给一组图片，猜测"接下来会发生什么"，例如"把黄色部分填满，让它形成一个完整的矩形"；任务"每个任务都像一片独特的雪花"，人类约十秒可解、AI 长期得分为零。
- **perplexity 的缺点示例**：句子 "Stanford was founded in 1855"，perplexity 会惩罚所有 token 的预测（包括"1885 这个词"与"founded 这个词"），尽管只有年份是有用的知识。

## 常见误区

- **误区：perplexity 越低模型就越好。** 澄清：perplexity 不区分 token 重要性，会惩罚所有 token 的预测（含句子第一个词、founded 这类没意思的词）；许多以准确率计分的基准（LAMBDA、HellaSwag）本质是"伪装起来的 perplexity"；可用条件 perplexity 聚焦目标 token。
- **误区：排行榜分数高就说明模型好。** 澄清：分数高可能是过拟合基准、数据污染或评估机制漏洞（如 LLM 裁判偏爱长回复导致 Alpaca Eval 排行榜被微调模型刷爆）；"你们对这些数字应该始终持保留态度"。
- **误区：选择题太简单是考试基准的问题。** 澄清："我可以给你出一道非常难的选择题"，选择题本身可以任意难；真正的问题是"选择题限制了你能提出的问题类型"且"根本没法反映真实世界里的使用场景"，"根本没人会拿 HLE 的问题去问语言模型"。
- **误区：Chatbot Arena 的排名是客观真理。** 澄清：用户是谁分布未知（"这有点像狂野西部"），可能有垃圾信息发送者、自提交模型的利益方；二元偏好"把风格和正确性给混在一起了"；还有谄媚问题——更讨人喜欢的答案可能比诚实正确的答案得分更高。
- **误区：测试集没公开 = 安全。** 澄清：HLE 保留了私有测试集"以确保这些数据不会进入训练集"，但仍需把问题通过 API 发给模型，"这些提示不会最终被用于训练，但让我们希望情况确实如此"；"时间戳其实也不一定安全"，代码可能从其他仓库衍生而来。
- **误区：通过所有测试用例 = 正确解决。** 澄清："测试用力（用例）可能是不完整的，所以你可能会通过所有测试用力但解决方案仍然无法正常工作"；TerminalBench 中"如果智能体只是输出一个空响印（空响应）它就能获得大约 38% 的分数"。
- **误区：有个指标就行，不用看输出。** 澄清："你都应该始终查看输出并尝试审计它，以确保你确实认为你测量的是你认为你在测量的东西"。

## 详细章节

### 为什么评估：从抽象到具体指标
- 评估提出的问题：模型"到底有多好"；什么才算好没有唯一答案。
- 三种"好"的视角：基准表现好（Artificial Analysis 智能指数与运行成本的关联）、人们喜欢（Arena AI / Chatbot Arena 的人类偏好排名）、人们愿意付费（OpenRouter 的经济视角）。
- 评估的作用：塑造模型未来的能力边界（"你实际上就在潜移默化地塑造你的模型"），是开发者衡量进展的标尺。

### 困惑度（Perplexity）与同分布评估
- 定义与度量、训练即最小化训练集困惑度。
- 经典同分布范式：PTB、Wikitext、十一词基准；2016 年 CNN+LSTM 大幅降低十一词困惑度的论文被视为"纯粹的神经网络显然是正确的发展方向"。
- 2019 年 GPT-2（WebText 40GB）零样本分布外评估：在 PTB 上得到 35 的困惑度（当时最优 46），"这开启了一个新的思考范式"。
- "信徒"论证与反驳；条件 perplexity；LAMBDA、HellaSwag 是"伪装起来的 perplexity"。
- perplexity 排行榜的信任问题（概率要归一化）、VAE 只能算下界。

### 考试基准测试：MMLU → GPQA → HLE
- 考试范式的好处与起源。
- MMLU：50 学科、知识与推理而非纯粹语言理解；GPT-3 few-shot 几乎只是比随机好一点；到 GPT-4 时代 90+ 分饱和。
- MMLU 升级版（转录语境指更难的变体）：去噪声琐碎题、选项 4→10、用思维链，准确率一度降到 33% 又回升到 88%。
- GPQA（Google-Proof QA）：通过谷歌可搜到就太简单；61 位博士合同工 + 专家验证 + 非专家带谷歌答题的钻石集筛选；博士专家仅 65%，GPT-4 时代 39，后来 94。
- HLE（人类的最后考试）：多模态、众包 + 署名激励、多轮审查 + 前沿模型筛选、保留私有测试集；"每篇数据集论文看起来都差不多"——之前的基准看模型表现多好，我的数据集看所有模型都表现很差。
- 关于数据污染的问答："那你怎么知道这些问题不在训练集里呢？简短的回答是我们不知道"。
- 对选择题形式的批判：可任意难，但限制问题类型、脱离真实使用场景。

### 聊天基准测试与 LLM-as-judge
- Chatbot Arena 的匿名成对比较 + ELO：机制、优点、隐患（用户分布、二元偏好混风格与正确性、谄媚、用户自己也不知道答案）。
- Alpaca Eval（2023）：vs GPT-4 Preview 基线的胜率 + LLM 裁判；裁判偏爱长回复导致排行榜作弊，后以简单回归方法消除偏差。
- 指标本身的评估：与其他指标的相关性（0.98）是合理性检查而非标准答案。
- WildBench：真实对话样本 + 按提示词动态生成的检查清单，把模糊的"好/坏"评估限定范围；与 Chatbot Arena 相关性的循环论证问题。
- 开放式回复评估的方法论：一对一比较优于绝对评分、多裁判（人类+模型）、定义评分标准与检查清单、先做评估审计。

### 智能体评估
- 从"说什么"到"做什么"；智能体 = 语言模型 + 脚手架。
- SWE-bench（含 SWE-bench Verify 背景）：Issue→PR→单元测试；16%→93%。
- TerminalBench：终端环境、通用性、89 个任务；框架影响准确率。
- 网络安全夺旗（40 个任务，标志字符串）。
- MLE 工程：分类竞赛、数据处理与模型训练、提交评分。
- 智能体框架的重要性；评估对象是"语言模型 + 智能体框架"。
- 智能体设计实践：明确规划、分层委托、封装式记忆、显式读写文件、上下文工程。

### 纯推理基准：ARC-AGI
- 动机：把流体智力（推理）从知识/事实中分离。
- 2019 年启动，人类 100% 可解、AI 有挑战；每个任务像独特雪花，无法靠记忆解决。
- 预训练模型时代得分为零；2024 年 O1/O3 后"情况开始突然好转"，"实际上推理能力解锁了这一切"；ARC-AGI-2/3 相继推出，ARC-AGI-3 目前得分很低。
- 反思：是否存在"纯粹推理"仍有争议（"你是不是真的能完全把东西解藕""它同样也受限于人类的推理方式"）；目标限于人类可解，不延伸到超人类推理（IMO 金牌、开放数学难题）。

### 安全评估
- 以汽车碰撞测试类比"安全评级"的来之不易（几十年游说摸索）；AI 安全"没有一个很好的答案"。
- Harm Bench 类基准：用本身带害处的内容提示模型，期望模型拒绝回答。
- 越狱子问题：自动化优化提示词绕过安全机制（GCG 坐标方向优化）；"在开放模型上进行优化可以使这种攻击迁移到其他模型上"。
- 安全性的上下文依赖性（政治、法律、社会规范，各国不同）；风险多样化：幻觉（医疗/法律/金融）、教唆犯罪、不平等、丧失批判性思维；双重用途（网络代理既可入侵也可渗透测试）。

### 评估的广泛考量：生态效度、数据污染与数据集质量
- 生态效度：评估能否反映真实使用；GDP-Valve（OpenAI，前 9 大行业、44 种职业、约 14 年经验的专家出题）、医学临床任务（121 个任务、29 位临床医生，而非标准化考试）；现实性与隐私的矛盾（可让语言模型在保护隐私的前提下分析真实数据）。
- 科学有效性：基础模型之前"别在测试集上训练"很明确；现在模型在互联网上训练、"你并不知道数据里有什么"，使评估变得非常不同。
- 抗污染策略六条（见工作机制）：顺序推断、主动报告、置信区间、立场论文（对模型提供商建模）、"放弃 + 新评估"（截止日期后评估，但时间戳不安全）、私有评估。
- 数据集质量：SWE-bench 未经核实的排行榜（任务非单元测试、测试不严谨）；GSM8K/MMLU 经更仔细审查发现问题；Agentic 基准因涉及完整交互环境而更难评估；测试用例不完整、空响应 38% 得分等琐碎问题；用语言模型检查 Agent 轨迹的定性工具（转录作 "Doent"）；"始终查看输出并尝试审计"。

### 评估的目的：没有唯一答案
- "你得非常清楚它的目的是什么"：购买决策（A/B）、研究者衡量智能、商业/政策利弊、开发者获得反馈改进模型——不同目标导向不同基准或策略组合。
- 评估对象的历史变迁：基础模型之前评估"方法"（算法唯一可变），今天主要评估"模型和系统"。
- 结论：难度、真实性、无污染三者难以兼得，"你不得不在这些因素中选择其中一个做出妥协，而根据你的目标，你必须选择愿意在哪个方面妥协"。
