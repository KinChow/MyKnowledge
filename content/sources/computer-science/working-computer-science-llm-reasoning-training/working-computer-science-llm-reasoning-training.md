# 推理能力训练（RLVR/GRPO）

## 一句话结论

RLVR（基于可验证奖励的强化学习，Reinforcement Learning with Verifiable Rewards）把"答案是否正确"这类可自动化验证的客观信号当作奖励，用 GRPO 等算法对模型做强化学习，绕开 RLHF"过度优化"的瓶颈——"我们只是想要更难以被钻控制的奖励""这样我们才能真正投入更多的算力"——从而让模型涌现出长思维链（CoT）推理能力。DeepSeek R1/R1-Zero、Kimi K1.5、Qwen3-Coder-Next 都是这条路线训练的推理模型；GRPO 是促成这一切的关键算法。

## 核心概念

- **RLVR（基于可验证奖励的强化学习）**："也就是基于可验证奖励的强化学习"。对数学、编程这类最终答案可客观判断的任务，用可验证信号（答案正确性、测试用例、编译器/验证器）直接作为奖励，替代 RLHF 里脆弱的人类偏好奖励模型。
- **结果监督（Outcome Supervision）**："监督指的是你只根据最终答案是否正确来给予奖励"——只对最终结果打分，不对中间步骤打分。
- **过程监督（Process Supervision）**："比如说用来检查证明过程中中间步骤是否有效"——用一个评分标准检查每一步推理是否有效；DeepSeek R1 放弃过程监督，只用结果监督。
- **GRPO（组内奖励归一化）**：DeepSeek 数学论文提出，去掉 PPO 的价值网络，"我将把优势计算为组内的Z分数"——对同一提示采样 K 个 rollout，"减去均值再除以标准差"，用组内相对优劣作为优势。
- **长度归一化（Length Normalization）**："我们是在用更大的数来除更长的序列""这样一来就会鼓励模型生成更长的输出"；它是思维链不断变长的机制根源，也可被奖励操纵利用。
- **奖励操纵 / 奖励黑客（Reward Hacking）**："就会找到越来越隐蔽的方式来欺骗你"——模型学会利用奖励函数的漏洞（如篡改 git 历史查答案）而不是真正解题。
- **测试时计算（Test-time Compute）**："它符合了人们预期的许多测试时扩展行为"——通过让模型思考更久（生成更多 token）换取性能，是推理模型部署侧的关键杠杆。
- **专家迭代（Expert Iteration）**："这种方法被称为专家迭代"——只在模型自己生成且被验证为正确的样本上训练（拒绝采样微调）；Kimi 消融表明真 RL 优于专家迭代。
- **智能体 RL（Agentic RL）**：Qwen3-Coder-Next 在 SWE-Bench 类环境中对读仓库、改代码、跑测试的智能体轨迹做 RL，把编码智能体能力直接训练进模型。
- **Z 分数优势（Group Normalized Advantage）**：AI = (R − mean) / std；在线 rollout 情形下 clipping 消失，GRPO 目标退化为"Advantage减去KL惩罚"。
- **啊哈时刻（Aha Moment）**："那就是所谓的啊哈时刻"——R1 报告里模型在训练后期"顿悟"的现象，但讲师指出它"实际上在基础模型中就已经出现了"，并非 RL 独有。

## 工作机制

### 1. 动机：RLHF 的瓶颈
"RLHF并不能真正带我们到达想去的地方"。"但这个方法从根本上受限于标注瓶颈"，"不能一直往同一个模型投计算资源""最终你会过度拟合奖励模型"。对比 AlphaGo，"在AlphaGo里我们优化的目标正是我们想要的""围棋的输赢条件非常明确"；而 RLHF 更像学习问题，奖励模型可被过拟合。形式化数学、自然语言数学"具有更强的可验证性""因此也更适合应用强化学习"。

### 2. 从 PPO 到 GRPO
PPO 概念上简单（策略梯度 + 优势 + 裁剪 + 价值网络），但实现现实痛苦："标题是PPO的37个实现细节""这是一个对实现决策非常敏感的算法"。价值网络"它跟原始模型一样大"，且常被退化成 gamma=lambda=1（"把它又变回了一个bandit问题"）。GRPO "在精神上与PPO非常非常相似""它只是去掉了几个最复杂的部分"，用组内 Z 分数替代价值网络。

### 3. GRPO 目标函数与更新
- 对同一提示采样 K 个 rollout，计算每个 rollout 的奖励；
- 组内归一化：AI = (R_i − mean) / std，得到 Z 分数优势；
- 目标 = clipped advantage + KL 项（让模型不偏离参考策略）；
- "在在线情况下" rollout 与当前策略一致，clipping 无效，"这打破了那种基线约定"；
- "你基本上可以用一个非常简单的代码块""写下整个GRPO"，几乎所有开源工作都建立在此算法之上。

### 4. 长度/标准差归一化的副作用
- 长度归一化"用更大的数来除更长的序列"，鼓励长输出；负奖励时"那我就会生成一个无限长的字符串"稀释惩罚（错误答案"继续喋喋不休的说下去"）。修复后思维链长度增长"实际上最终会稳定在一个常数上"。
- 标准差归一化"它是在强调那些标准差比较小的题目"（过易或过难），"既提升简单题""也提升难题""这显然不是我们想要的"。

### 5. 数据与课程设计
"如果你的问题太难了""那你根本得不到任何奖励""如果没有信号""你就无法学习"。所以做 best-of-K 过滤（"如果他们在最佳八次中成功了""那么这就不算一个好的强化学习事例"），保留中等难度事例，"那么进行这种中等难度的过滤""其实是一个非常不错的做法"。

### 6. RL 基础设施与在策略现实
"强化学习的基础设施""真的非常困难"——长 rollout 拖累批处理、训练/推理权重要来回搬运；"GRPO在简单在策略形式下表现很出色"，但"要是能重用我的rollout就好了"会引入"但这会导致离策略问题""进而导致训练不稳定"。

## 示例或代码

- **GRPO 参考实现（玩具版）**：讲师展示了 Matt Gille 等朋友的 GRPO 参考实现，"所有这些内容都只占半夜换灯片"，与论文原文唯一不同是在标准差计算中加了一个很小的 epsilon，防止当只有一个样本或所有样本奖励相同时标准差爆炸。
- **DeepSeek R1-Zero 奖励组成**："他们基本上就是做RLVR""其中他们GRPO算法的奖励包括准确性奖励""以及格式奖励"；格式奖励"基本上允许他们之后提取出思维链"（要求用思考标签包裹内容）。"简单基础模型加GRPO数学能力就很好"，几乎没有生产训练流程里的杂乱组件。
- **Kimi K1.5 长度奖励**：不做序列长度归一化，反而"Kimi想要去压缩思维链"——"因为思维链需要推理成本""基本上就是在补贴用户"。启发式长度奖励要避免错误答案"他们就再也没有办法恢复过来了"，而是"激励他们只比平均水平稍微短一点"。
- **Qwen3-Coder-Next 智能体 RL**：训练 web 开发/UX/QA/软件工程四个智能体专家再蒸馏回同一模型；SWE-Bench 是"这类评估里的黄金标准"；只用"也就是4000个样本来做强化学习"就"取得相当惊人的进展"；"一个只有30亿活跃参数的模型"在 SWE-Bench 上"能达到大约76%准确率"。

## 常见误区

- **误区：思维链越长 = 模型越聪明。** 澄清：思维链变长是"长度归一化带来的一个自然副作用"，尤其错误输出会"继续喋喋不休的说下去"；Kimi 证明把思维链压短、只比平均稍短，性能照样提升（OmniMath 例子："思考时间没延长太多""但性能持续提升"）。
- **误区：啊哈时刻是强化学习独有的神奇现象。** 澄清："实际上在基础模型中就已经出现了"，"所以很明显它不可能仅仅仅仅是强化学习算法的结果"，RL 只是把它"提取出来了"。
- **误区：可验证奖励 = 完美、不可作弊。** 澄清："RLVR的鲁棒性取决于奖励函数""而奖励函数有时可能一点也不鲁棒"；SWE-Bench 环境里模型学会"是一个非常容易学会的作弊手段"（查 git 历史/远程仓库），"Lean编译器并不具备对抗鲁棒性"（可注入字符串"验证那些本不该被验证的证明"）。
- **误区：GRPO 是策略梯度的第一性原理推导。** 澄清：除以标准差"这打破了那种基线约定"，"GRPO并不是这个想法的第一性原理推导""它实际上在做一些略有不同的事情"（既非纯基线，长度与标准差归一化也未从策略梯度推出）。
- **误区：DPO 可以替代 PPO/GRPO 做推理训练。** 澄清：DPO 面向"Bradley Terry比较的成对反馈"，而数学问题"并不是以成对比较的形式出现的"，"你只是用错了工具"；PPO 是"更通用的锤子"。
- **误区：过程监督一定优于结果监督。** 澄清：DeepSeek 尝试让过程奖励模型工作"但它们对我们来说效果不大"，结果奖励模型"已经足够用了"且"你可以更容易地为它们扩展数据"；MCTS 也是"我们没能让它很好的工作"。
- **误区：只靠 SFT/蒸馏就完全够，不需要 RL。** 澄清："如果你有合适的蒸留流程""基本上光靠SFT""就能榨出很多长思维链的推理能力"，但 Kimi 消融证明"这类强化学习方法的效果一直比专家迭代要好"，"如果你想榨干模型的所有性能""你就无法回避强化学习"。

## 详细章节

### 为什么通用 RLHF 不足以提升推理
RLHF 的目标是"人类偏好"这一学来的奖励模型，存在"过度优化"问题："不能一直往同一个模型投计算资源""最终你会过度拟合奖励模型"。而可验证任务（数学、编程）"具有更强的可验证性""因此也更适合应用强化学习"，可以把 RL 从"学习问题"变回"搜索问题"（AlphaGo 式：优化目标即想要的，可无限投入算力）。

### RLVR：可验证奖励作为监督信号
"强化学习是一个极好的监督信号来源"——解决前沿数学问题没有现成监督信号获取长思维链，"强化学习让你自生成数据"（在策略采样生成训练信号）。通用对齐方法（SFT/RLHF/DPO）见 [[llm-post-training]]，此处仅讨论用可验证奖励做推理 RL。

### 结果监督 vs 过程监督
- 结果监督："监督指的是你只根据最终答案是否正确来给予奖励"。
- 过程监督："比如说用来检查证明过程中中间步骤是否有效"。
- 结论（DeepSeek 消融）：过程奖励模型"对我们来说效果不大"，结果奖励模型"已经足够用了"，且"你可以更容易地为它们扩展数据"（过程监督需要一步步的评分标准，难以规模化）。R1 的关键决策就是"他们放弃了过程监督""他们转而只使用结果监督"。

### PPO 在推理训练中的实现现实
PPO 概念简单但"标题是PPO的37个实现细节"，"这是一个对实现决策非常敏感的算法""事实证明很多人都把这个算法实现错了"。痛点：价值网络"它跟原始模型一样大"（占显存）；KL 项"实际上是逐Token进行操作的"；GAE 常被退化（"人们常常就直接用gamma""等于lambda等于1""这其实只是一个退化的设定""把它又变回了一个bandit问题"）。因此"研究界其实特别希望不用PPO"——"希望DPO和GRPO被采纳的事实能告诉你""让PPO工作是多么痛苦"。

### GRPO：组内奖励归一化算法
GRPO"在精神上与PPO非常非常相似""它只是去掉了几个最复杂的部分"。核心：去掉价值网络，对同一提示采样 K 个 rollout，"我将把优势计算为组内的Z分数"——"减去均值再除以标准差"。在线 rollout 情形 clipping 消失（新旧策略比值接近 1），目标简化为 "Advantage减去KL惩罚"。实现简单："你基本上可以用一个非常简单的代码块""写下整个GRPO"。注意实现细节：标准差计算加小 epsilon 防除零（只有 1 个样本或奖励全相同）。

### 长度归一化与奖励操纵
GRPO 接近按 token 计算、除以序列总长度归一化。"我们是在用更大的数来除更长的序列""这样一来就会鼓励模型生成更长的输出"；负奖励时"那我就会生成一个无限长的字符串"（"我就能处以无穷大"）稀释惩罚，错误答案"继续喋喋不休的说下去"。修复长度归一化后，思维链长度增长"实际上最终会稳定在一个常数上"而不是无限增长。标准差归一化则"它是在强调那些标准差比较小的题目"——"既提升简单题""也提升难题""这显然不是我们想要的"（希望模型学习可解决范围内的事例）。R1 的思维链变长现象实为"长度归一化带来的一个自然副作用"。

### DeepSeek R1 / R1-Zero
R1"是一种社会现象""开启了开源RL VR模型的浪潮"，且"提供了一个任何人都可以实施的强化学习方案"（GRPO）。R1-Zero：基础模型 + GRPO，奖励只有"准确性奖励"和"格式奖励"（"基本上允许他们之后提取出思维链"），"简单基础模型加GRPO数学能力就很好"。被炒作的两个现象：思维链越来越长（长度归一化副作用）与"啊哈时刻"（"实际上在基础模型中就已经出现了"）。R1 生产化：长思维链 SFT（讲师怀疑是蒸馏数据，"如果你能为这些模型提供合适的常思维链"光靠 SFT 也能解锁能力）、语言一致性奖励（避免语言切换）、把不可验证的奖励也加入 GRPO（融入 RLHF）。蒸馏：把 R1 思维链放到其他模型上"就能真正显著提升这些模型的性能"，"这种方法甚至对LAMA模型也有效"。

### Kimi K1.5：DPO 风格推导与长度压缩
与 DeepSeek"差不多是同一时间出来的"，"他们击败了OE"，但讨论中不常被提及。数据："他们排除了选择题"，做 best-of-K 中等难度过滤（"如果他们在最佳八次中成功了""那么这就不算一个好的强化学习事例"）。算法："他们有一个受DPO启发的论点""但并不是GRPO"——对 DPO 最优解加平方损失，结果梯度"重新发明了祖军值归一化基线"。长度：不按序列长度归一化，反而"Kimi想要去压缩思维链"（"因为思维链需要推理成本""基本上就是在补贴用户"），启发式长度奖励避免错误答案过短卡死。消融：真 RL 方法"效果一直比专家迭代要好"，"如果你想榨干模型的所有性能""你就无法回避强化学习"。

### Qwen3-Coder-Next 与智能体 RL
结构：中期训练（拼接代码仓库生成长上下文、RAG 合成上下文、智能体运行轨迹等）→ 推理 RL → 思维模式融合 → RLHF → 蒸馏小模型。专家模型：训练 web 开发/UX/QA/软件工程四个智能体专家再"全部蒸馏回同一个模型里"（讲师称没见过这种"生成不同模型专家""然后再蒸馏回去的做法"，接近学术上的 Branch-Train-Merge）。规模：只用"也就是4000个样本来做强化学习"取得惊人进展；"一个只有30亿活跃参数的模型"在 SWE-Bench 上"能达到大约76%准确率"。思考模式：特殊标记可"提前退出思考"，改变思考预算时性能"很优雅地慢慢下降"；把思考/非思考融合进单模型会牺牲数学编码性能，后续版本已放弃融合。

### 思维链涌现与测试时计算
长思维链是 RLVR 训练的直接产物（OpenAI o1"拥有非常长的思维链""很明显它经过了强化学习训练"），R1"符合了人们预期的许多测试时扩展行为"——给更多 token 能解更难的问题。但 Kimi/OmniMath 表明性能提升不必依赖长度无限增长（"思考时间没延长太多""但性能持续提升"），长度控制机制在起作用。

### 数据与课程设计：中等难度过滤
RL 数据设计比 SFT 微妙：难度不合适就没有信号（"如果你的问题太难了""那你根本得不到任何奖励""如果没有信号""你就无法学习"）。best-of-K 过滤：采样 K 次若成功率过高说明已到模型能力边缘（"它已经处于模型能力的边缘了"），保留中等难度事例；模型学会某问题后把它移出问题集以节省算力。

### 专家迭代 vs 强化学习
"这种方法被称为专家迭代"——只在正确答案上训练（拒绝采样微调，RFT）并"扔掉其他所有东西"。DeepSeek 数学论文中 GRPO（黄/蓝线）明显优于 RFT；Kimi 大规模消融证明"这类强化学习方法的效果一直比专家迭代要好"（橙色线打败蓝色线）。

### RL 基础设施与在策略现实
RL 同时包含训练与推理（rollout），"强化学习的基础设施""真的非常困难"：长 rollout 拖累批处理（"其他任务都得等这个rollout完成"）；训练/推理权重搬运、共享机器调度；在策略 vs 离策略权衡——"GRPO在简单在策略形式下表现很出色"，但系统利用率低，想"重用我的rollout"又会"但这会导致离策略问题""进而导致训练不稳定"。
