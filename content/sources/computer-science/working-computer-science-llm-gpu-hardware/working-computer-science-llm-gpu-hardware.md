# GPU/TPU 硬件原理

## 一句话结论

现代 LLM 加速器（GPU/TPU）的性能故事，与其说"算得多快"，不如说"数据搬得有多省"。硬件层最核心的事实是：**算力（FLOPS）的增长远超内存带宽与互联速度的增长**（转录：内存带宽"它增长的相对较慢"），因此训练与推理越来越受"内存搬运"约束，本节全部优化本质上都是"减少全局内存（HBM）访问、把数据留在快速 SRAM（寄存器/共享内存/L1）里"。在此基础上，**矩阵乘法是芯片上唯一能高效获取吞吐的特权操作**——GPU 的 TensorCore 与 TPU 的 NXU 都是矩阵乘法单元、底层同为脉动阵列，matmul 比任何其他浮点运算快 10 倍以上，所以每个 ML 加速器都带一个矩阵乘法单元；TPU 与 GPU 是"趋同进化"，高层架构几乎一样，真正的差异只在组件的规模、数量与网络互联，而非芯片本身的逻辑。FlashAttention 正是这一套硬件认知的集大成：分块 + 重计算 + 在线 softmax，把注意力从朴素的多内核/多次 HBM 往返压缩成单内核的 SRAM 内融合计算。

## 核心概念

- **SM（流式多处理器）**：GPU 的基本计算单元。转录称"GPU的基本单元是一个SM……流适多处理器"（streaming multiprocessor，ASR 误写"流适"），每个 SM"有点像是一个核心"、内部有多个流处理器（stream processors）并行执行不同线程。芯片上有大量 SM：A100 有 128 个、H100 约 132 个，每个可独立编程、独立执行不同任务，并可访问芯片外的全局内存。
- **内存层级（寄存器 → 共享内存/L1 → L2 → HBM/全局内存）**：容量从小到大、速度从快到慢。寄存器是最快最本地的存储；共享内存与 L1 缓存读写只需约 20-30 周期；L2 慢得多；全局内存（HBM）"比L1缓存要慢上10倍"。全局内存是程序员通常说的"GPU 内存"（如 H200 的 144GB），物理上位于计算单元外部的内存芯片，而 L2/缓存物理上在芯片内部、离计算单元近。
- **共享内存 vs 缓存**：共享内存是**可编程**的（"你会实际与它交互"），可主动放入/取出数据；缓存是自动的、存最近访问过的数据。二者都是 SRAM，但共享内存是程序显式控制的数据本地化工具，是分块（tiling）的物质基础。
- **高带宽内存（HBM）/ 全局内存**：容量大、速度慢、位于片外的 DRAM，是 GPU/TPU 之间共同的结构（TPU 同样"都有一种慢速内存叫做高带宽内存"）。
- **运算强度（arithmetic intensity）**：每次内存读取所对应的计算量。转录示例：FP32 下"我只有一个Flop的操作量……一个Flop对应八个字节"；低精度把每操作字节数减半，就减少了内存搬运。屋顶线图中要在对角（memory-bound）区域提高运算强度，让计算单元饱和，进入平坦（compute-bound）区域。
- **屋顶线模型（roofline）**："在某个点前会受内存限制"（对角段）+ 之后是"计算限制的平坦区域"；内存越快曲线越高，但瓶颈类型由每个内存单位能配到多少计算决定。
- **分块（tiling）**：把矩阵切成瓦片（tile）加载进共享内存，反复读写、做完计算再写回，把全局内存读取减少到 1/t（t 为分块边长）。
- **脉动阵列（systolic array）**：通过"数据流进流出"完成矩阵乘法的底层电路，GPU 的 TensorCore 与 TPU 的 NXU"使用了相同的底层电路……都采用了所谓的脉动阵列架构"。
- **TensorCore / NXU**：易混淆的命名——TPU 的"流多处理器叫TensorCore"，而 GPU 的矩阵乘法单元也叫 TensorCore；GPU 的 TensorCore 几乎完全对应 TPU 的 NXU（NXU 也是矩阵乘法单元）。因此说"TPU 的 TensorCore"指处理器、说"GPU 的 TensorCore"指矩阵乘法单元，必须按上下文区分。
- **低精度（FP32→BF16→FP8→FP4）**：NVIDIA 投入精力最大的方向之一。P100/V100 后算力超指数增长的一大来源就是数字表示更低位宽；"如果你只有一半的比特……你就只需要移动一半的比特"，既减少内存搬运，也让吞吐翻倍。低精度的难点是"你必须弄清楚你的哪些操作……必须采用哪种数字格式"（如 matmul 的权重/激活可低精度、softmax 需 FP32、指数运算可用 BF16）；FP8 起不再有统一格式（E4M3 四位指数三位尾数 vs E5M2）。
- **控制分歧（divergence）**：GPU 线程遵循"每个线程都必须执行相同的指令"、仅输入不同的模型（SIMT 思路）。遇到条件分支时每个线程都要执行两个分支、不属本分支的线程被屏蔽闲置，造成计算间隙，所以 GPU 代码倾向用"掩码相乘"代替 if。
- **FLOPS 与带宽的剪刀差**：总浮点运算能力增长极快（灰线），内存带宽（绿线）与设备间并行互联速度（蓝线）增长缓慢，"就会看到计算能力和内存之间的差距变得越来越大"——因此"我今天讲的很多优化……都是内存优化"。

## 工作机制

1. **GPU 与 CPU 是两种设计哲学**：CPU 为快速串行执行设计，有大控制单元、少量能算数的 ALU，追求低延迟（"从收到指令到完成的时间要非常短"）；GPU 关注吞吐量，靠"拥有大量轻量级的核心"（数百个计算单元封装在一颗芯片上、全部并行执行）换取巨大的总吞吐，哪怕单个任务完成得不快。这是"横扩展"而非"让时钟更快"（后者 2000 年左右撞上物理墙，即转录里的"Dinar的定律"所指）。
2. **SM 是基本单元，内存层级决定数据怎么放**：GPU 由大量 SM 构成，每个 SM 内部有多个流处理器并行跑线程；SM 连接芯片外部的全局内存（HBM）与芯片内的 L2/共享内存等。为什么不全用共享内存造芯片？因为它贵（转录作"它要跪上几百倍"，"跪"为 ASR 对"贵"的误写）且更耗电，所以"你需要有这种内存层次结构"并有效地利用它。
3. **矩阵乘法是芯片的核心任务**：从 V100 起 NVIDIA 加入专门的矩阵乘法硬件（TensorCore），"一旦这种硬件存在了……矩阵乘法就成了机器学习中……一种特权级的操作"。因为它"比你在GPU上能做的任何其他浮点运算……都要快10倍以上"，是"你真正能有效获得大量计算吞吐量的唯一方式"，所以"芯片的核心任务就是进行矩阵乘法"——这也是任何随算力扩展的 ML 架构都含矩阵乘法单元的原因。
4. **算力跑赢带宽 → 内存成为瓶颈**：GPU 整体计算吞吐增长飞快，"甚至比内存还要快"，于是"内存变得非常重要"，"我们所做的一切都必须尊重内存层次结构……尽可能多地把数据放到共享内存中……而不是全局内存"。推理比训练更极端："推理甚至比训练更受内存限制"；预填充（prefill，转录误写"郁田冲"）重矩阵乘法、计算型，解码部分"更受内存带宽限制"，业界已出现把两者拆到不同芯片的 PD 分离硬件（如把 attention 层和 MLP 层分到不同加速器的尝试）。
5. **屋顶线模型指导写代码**：代码要高效，就要让自身落在屋顶线的平坦段（计算受限、饱和），避免对角段（内存受限）。手段是提高"每次内存读取"对应的计算量——这正是后面六种技巧（低精度、分块、合并、重计算、量化等）的共同目标："尽可能减少内存移动这种风格"。
6. **分块实现数据复用**：把矩阵切成瓦片载入共享内存，"一旦这块瓦片加载好了……我就会反复从它里面读取数据……尽可能多地做计算"。数学上，朴素 n×n 矩阵乘法每个元素从全局读 n 次；用边长 t 的分块后，每个输入先从全局读 n/t 次、块内再读 t 次，全局访问减少 t 倍。
7. **内存合并利用突发窗口**：DRAM 以突发段/行访问为高效单位（选中一列后读整行更便宜），行主序矩阵中沿主索引方向移动的线程不会合并，按列读取会让"我其实只想要其中一列"却读回整块；合并读取能把多次访问合并成对突发段的充分利用。
8. **FlashAttention = 分块 + 重计算 + 在线 softmax**：注意力有三个矩阵乘 + 一个全局 softmax。难点是"因为Morphix是全局操作……把所有分块连在一起"（"Morphix"为 ASR 对 softmax 的误写），无法朴素分块。解法是"在线"计算 softmax（边算边跟踪最大值、指数式在线累加求和），从而逐块计算、保留少量部分累加、最后统一归一化，"最后你就得到了一个融合的结果"——把注意力做成单个内核、数据留在 SRAM，避免 HBM 往返。反向传播用重计算（丢弃 n² 的注意力激活、逐块重算），"使得内存访问次数达到次二次级别"。
9. **硬件感知设计**："他们非常注重硬件感知"，"这需要一直深入到硬件层面"才能理解"我们为什么做这些事情"；不是"盲目搬运32指矩阵乘法器"（转录对某种抽象实现的说法），而是把内存-计算差距作为架构与算法的第一约束。

## 示例或代码

- **低精度与运算强度（算术强度倒数）**：对大小为 N 的向量做一次读、算、写，"那将是每个操作四个字节……总共八个字节的内存访问……我只有一个Flop的操作量……所以那是一个Flop对应八个字节"；如果把精度减半，"每个操作所需的字节数就减少了"，内存搬运随之减少。这就是低精度在"内存"侧的红利（精度侧另有数值问题）。
- **分块的访问计数**：n×n 朴素乘法每个元素从全局内存读 n 次；分块边长 t 时，全局读取变为 n/t 次 + 块内 t 次。极端 t=n："我从全局内存读一次数据……然后在共享内存里访问它n次"——全局内存访问减少 t 倍。
- **A100 的 108 个 SM 与 occupancy（波前量化）**：用 256×128 分块乘 1792×1792 的矩阵得到 98 个分块，"98个分块刚好能放进108个SM里"；升到 1793 后分块变 120 个，"120个分块就放不进108个SM了"，多出的 12 个分块处理时大部分 GPU 空闲，吞吐量骤降——"仅仅因为把分块大小……增加了一"、"就突然需要等待整整一个周期……来处理一批分块"，即"拨前量化"（ASR 误写，指 wave quantization/occupancy 效应）。
- **FlashAttention 的分块可视化（图来自 FA2/FA3）**："虚线框表示在SRAM中……做分块处理的部分……蓝色框表示位于高带宽内存……也就是全局内存中的部分"：QK 内积（分块矩阵乘）→ 结果存 SRAM → 算指数/统计量 → 移到下一分块 → 最终以分块形式与 V 相乘、最后做除法。
- **TPU 与 GPU 的组件数量对比**：H100 "可能有大约132个流多处理器"、矩阵乘法单元"它有528个"；TPU 只有两个并行单元、矩阵乘法单元"只有8个"，且"这些单元在规模上大致是相当的"——TPU 依赖更大但数量更少的 matmul 单元（转录："TPU依赖的是更大""但数量更少的矩阵乘法单元"），GPU 依赖更小但数量更多（转录："但数量更多的矩阵乘法单元"）；前者灵活性低、基本只能做大矩阵乘，后者可编程做各种事（代价：TensorCore 只接受 64 维以上输入，作者论文里做 P 大小扫描"结果就在64那里停住了"）。

## 常见误区

- **误区：GPU 快是因为主频高 / 让晶体管更小更快。** 澄清：2000 年左右频率缩放撞上物理墙（"从基本的物理原理上讲到了一定程度……你确实无法再从越来越小的晶体管中获得好处了"），GPU 的路线是"横扩展"——大量轻量核心并行执行，关注吞吐量而非单任务延迟。
- **误区：GPU 内存 = 全局内存（HBM）的全部。** 澄清：HBM/全局内存只是层级的一端（慢但大，"当H200告诉你它有144GB内存时……你指的就是全局内存"）；真正的高效计算发生在寄存器/共享内存/L1（SRAM）里，"一旦你超出了共享内存的范围……那么操作就会变得非常慢"。
- **误区：TPU 与 GPU 是两种完全不同的东西。** 澄清：两者是趋同进化，高层架构、内存结构（慢速 HBM + 快速本地内存）、矩阵乘法单元都非常相似；"今天我所讲的左边这部分内容……你都可以直接映射到TPU上"，差别在组件规模/数量与网络互联。
- **误区：GPU 的 TensorCore 和 TPU 的 TensorCore 是同一个东西。** 澄清：二者"被命名为完全相同的东西"——TPU 的 TensorCore 指流多处理器（处理器），GPU 的 TensorCore 指矩阵乘法单元，"你必须根据上下文来区分它们"。
- **误区：矩阵乘法单元越多越好。** 澄清：TPU 只有 8 个但很大、GPU 有 528 个但较小，规模相当、可比较；多而小换来灵活性（可编程干各种事），少而大换来对 ML 负载更深的优化。
- **误区：分块大小越大越好 / 随便取都行。** 澄清：分块要能被突发窗口对齐（2 的幂、可被 32 整除更好）；"一旦你开始使用更高的倍数……基本上就不会再有什么性能衰减"，但 16/32 之外再加除数无益；分块大小本身通常交给底层系统（除非写自己的内核）。
- **误区：FlashAttention 是"算法"创新，改的是注意力公式。** 澄清：它"涉及的是整个系统层面的优化"，从"PyTorch朴素注意力实现"变为"一个巧妙融合的单一内核"，本质是分块 + 重计算 + 在线 softmax 的内存优化，"很多性能提升都来自于减少了从HBM……也就是全局内存传输的数据量"。
- **误区：GPU 编程必须手动管理一切、全用 if 分支控制。** 澄清：线程执行 SIMT 模型，if 分支会触发控制分歧、所有线程都要遍历两个分支（部分闲置），GPU 代码倾向用掩码乘法替代 if；但编程模型细节（线程/块/线程束/网格）见独立文档 [[llm-cuda-programming]]，本文档只记录其硬件根源（"每个线程都必须执行相同的指令"）。

## 待验证项

- **CUDA core 的具体数量/命名**：转录只提 SM 内"有多个流处理器"（stream processors），未给出每个 SM 的 CUDA core 数量、也未展开 SM 内部调度器/寄存器堆等微架构细节；SM/CUDA core 的精确构成需对照 [[gpu-overview]] 或硬件手册。
- **HBM 的带宽数值**：转录给了 A100 的延迟基准表（L1/共享内存 20-30 周期、全局内存慢 10 倍）与容量（H200 144GB），但未给出具体带宽数字（如 TB/s），也未给出 FLOPS 峰值数字。
- **TPU 的规模细节**：转录提到"TPU只有两个单元""只有8个"矩阵乘法单元、等效 L 缓存更快，但未指明是 TPU v几、NXU 的精确规模；"脉动阵列"也只点到数据流进流出。
- **波前量化（occupancy）的定量模型**：以 A100 108 SM 的 98/120 分块举例，但未给出"一个 SM 能同时容纳几个块/占用率如何计算"的一般公式（讲师在 Q&A 中坦言"一个区块里有多少个WARPER……得看具体情况"）。
- **FlashAttention 版本差异**：转录引用"Flash Attention 2或者3……我猜应该是2"的可视化图，但未系统对比 FA1/FA2/FA3 的实现差异。
- **Dinar 定律的具体表述**：转录把摩尔/登纳德缩放现象称作"Dinar的定律"（ASR 误写），未展开其具体内容与失效年份。

## 详细章节

### GPU 与 CPU：延迟导向 vs 吞吐导向

CPU"为快速串行执行而设计"，处理复杂分支逻辑、大控制单元 + 少量 ALU，追求"从收到指令到完成的时间要非常短"（低延迟）；GPU 关注吞吐量，"靠的是拥有大量轻量级的核心"，数百个计算单元封装在一颗芯片上并行执行——即使单个任务完成得不快，总吞吐巨大。这种差异源自 2000 年前后频率缩放（转录称"Dinar的定律"）撞墙：晶体管继续缩小但不再跑得更快，于是从"让时钟更快"转向"横扩展"——"让更多的单元……并行地执行你的指令"。

### SM：GPU 的基本单元

"GPU的基本单元是一个SM"（即流式多处理器，转录误写为"流适多处理器"）：一个 SM 像一个核心，是独立的计算单元，内部有子组件（多个流处理器）可并行执行不同线程；"你可以把每个SM几乎想象成一个核心……而GPU有大量的SM"，如 A100 128 个、H100 约 132 个，各自可独立编程、独立执行不同任务，并能访问芯片外部的全局内存。讲师强调"我不希望你把它想象成……NVIDIA Smile上显示的一堆文本……我希望你能在脑海中形象地看到……GPU的硬件是什么样子的"。

### 内存层级：寄存器 / 共享内存 / L1 / L2 / HBM

- **寄存器**：最快最本地的存储（存数组起始/结束地址之类）。
- **共享内存与 L1 缓存**：读取约"只需20到30个周期"；共享内存可编程（主动放入/取出），缓存自动记录最近访问。
- **L2**：芯片内部，但"访问L2缓存会慢得多"。
- **全局内存 / HBM**：位于计算单元外部的内存芯片，"那你知道它比L1缓存要慢上10倍"；"大致就是你作为高级程序员……通常认为的GPU内存"，如 H200 的 144GB。L2 与共享内存等物理上在芯片内、离计算单元近，故延迟好。

### 为什么需要内存层级：SRAM 的昂贵与耗电

既然共享内存（SRAM）这么快，"为什么不直接用共享内存……来构建整个芯片呢"？因为"它要跪上几百倍"（贵几百倍，ASR 误写"跪"）、功耗大得多（"比如SRAM需要一直通电……才能保持住数值……非常耗电"），且必须物理靠近计算单元（信号传播难题）。所以实用加速器"你需要有这种内存层次结构……并有效地利用它"。例外如被 NVIDIA 收购的 Groq（转录作"Grook"）："它的设计就是有大量的SRAM"，对推理工作负载有帮助，但代价"非常非常昂贵"。

### 矩阵乘法为何是核心：TensorCore、特权操作、脉动阵列

V100 时代开始有 TensorCore，"这是重大的硬件创新之一"；此前要用着色器"黑客式"地手动实现 matmul（"我们虽然有这些现成的着色器……但我们可以编写特定的着色器……实际上实现矩阵乘法"）。一旦专门硬件存在，"矩阵乘法就成了机器学习中……一种特权级的操作"：它"比你在GPU上能做的任何其他浮点运算……都要快10倍以上"，是"你真正能有效获得大量计算吞吐量的唯一方式"，所以"芯片的核心任务就是进行矩阵乘法"，任何随算力扩展的 ML 架构都含矩阵乘法单元。硬件实现上，GPU 的 TensorCore 与 TPU 的 NXU"使用了相同的底层电路……都采用了所谓的脉动阵列架构……通过数据流进流出来完成矩阵乘法"。

### 算力 vs 内存带宽：剪刀差与"内存即瓶颈"

三条增长曲线：总浮点运算能力（灰线）极快、内存带宽（绿线，"这是我们传输数据的速度"）较慢、跨设备互联（蓝线）也慢。"现在随着我们越来越往这张图的右边移动……就会看到计算能力和内存之间的差距变得越来越大"——所以"我今天讲的很多优化……都是内存优化"，越往右内存与通信瓶颈越明显。结论是"内存变得非常重要"，一切优化都要"尽可能多地把数据放到共享内存中……而不是全局内存"。推理更极端："推理甚至比训练更受内存限制"，预填充（"郁田冲"）重 matmul、解码"更受内存带宽限制"，业界已出现 prefill/decode 分芯片（PD 分离），甚至把 attention 层与 MLP 层分到不同加速器的尝试。

### 屋顶线模型：memory-bound 与 compute-bound

"这就是屋顶线模型"：对角线部分是内存受限（"说在某个点前会受内存限制"）、之后是"计算限制的平坦区域"。对角线段的含义："每单位内存移动……你有足够的工作量……以至于我可以让我的计算单元完全饱和"；过了转折点，"无论你给我多少额外的工作……那都没用……因为我已经被矩阵惩罚单元完全饱和了"（"矩阵惩罚"为 ASR 对"矩阵乘法单元"的误写）。内存更快时整条曲线被推高。要高效，就应"我们要提高运算强度……每次内存读取……我们做的计算量需要足够高"，把代码推进平坦段、避免对角段。

### 低精度：更少比特、更少搬运、更高吞吐

从 FP32 到 BF16 再到 FP8/FP4，"你只是不断降低数字的精度"；"如果你只有一半的比特……你就只需要移动一半的比特……所以你就减少了内存移动"。算术强度例：FP32 下"每个操作四个字节……总共八个字节的内存访问……我只有一个Flop的操作量……所以那是一个Flop对应八个字节"，降精度即减小每 Flop 的字节数。难点在于逐操作选格式：matmul 的权重/激活可低精度，softmax"可能需要在FP32下进行"，指数运算"也许需要FP32或用BF16也能应付"；低精度训练"花了好几年的时间"、是"缓慢的……渐进的实证工作"。FP8 起无统一格式（E4M3 四位指数三位尾数 vs E5M2），MXP8 等新格式配合 FP32 缩放因子（因指数位太少"你很快就会遇到上亿或下亿的问题"）。

### 控制分歧：SIMT 的硬件代价

所有线程执行同一指令（"每个线程都必须执行相同的指令"），if 分支时"实际上每个线程都会执行EF和Else这两个分支……就会把那个计算屏蔽掉"，部分线程空转造成"很大的计算间隙"——"这就是为什么你真的不想写EF语句的原因之一"，GPU 代码常用"用零相成或者用掩码相成"（"相成"为 ASR 对"相乘"的误写）替代（"乘法能一次性完成……而EF语句可能要等两个时钟周期或类似操作"）。

### 分块（tiling）：把内存访问分组到共享内存

分块是"对性能堆叠的影响……可能最大"的技巧，"就是尽可能利用好内存层次结构"：把空间切成一块块瓦片（tile），每块载入共享内存后反复读取、多算，再写回。朴素 n×n matmul 每个元素从全局读 n 次；分块后"每个输入会先从全局内存读取n除以t次……然后在每个分块内部再读取t次"，全局访问减少 t 倍（t=n 极端："我从全局内存读一次数据……然后在共享内存里访问它n次"）。"你调用的任何矩阵惩罚在底层都会进行分块"（框架自动处理，除非写自己的内核）。分块的坑：分块大小要与突发窗口对齐（可被 32 整除、2 的幂更好），尺寸不可分会导致低效的 padding 等微妙问题。

### 内存合并与突发窗口

DRAM 以行为访问单位（"内存单元是排列成一个网格的"，选中列后读整行更便宜，"读取这一列里多个元素的信息成本……就会比读取上面那个红色区域低得多"）。行主序矩阵中，沿主索引（行）方向移动的线程可合并（"因为它们基本上用满了整个突发段……我充分利用了DRM内存的这个非常好的特性"，"DRM"为 ASR 对 DRAM 的误写），而按列移动则"尽管我其实只想要其中一列"却得读回整块。合并"可以显著改善"内存读取效率，这是"为什么你要告诉我DDRM的小知识"——因为矩阵乘法中某些访问方式比其他规整得多、可利用这一点实现非常快的内存读取。

### SM 数量与 occupancy：98 vs 120 分块的吞吐悬崖

分块数超过 SM 数会触发波前量化（"拨前量化"，ASR 误写）：用 256×128 分块，1792 的矩阵切出 98 个分块，"98个分块刚好能放进108个SM里"；1793 时变成 120 个分块，"120个分块就放不进108个SM了"，多出的 12 个分块处理时"大部分GPU空闲"，"仅仅因为把分块大小……增加了一"、"就突然需要等待整整一个周期"，吞吐量骤降。这解释了课程开头那张 matmul 吞吐量图中的"比如特定尺寸下,矩阵乘法比其他尺寸慢得多"的奇怪现象。

### TPU：更简单、更大的矩阵乘法单元

TPU 是 GPU 的"另一种演化路径"，高层架构趋同进化："最核心的思维差异就是TPU在某种意义上更简单一些……针对机器学习工作负载进行了更深入的优化……拥有更轻量的控制单元以及规模大得多的矩阵乘法单元"。内存结构也相似（慢速 HBM + 快速本地内存"SMAN或者共享内存"）。"真正的区别在于这些组件的规模……大小以及操作的灵活性"，"GPU中的每一个概念……在TPU中都有一个对应的概念……这种映射实际上非常精确"（GPU TensorCore↔TPU NXU）。数量对比：H100 约 132 个 SM、528 个矩阵乘法单元 vs TPU 两个单元、8 个矩阵乘法单元（"这些单元在规模上大致是相当的"）；TPU 依赖更大但数量更少的 matmul 单元（转录："TPU依赖的是更大""但数量更少的矩阵乘法单元"；灵活性低、只做大矩阵乘），GPU 依赖更小但数量更多的单元（转录："但数量更多的矩阵乘法单元"；可编程、灵活）。命名陷阱："TPU的流多处理器叫TensorCore……GPU的矩阵乘法单元也叫TensorCore"，必须按上下文区分。讲师自陈最大的差异其实在网络互联："实际上最大的差异在于网络……而不是单个芯片本身"。

### FlashAttention：硬件感知的融合内核

"Flash Attention是Attention近段时间的一大进步……而且它涉及的是整个系统层面的优化"：从"PyTorch朴素注意力实现"变为"一个巧妙融合的单一内核"，"很多性能提升都来自于减少了从HBM……也就是全局内存传输的数据量"。做法只有两件事——"应用分块和重计算"，"使得内存访问次数达到次二次级别"。难点：注意力是三个矩阵乘 + 一个全局 softmax，"因为Morphix是全局操作……把所有分块连在一起"（"Morphix"为 ASR 对 softmax 的误写），无法朴素分块；关键观察是"在线"计算 softmax——"你一边计算皈依化的Morphs crew……一边进行排序……每次遇到比之前更大的数……就替换掉当前的最大值"（"皈依化的Morphs crew"为 ASR 对"归一化的 softmax"的误写），"跟踪当前最大值……对之前看到的所有东西……做一个指数式的在线累加求和"，"最后你只需要把所有结果……都除以那个在线计算出来的累加器就行了"。于是可逐块计算、保留少量部分累加（存共享内存/寄存器）、"最后你就得到了一个融合的结果"，"尽可能避免来回移动数据"；反向传播用重计算（不保存 n² 的注意力激活，"在反向传播中逐分块……重新计算所有内容"）。它把分块、低精度、在线统计、重计算等全部技巧串成一个内核，是本节"内存即瓶颈"思想的胜利冲刺；"你看到的很多关于高效实现……和如何用好GPU的技巧……归根结底……都是这些想法"。

### 推理硬件格局（简要）：prefill 与 decode 分离

算力-内存差距在推理侧更疯狂：prefill（"郁田冲"，ASR 误写）重矩阵乘法、放一个芯片，decode"更受内存带宽限制"、放另一个芯片；甚至有模型（"我想是Step R3……一个中国的开源模型"）尝试把 attention 层与 MLP 层拆到不同加速器。"如果这个差距扩大……任何利用你非常宝贵的快速内存的巧妙技巧……都会变得非常有价值"——这是未来芯片布局/预算分配的方向（转录 Q&A 中讲师确认这会"影响未来芯片的布局方式"，"或者说可能会影响未来芯片的预算分配"）。
