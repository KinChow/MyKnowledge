# 多模态架构与对齐

> 来源：Stanford CS336（Bilibili 搬运版）P17「多模态对齐，从语言模型走向全模态 AI」（cs336-p17）转录。本笔记专注**多模态的架构与对齐机制**（把图像等非文本模态接入 Transformer、视觉编码器、模态融合/对齐、图像 token 化与分辨率、跨模态数据、多模态训练策略、评估与常见模型演进）。RLHF/DPO 类后训练对齐见 [[llm-post-training]]，本笔记中的"对齐"专指**多模态嵌入空间对齐**。

## 一句话结论

要让 Transformer 处理图像等非文本模态，核心是把图像"Token 化"（离散或连续 token），主流做法是「预训练视觉编码器（CLIP/SigLIP 的 ViT）+ 投影器/适配器 + 预训练 LLM」的拼接式 VLM：训练分阶段，先冻结视觉编码器与 LLM、只训练投影器把图像嵌入映射进文本嵌入空间（即"对齐阶段"），再逐步放开训练；图像分辨率用 AnyRes 的"裁剪分块"思路解决（不降采样），视频/多图靠降低每帧 token、按样本长度归一化损失、拉长上下文（如 156K）来处理；另有一条 Chameleon 的"全离散 token"早期融合路径，优雅但训练不稳定、离散化丢细节且性能不理想，当前最佳实践仍是**连续编码器**（CLIP 问世五年仍是捕捉图像语义的主流方式），生成侧则交给扩散模型。

## 核心概念

- **全模态模型（Omnimodal）**：能接收文本/图像/音频/视频中任意组合的输入，也能输出任意组合。课程开场即定下终极目标："就是可以接收这些模态中的任意组合"+"同时也能输出这些模态中的任意组合"。本课只搭建"这些组件至少能让你处理一点图像"的基础组件。
- **Token 化（Tokenization）**：Transformer 只处理 token 序列。文本已有 BPE 分词器；非文本模态需要"找出一个相当于BPE分词器的东西"，把图像/音频转成离散或连续的 token。一个像素单独看"肯定是没有意义的"，token 应代表"语义上的信息单元"。
- **CLIP（对比语言-图像预训练）**：2021 年 OpenAI 提出，用约 4 亿互联网图像-文本对做对比学习，让匹配对的图像/文本嵌入点积最大。被讲师称为"现代视觉模型的基础"。
- **ViT（Vision Transformer）**：把图像切成 patch（CLIP 用 14×14），每个 patch 就是一个 token，加位置嵌入后过标准 Transformer。CLIP 尝试了 ResNet 与 ViT，"他们发现Vision Transformer的效果最好"。
- **SigLIP**：Google 的 CLIP 改进版（Sigmoid Loss for Language Image Pre-Training）。把 CLIP 的 N 类对比改为逐对二分类，从而把 batch size 与损失函数解耦、可跨设备并行，训练效率高得多。
- **VLM（视觉语言模型）**：把预训练图像编码器输出的向量经投影器注入预训练 LLM，"我们是在把这些图像转换成文本token"，从而复用预训练语言模型，而不是从头训练。
- **投影器/适配器（Projector/Adapter）**：连接视觉编码器与语言模型的桥梁。演进：LLaVA 的线性投影矩阵 W → LLaVA-OneVision 的两层 MLP → Qwen-VL 的交叉注意力（固定 256 维）→ Qwen3-VL 的 DeepStack（把视觉嵌入直接加入语言模型的残差流）。
- **对齐阶段（Alignment Stage）**：VLM 训练第一阶段，冻结视觉编码器和 LLM、只训练投影器 W，"确保图像能够被映射到大致相同的知识空间里"，让图像嵌入"看起来像自然语言的token嵌入"。
- **AnyRes**：LLaVA-1.5 提出的高分辨率思路——把图拆成多个与视觉编码器分辨率一致（如 336×336）的小块分别编码再拼接；"与其做降采样不如直接裁剪图像"，图块过多时插值减少。自适应的，与 Transformer 对任意长度文本的自适应能力对称。
- **多模态 RoPE**：把一维 RoPE 推广到三维（高度、宽度、时间），每个 patch 有坐标三元组，按维度分别算 RoPE 再拼接。Qwen3-VL 发现原实现把时间维度全放在低频、空间维度全放在高频，改为交错排列让所有轴同时接触低/高频。
- **VQ-VAE（向量量化变分编码器）**：2017 年的图像离散化方法——编码为连续向量后"四舍侮辱到最近的编码"（码本如 8000 项，ASR 原文如此，即四舍五入），解码器重建图像；512×512 图 → 1024 个 token，每个 token 来自 8K 词表。
- **Chameleon**：Meta 2024 论文，主张"把所有东西都映射成离散的token"，让文本与图像"真正的生活在同一个空间里"，是"全离散 token"的早期融合路径。

## 工作机制

### CLIP 对比训练（[00:04:32]-[00:13:14]）
1. 对 batch 中每张图用图像编码器得嵌入，每条文本用文本编码器得嵌入，构成 N×N 相似度矩阵（先归一化、再用温度系数算点积）。
2. 目标：匹配对（对角线）的点积远大于该图像/文本与其他所有样本的点积；等价于行向+列向共 2N 个 Softmax 分类问题，最后算交叉熵。
3. 数据：从网上用查询词搜刮图像-文本对，最终约 4 亿对；未公开发布，OpenCLIP 复现并扩展出 LAION-5B（50 亿对），并"用CLIP来做数据过滤"再训练 OpenCLIP（bootstrap）。
4. 预处理启发式：把图缩放让较短边=336px（或 224px），再中心裁剪成正方形——因为神经网络"希望输入是固定大小的"；该设计围绕 ImageNet 分类，物体通常在图像中间。
5. 零样本用法：图像嵌入与一堆文本标签嵌入算点积，取最高分。
6. 备选目标对比：直接从图像预测文本（生成式/语言模型式）"效率要低一些"，因为"实际上精确地去建模描述文本里""对于获得图像的一个粗略表示来说"并不是那么重要。

### LLaVA 两阶段训练（[00:25:42]-[00:27:01]）
1. 阶段一（对齐）：冻结视觉编码器（CLIP ViT-L/14）+ LLM（Vicuna），只训练线性投影矩阵 W。
2. 阶段二：仍冻结视觉编码器，同时训练 W 与语言模型（在自己的图文→文本数据上微调）。
3. 数据：基于 MSCOCO 人工标注（Mechanical Turk 标注边界框+标题），用 GPT-4 基于标题/检测到的物体生成问答、详细描述与复杂推理，共 158,000 个合成样本。

### LLaVA-OneVision 三阶段 + AnyRes（[00:29:26]-[00:33:39]）
1. 升级：视觉编码器换 SigLIP，LLM 换 Qwen2，投影器升级为两层 MLP。
2. 数据/采样策略：单图 = 1 张降采样全图 + 最多 9 个 336×336 裁剪块；多图只用基础分辨率；视频每帧用更低分辨率/更少 token、最多 32 帧。
3. 训练三阶段：阶段一只训投影器（对齐）→ 阶段二训练（引入高质量、偏知识型数据）→ 阶段三训练整个模型（贴近下游任务的数据）。
4. 数据性质：非常任务导向（VQA、表格问答、找两图不同等），毫不掩饰地"基本上就是在蒸馏GPT4模型"来达到最佳性能；属于后训练阶段。

### Qwen-VL 三阶段（[00:36:52]-[00:37:47]）
1. 阶段一（称"预训练"，1.4B 样本，大规模但质量较低）：冻结 LLM，训练**视觉编码器 + 适配器**（与 LLaVA 冻结视觉编码器不同，是特色差异）。
2. 阶段二：高质量、针对特定任务的数据（VQA、图表问答等），训练全部参数。
3. 阶段三：指令微调数据，冻结视觉编码器，训练适配器 + LLM。
4. 特殊 token：Image（图像）、Box（边界框）、Ref（描述）标签。

### Chameleon（全离散 token 路径，[00:53:51]-[00:56:03]）
1. 用 VQ-VAE 把图像映射成离散 token，训练一个新分词器（因为数据类型与自然语言不同）。
2. 训练退化为普通语言模型训练："没有适配器""不需要调整视觉编码器""现在只有一个语言模型"。
3. 两阶段：阶段一大量有监督纯文本+图文数据，阶段二混入高质量数据。

## 示例或代码

- **CLIP 损失（讲师口述的代码部分，[00:05:47]-[00:06:08]）**：图像编码得到一个 N×D 矩阵、文本嵌入得到 N×D 矩阵，归一化后"用某个温度系数来计算点击"，再计算交叉熵，"其中样本是以这种N乘N矩阵的形式组织的"。
- **LLaVA 的"不寻常"例子（[00:27:01]-[00:27:37]）**：输入一张小货车载着衣服的图，用户问"这张图片有什么不寻常的地方"，模型答"你通常不会在小货车的后背上运衣服"；且即使用户提示没有明确指向不寻常处，模型也会提到这一点——当时除 GPT-4 外其他模型做不到。
- **Qwen-VL 的边界框能力（[00:38:07]-[00:38:22]）**：问"你能在图片中找到蜘蛛侠和绿巨人吗"，模型输出边界框（"它实际上并不会输出一张图像"，只输出边界框）；还能做 OCR 识别、图像比较。
- **Chameleon 交错生成（[00:53:25]-[00:53:36]）**：提示"你给我看一些鸟"，模型先生成文本、接着是交错的图像、"然后又是更多的文本和一些图像"，文本与图像在同一序列里交错。
- **Qwen2-VL 动态 token 数（[00:38:54]-[00:39:04]）**：一张大图"可能被映射成一线一千个Token"，一张很小的方程式图片"可能只被映射成八个Token"。

## 常见误区

- **误区：把图像叫成"离散 token"就万事大吉。** 澄清：文本 token 熵低（大多数词某种程度上可预测），图像 token 熵很高（"最终会呈现出哪种蓝色调"）。Chameleon 用混合方式训练"就会导致参数的范数大幅增长""然后就会造成能力上的损失"，需靠 QK-Norm 和 Z-Loss 正则化缓解；离散化也必然丢失信息（OCR 小字"那你就再也无法读取它了"）。
- **误区：CLIP 的向量能用于所有任务。** 澄清：CLIP 是围绕 ImageNet 分类/高层语义设计的（"只要能捕捉到高层羽翼就够了"）；但 OCR 或图像生成"需要非常精细的细节"，这时向量不够，这正是扩散模型擅长的（能"优化低频和高频的信息"）。不存在一个通用的编码器。
- **误区：从图像直接生成文本（生成式目标）比对比学习更好。** 澄清：课程明确"实际上精确地去建模描述文本里""对于获得图像的一个粗略表示来说"并不是那么重要，对比式 CLIP 效率更高。
- **误区：视觉编码器应该和 LLM 一样大。** 澄清："在某种程度上是一个非常局部的操作"，"它只是在观察一个图像块"，所以参数通常不到 10 亿（"而VIT的参数通常不到10亿"），远小于 LLM（如 70B）；"实际上仍然集中在语言模型部分"。
- **误区：高分辨率图像必须降采样。** 澄清：AnyRes 的思路是"与其做降采样不如直接裁剪图像"——拆成多个编码器分辨率的块分别编码再拼接，图块过多时插值减少；对文档/OCR 场景，直接缩放到 336×336 会导致"那你就根本没法读了"。
- **误区：视频 token 多就该多占权重。** 澄清：视频信息密度比文本低（"视频的信息密度肯定比文本要低"），"把文本给压过去"不是好主意。做法包括按样本长度平方根归一化损失（"除以它长度的平方根来做归一化""这样就能降低那些特别长的样本带来的影响"）、按需调整数据混合权重，同时上下文长度要做到 156K 才能容纳长视频。
- **误区：对齐阶段不需要预训练的语言模型。** 澄清："他肯定必须是预训练好的"；对齐阶段语言模型是冻结的，只训练适配器，把给定的视觉编码器和给定的语言模型连接起来（有 token 预算、无自适应阈值）。
- **误区：VLM 能生成图像/视频。** 澄清：课上的 VLM"不生成视频或图像""视频所有的多模态内容都在输入册""你始终是在生成文本"；想生成图像要么加扩散头，要么走 Chameleon 式离散 token 生成，要么用扩散模型本身。

## 待验证项

- GPT-4/Gemini 被宣传为"原生多模态"，但"那当然关于他们具体是怎么构建的"没有公开细节。讲师推测是"用一个连续的编码器""然后再用扩散模型来做生成"的组合方案——**明确是猜测，非事实**。
- CLIP 最佳模型 ViT-L/14 的层数：讲师自述"我记得它大概有24层左右"，并补充"不过这一点我不太确定"。
- Qwen3-VL"进行规一化的损失计算"的具体实现：讲师自述"具体细节其实不太清楚"，只推断是"除以它长度的平方根来做归一化"。
- Qwen 系列后续模型的"数据混合的具体细节其实并不多"，需回看 LLaVA 论文或另一篇移动端论文才有更多细节。
- ASR 对专有名词大量错译：CLIP→Sleepy/CIP、SigLIP→SQLIP/SizeCLIP、Vicuna→VQNET、Qwen→QWIN/Curen、Chameleon→通信/Curen 等，需以官方论文为准核对。
- 多模态 RoPE 在 Qwen3 中被认为"其实有点不太理想"（讲师对 Qwen3-VL 改进动机的解释），具体原因（各维度频率分配）为课程转述，可对照官方技术报告验证。

## 详细章节

### 从语言模型到全模态模型（[00:00:00]-[00:03:18]）
本课原计划讲强化学习，但因"多模态已经无处不在"而改为多模态概述。此前课程只关注语言模型（能由任意文本生成任意文本，甚至 DNA）；终极目标是从语言模型走向"全模态模型"——接收任意模态组合、输出任意模态组合（如"我给你一张图片和一个视频"，再针对它提问）。实现路径的现实约束是："现实就是Transformer的效果非常好""但在所有这些模态上大规模使用时"，"Transformer仍然是我们拥有的最好的东西"。Transformer 为文本设计、只处理 token，因此必须把非文本模态"转换成离散的或者连续的Token"。需要注意的两个问题：如何把非文本数据输入 Transformer、如何把它们生成出来；本课主要聚焦输入侧。

### 视觉编码器：ViT 与 CLIP 的画像（[00:09:54]-[00:12:58]）
CLIP 的视觉编码器尝试了 ResNet 和刚出现的 ViT，ViT 效果最好，通常说的 CLIP 就是 ViT 变体。ViT 工作方式：图像切成 patch（原论文 16×16，CLIP 用 14×14），"每个小块在某种意义上就是Vision Transformer的一个Token"，加位置嵌入后输入标准 Transformer；池化时可用注意力池化（先全局平均所有激活值，再用查询向量对每个位置的键值做另一轮注意力）比直接平均更有信息量。最佳模型 ViT-L/14：大 ViT、约 24 层、14×14 图块、RGB 三通道、在 336×336 上训练（先低分辨率、后高分辨率提速）。位置嵌入尝试了二维版本，"但发现一维版本其实也差不多"，影响不大（在 ImageNet 分类背景下）。文本编码器是 GPT-2 风格的标准 Transformer（CLIP 与 GPT-2 同团队），用末尾 EOS 标记的顶层激活代表整个序列。

### 对比预训练 CLIP（2021，[00:03:21]-[00:17:05]）
背景：GPT-2/GPT-3 进入基础模型时代，计算机视觉传统上依赖 ImageNet 这类大标注数据集 + ResNet + 数据增强；OpenAI 想利用互联网上"大量的图像和文本描述"。CLIP 概念：给一堆图像-文本对，用图像编码器/文本编码器各得嵌入，目标是对齐（点积）远大于与其他所有对，构成 2N 个 Softmax 分类问题，等价于在 N×N 矩阵上做交叉熵。数据：用查询词搜刮约 4 亿对（未公开），OpenCLIP 复现扩展出 LAION-5B（50 亿对，开源），且用 CLIP 做数据过滤（bootstrap）。预处理：缩放较短边到 336px（或 224px）+中心裁剪成正方形。最引人注目的结果（2021 年）："零样本的CIP性能超过了在120万张ImageNet图像上训练过的ResNet"——无需人工标注即可零样本推理。数据噪声大（alt 文本、标题不一定逐字描述图像内容），"所以它居然能工作"，"这确实有点让人意外"。备选方案（直接用图像预测文本）效率更低，因为逐 token 建模描述对获得图像的粗略表示并不重要。技术缺点：需要很大的 batch size（30K 量级），小 batch 不工作，且 N×N 矩阵运算在整 batch 上进行、不易分解。

### SigLIP：二分类与 batch 解耦（[00:17:36]-[00:22:12]）
Google 的论文，全称 Sigmoid Loss for Language Image Pre-Training，本质是"CLIP的一个改进版本"。区别：CLIP 做多类分类（一对正样本 vs 所有备选），SigLIP "基本上就是二分类"——对任何给定的图像-文本组合判断是否匹配，矩阵对角线上是正例、非对角线上是负例，用 sigmoid 损失，目标函数非常简单。数据用 WebLI（数十亿图像-文本对，多语言，对含文本图像做 OCR，并做过滤）。训练效率：CLIP 用 256 个 TPUv3 训练十天，SigLIP 用 32 个 TPUv4 五天完成；单芯片 TPUv4 在该规模下其实慢了约 60%，优势在于一个 Pod 能放更多芯片且互联更好。并行化：跨设备"旋转循环"传递文本块以覆盖所有非对角线负样本（类似 DDP，但样本间存在相互作用、不像语言模型训练可独立处理）。关键收益："有效地将Batch Size与损失函数解有了"——CLIP 损失与 batch 绑定，SigLIP 可用更小 batch（<16K），方差更大但期望损失相同，临界 batch size 约 32K。

### 视觉语言模型 LLaVA（2023，[00:22:33]-[00:27:37]）
与 Qwen 是两类典型 VLM，"在大的框架上"相似、细节不同。基本思想：把预训练图像编码器与预训练 LLM"拼接在一起"，"而不是从头开始训练一个东西"，属"或者后期训练的那种风格"。LLaVA 背景：GPT-4 已能做视觉推理，LLaVA 作为开源模型虽不如 GPT-4 但让人"窥见其内部运作"。组成：视觉编码器用 CLIP（ViT-L/14，14×14 图块）；LLM 用 Vicuna（"微调过的LAMA模型"，对话来自被分享的 ChatGPT 对话）。数据：基于 MSCOCO 人工标注，用 GPT-4 由标题/检测物体生成问答、详细描述、复杂推理，共 158,000 个合成样本。架构：图像经视觉编码器输出向量，因"这个向量和文本向量并不在同一个空间里"，乘一个矩阵 W 映射到文本嵌入空间，与文本嵌入一起作为向量序列直接过标准 Transformer 产生输出——"我们是在把这些图像转换成文本token"。训练两阶段：对齐阶段冻结编码器+LLM 只训 W（"确保图像能够被映射到大致相同的知识空间里"），第二阶段仍冻结编码器、同时训 W 与 LLM。示例：小货车载衣服的"不寻常"图。

### LLaVA-OneVision（2024）：动态分辨率与多图视频（[00:27:41]-[00:35:56]）
LLaVA 之后的 LLaVA 1.5/LLaVA-NeXT 等延续"同样的配方"，野心更大：处理多张图像和视频（"视频本质上就是对应真采样的一系列图像"）。升级：视觉编码器换 SigLIP，LLM 换 Qwen2，投影器从线性投影改为两层 MLP——"系统框架还是差不多的"，只是"把各个部件升级了一下"。OCR 动机：CLIP 把图缩放到 336×336，文档裁剪后"那你就根本没法读了"，故引入 AnyRes：把图拆成多个编码器分辨率的块分别编码再拼接，图块过多时插值减少；"与其做降采样不如直接裁剪图像"。数据平衡：单图 = 降采样全图 + 最多 9 个裁剪块；多图只用基础分辨率（"我就只能从远处大致瞧一瞧了"）；视频每帧更低分辨率、最多 32 帧，避免数据集"被一大堆重复的针给主导了"。数据非常任务导向（VQA、表格问答、找两图差异等），"基本上就是在蒸馏GPT4模型"来达到最佳性能。训练从两阶段变三阶段（只训投影器 → 训高质量知识型数据 → 训练整个模型贴合下游任务）。有意思的发现：跨模态迁移——只有单图图表/OCR 数据却泛化到多图场景（GUI 代理可用），单图视觉提示（图像里圆圈高亮区域）能泛化到视频中；"这些模型似乎能进行一些迁移"。LLaVA 系列优势：少数"还开源数据的项目之一"，可复现研究。

### Qwen-VL 系列：交叉注意力、多模态 RoPE 与 DeepStack（[00:35:59]-[00:46:02]）
Qwen-VL（2023）：视觉编码器用 OpenCLIP（CLIP 的开源复现）；适配器用交叉注意力机制 + 二维位置嵌入，映射到固定 256 维（"现在这样确实不够动态"）；特殊 token 包括 Image/Box/Ref。训练三阶段：阶段一（1.4B 样本）冻结 LLM、训练视觉编码器+适配器（与 LLaVA 阶段一冻结编码器不同）；阶段二高质量任务数据（VQA、图表问答）训练全部参数；阶段三指令微调冻结编码器、训适配器+LLM。能力示例：图像中找蜘蛛侠和绿巨人并输出边界框、OCR、比较。Qwen2-VL：更大视觉编码器 + 动态分辨率（每个 224×224 块用 ViT 编码，2×2 合并以压缩 token，每图块约 66 token，视频每秒采样 2 帧、最多约 1600 token）；引入多模态 RoPE（三维：高度、宽度、时间，每块有坐标三元组，逐维算 RoPE 再拼接）。Qwen3-VL：用 Qwen3（含 MoE 变体）初始化，上下文 156K（"这个长度对于处理长视频来说是非常重要的"）；视觉编码器换 SigLIP2（架构向后兼容），并改进 RoPE——原来每个分量对应不同频率导致时间维度全在低频、空间维度全在高频，"基本上就把它们交错排列了"，让所有轴同时接触低/高频；加入显式的视频时间戳 token（"0秒本身就是一个token"），比隐含在位置编码里更有帮助（可直接引用"R秒之后发生了什么"）；损失上"按每个token的平方根"做归一化以平衡长短样本；适配器用 DeepStack（DeepSeek 团队论文）——"将视觉编码器深度融合到语言模型中的方式"，把视觉嵌入直接加入语言模型残差流，而非黑盒编码器只输出一串向量。训练：预训练四阶段、后训练三阶段，先训适配器，再在 8K→32K→256K 逐步加长序列上训练，后训练含长思维链 SFT、知识蒸馏与强化学习；基准与 Gemini、GPT-5、Opus 4.1 对比，"这些模型实际上相当强大"。

### Chameleon（2024）：全离散 token 的早期融合（[00:52:17]-[00:58:07]）
此前 VLM 把图像编码成向量注入语言模型，作为语言模型只能生成文本、不能生成图像（可附加扩散头）。Chameleon 的想法（Meta 2024）："如果我们把所有东西都映射成离散的token会怎么样"，让文本与图像"真正的生活在同一个空间里"，通过让一切"都向文本来实现的"。实现：用 VQ-VAE（2017 年想法）把图像映射成离散编码——编码成连续向量后四舍侮辱到码本（如 8000 个编码）最近项，解码器重建，靠重建损失+附加项训练（过程不可微）；512×512 图 → 1024 个 token，每个来自 8K 词表；再训练新分词器。训练退化为普通 LM 训练（无适配器、不调视觉编码器、只有一个模型），两阶段（大量有监督纯文本+图文 → 混入高质量数据）。优点："就真正以相同的方式处理了所有模态"，有简洁美感。缺点：训练不稳定——文本与图像虽同处一个空间"但他们的行为方式其实非常不一样"，"那里确实存在一个图像这个事实"；文本 token 熵低、图像 token 熵高，混合训练导致参数范数大幅增长、能力损失，靠 QK-Norm 与 Z-Loss 缓解；"这个模型的实际表现其实并不理想"；离散化丢信息（小字 OCR 不可读）；多模态训练本身棘手（权重调整问题比 Qwen 更严重）。VQ-VAE 曾因 Transformer 需要离散输出而流行于图像生成，后扩散模型"真正可用于生成任务"，此类方法热度下降。

### 总结：理解与生成的对称性（[00:58:13]-[01:00:16]）
如今前沿模型希望支持多模态，甚至"原生多模态或者全能模型"；Gemini/GPT 刚出来时被宣传为原生多模态，但具体构建无细节，讲师猜测是"用一个连续的编码器"+"然后再用扩散模型来做生成"的组合方案（明确是猜测）。最根本的挑战是"你怎么去处理那些不是文本的模态"。模态的理解和生成之间存在对称性，且"并不存在一个通用的编码器"：CLIP 只关心分类/高层语义，向量可很小；OCR 或生成图像需要精细细节，扩散模型能"优化低频和高频的信息"（在微观层面）。处理多模态要"怎么给它们合理的分配权重"——视频信息密度低于文本，别让视频压过文本。当前最佳实践：使用连续编码器（"你看即便是像CLIP这样已经问世五年左右的技术或者类似的概念"，"现在依然是捕捉图像语义的主流方式"），Transformer 仍发挥核心作用，生成侧由扩散模型承担。
