# 专家并行与 4D 并行

## 一句话结论

专家并行（Expert Parallelism，EP）是把混合专家（MoE）模型里的各个专家网络整体分片到不同设备上，靠 all-to-all（全对全）式调度把 token 路由到对应专家，是 MoE 模型下比张量并行（TP）更受青睐的模型并行原语；它与 DP、TP、PP 组合成所谓"三维或四维并行"（DP×TP×PP×EP），编排准则是"尽可能多用数据并行、张量并行保持在 8 以下、专家并行度可以放得很大"。

## 核心概念

- **专家并行（EP）**：把专家网络分片到不同的地方（设备）上，与张量并行相似但分片的粒度是整个 MLP 而非单个矩阵。转录原话："也就是把专家网络分片到不同的地方"。
- **混合专家模型（MoE）**：如今大多数大模型都是混合专家模型；关键事实是"混合专家模型只改变MLP"，完全不改变注意力机制，因此 EP 对模型的应用是不均匀的。
- **路由（Routing）**：MoE 中"Token会被路由到不同的专家"，通信路径不像稠密模型那样规则清晰。
- **all-to-all（全对全）调度**：EP 的通信模式，每次遇到一个 MLP 就要把 token 路由到各种不同的地方，且对延迟极其敏感。
- **专家域（Expert Parallelism 域）**：EP 的并行范围可跨多台机器组成"域"，例如 DeepSeek V3 把 8 台不同机器组合在一起构成 64 路专家并行。
- **4D 并行**：DP×TP×PP×EP 四种并行策略同时使用，转录称"因为你可以同时做4件不同的事"，并说"这就是人们所说的三维或四维并行"，且"我不认为存在所谓的五维并行"。

## 工作机制

### 1. EP 与 TP 的关系及选型

EP 与 TP 在机制上同源：都是在处理网络中的 MLP/FFN 组件，用各种方式拆分并产生通信开销；区别在于 TP 切分矩阵、EP 把整个 MLP 拆分到不同设备。EP 同样属于高带宽的并行化原语，且同样能减少激活内存。

但一旦使用 MoE 模型，应优先选择 EP 而非 TP，理由有二：
- TP 把矩阵切得太细时矩阵变小，GPU 利用率下降；而 EP 保持矩阵乘法尽可能大。
- 对 MoE 层，路由稀疏的 token 激活要比路由密集的大型张量并行矩阵乘法激活容易得多，还能把 token 精确路由到需要的地方并跳过部分开销。

### 2. EP 的通信模式与瓶颈

EP 的实现难点在于"你要进行大量的全对全调度"。每个 MLP 都要把 token 路由到各种不同的地方，且必须以对延迟非常敏感的方式完成，因为计算正在等待 token 到达；减少调度延迟极其重要。这催生了专门的高效底层库，例如 DeepSeek 的 DPP（做专家并行的路由和调度）和 NVIDIA 的 Hybrid AP（为专家并行的调度提供高效底层硬件实现）。

### 3. EP 与 DP 的组合约束

把并行化策略当乐高随意拼装的隐含假设在 EP 处失效。朴素的数据并行+专家并行做法是让两者副本相同：数据并行度为 8 时，把 8 个专家分片到 8 个副本上，数据也拆到这 8 个副本上，即"你根据数据并行来拆分你的GPU，然后你的专家并行就是那个拆分的一个子集"。这样 EP 的并行化程度会有上限，并限制 DP 与 TP 之间的交互方式。这是 EP 相对其他策略多出来的额外约束。

### 4. EP 与 TP 在 MoE 中的解耦

因为 MoE 只改 MLP，EP 只并行化 MLP 而不并行化注意力机制。为了并行化注意力需要高 TP 度，但这会反过来把 MLP 矩阵切碎、利用率变差，形成"注意力想要高 TP、MLP 想要低 TP"的冲突。近年来复杂系统把 MLP 与注意力机制的 TP 解耦：注意力层用一种张量并行，MoE 层用另一种，从而把 EP、TP、DP 有效组合起来。

### 5. 4D/3D 并行的组织与简单法则

从单卡扩展到大规模集群的总体思路：模型放不进内存之前，用一切必要手段切分模型——快速互联内（每台机器 8 块 GPU 的 NVLink 机箱内）用 8 路张量并行或专家并行，跨节点用流水线并行或 FSDP（ZRO3）处理剩余部分；一旦模型能放进去，剩下的就只用数据并行用完剩余 GPU，若批次太小再做梯度累积提高利用率。

转录给出的实践者准则（与稠密模型顺序相反但思路一致）：
- 最小化模型并行、最大化数据并行，尽量用多数 GPU 切分数据。
- 用 GPU 时保持在 NVLink 内（一台机器/一个机箱），专家并行和张量并行在一个机箱内。
- 跨节点用流水线并行实现。
- 若是 MoE 模型，优先选择专家并行。
- 处理长序列时用上下文并行（Ring attention）。

## 示例或代码

（本讲无代码，以下为转录提到的真实模型并行配置案例。）

- **DeepSeek V3（MoE）**：用专家并行替代张量并行，实现了 64 路专家并行，把 8 台不同的机器组合在一起构成专家并行的"域"；为支撑这种大规模 EP，借用了流水线并行中的流水线技巧，确保专家并行不出现利用率低下的时期。
- **Mixtral 8x7B（MoE）**：8 路专家并行 + 4 路流水线并行 + 4 路张量并行（针对注意力层），遵循"专家并行度大致保持在 8 左右"的规则。
- **Qwen3（MoE）**：遵循 DeepSeek 配方，32 路专家并行 + 8 路流水线并行 + 2 路张量并行（用来拆分注意力矩阵）。
- **Nemotron 3 Super**：遵循 DeepSeek V3 模式，有一堆专家并行以及上下文并行（做长上下文扩展）。
- **Llama3 405B（稠密模型，对照）**：主预训练阶段为 8 路张量并行 + 1 路上下文并行 + 16 路流水线并行 + 128 路数据并行；长上下文扩展阶段提高上下文并行、降低数据并行。因是稠密模型，用张量并行而非专家并行。

## 常见误区

- 误区：MoE 模型里 TP 和 EP 可随意替换。澄清：转录明确"如果你在使用混合专家模型，你几乎总是更倾向于使用专家并行的分片策略，而不是张量并行"。
- 误区：EP 只是省参数内存、不影响激活内存。澄清：EP 也是高带宽并行化原语，"同样能减少激活内存"。
- 误区：EP 对模型所有层均匀生效。澄清：MoE 只改 MLP，EP 只并行化 MLP，"我并没有并行化注意力机制"。
- 误区：TP 度和 EP 度可以同时开得很大。澄清：高 TP + 高 EP 会把矩阵切成非常小的碎片，"利用率会非常差"。
- 误区：DP 与 EP 完全正交、可任意叠加。澄清：朴素做法下"专家并行就是那个拆分的一个子集"，EP 并行化程度有上限，且会限制与 TP 的交互。

## 详细章节

### 专家并行的动机与定位

- 现代语言模型普遍为 MoE 架构，token 被路由到不同专家，通信路径不清晰，GPU 全互联网络为此而建。
- EP 属于"标准并行化工具箱"的最后一个组件，与流水线并行（切分层）、张量并行（切分矩阵）并列。

### EP 的原理与通信模式

- 分片对象是整个 MLP/专家网络；与 TP 同属高带宽并行化原语。
- 通信模式为大量 all-to-all 调度，延迟敏感，计算在等待 token 到达。
- 为此出现专用库：DeepSeek DPP、NVIDIA Hybrid AP。

### EP 与 DP 的组合约束

- 朴素做法：EP 副本 = DP 副本，EP 是 DP 拆分的子集。
- 后果：EP 并行度有上限，限制 DP 与 TP 的交互方式。

### EP、TP 在 MoE 层与注意力层的解耦

- MoE 只改 MLP，EP 只并行化 MLP。
- 注意力要高 TP、MLP 要低 TP 的冲突，靠"解耦张量并行"解决。

### 3D/4D 并行与组织准则

- 三维或四维并行 = 组合多种策略外推效率曲线。
- 准则：切分到能放得下为止，NVLink 内用 TP/EP，跨节点用 PP/FSDP，剩余 GPU 全上 DP。

### 真实模型案例

- MoE：DeepSeek V3（64 路 EP）、Mixtral（EP8/PP4/TP4）、Qwen3（EP32/PP8/TP2）、Nemotron 3 Super（EP+CP）。
- 稠密对照：Llama3 405B（TP8/CP1/PP16/DP128，长上下文提 CP 降 DP）。
- 共性规律：最大化 DP、TP≤8、EP 可大。
