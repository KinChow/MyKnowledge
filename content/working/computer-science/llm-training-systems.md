# 训练系统：算力、内存与效率

> 覆盖范围说明：本稿主题为「预训练方法与训练目标」，但 cs336-p02（课程映射为 Lecture 2: PyTorch (einops)）实际是一节系统/性能视角的课，讲的是训练一个步骤到底要多少算力、多少内存、用什么精度、怎么省内存。它**不包含**语言建模目标（next-token prediction、cross-entropy loss、困惑度）与学习率调度的实质内容——授课者自己两度表示"我直接跳过训练循环这部分"。因此凡转录中没有的内容一律写「无」，绝不外推补写。文中双引号内均为单时间戳段内的逐字转录原文（ASR 误差原样保留，如「辅典运算次数」= FLOPs、「张亮」= 张量、「T度」= 梯度），每段引文 ≥12 字符且不跨段。

## 一句话结论

预训练的一个训练步骤（前向 + 反向 + 优化）从系统角度看，计算量约等于 **6 × 数据点（token）数 × 参数量**（即常说的 6ND），其中反向传播恰好是前向的两倍、因为要分别计算关于参数与关于输入的两个梯度；内存方面则要同时装下参数、梯度、优化器状态和激活值四类张量（Adam 每参数约 2+2+4+4=12 字节），因此批量大小、精度选择（bf16 混合精度）、梯度累积与激活检查点共同决定了能否把模型塞进显存、以及训练有多快。这节课是后续讲缩放定律（p09）与并行（p07/p08）的算力/内存账本基础。

## 核心概念

- **浮点精度（fp32 / fp16 / bf16 / fp8 / fp4）**：fp32=1 符号位+8 指数位+23 尾数位，是默认基准；fp16 只有 5 位指数，动态范围差、易下溢上溢甚至产生 NaN；bf16 保持总位数 16 不变，但"把一些位从尾数部分挪到指数部分"，动态范围"实际上和float32的动态范围是一样的"、精度更差，成为现代训练折中首选（"所以bf16可以说是一个折中的最佳选择刚刚好"）。fp8 于四年前引入、有两个版本；fp4（"去年MDAY开发了MVFP4"）是分块量化、按块整体缩放（"而且每个块都可以根据需要进行整体缩放"）。
- **混合精度训练**：一部分计算用一种精度、另一部分用另一种；通用规则是参数/激活/梯度用 bf16，"而对于优化器状态你会使用fp32"（为稳定性）。PyTorch 通过 AMP 自动处理，矩阵乘法等安全运算转 bf16、指数等保留 fp32。
- **FLOPs 与 FLOP/s**：FLOPs（小写 s）= 浮点运算次数，衡量已完成的计算量；FLOP/s（每秒浮点运算次数）= 硬件速度。GPU 规格表给的往往是标称峰值（H100 BF16 密集约 989 TFLOPS），且该峰值是"这个数值是开启稀疏化后的结果"，稠密计算要除以 2。
- **6ND 公式**：一次训练 step 的总 FLOPs ≈ 6 × token 数 × 参数数 = 前向 2·B·P（矩阵乘法=长宽高相乘×2） + 反向 4·B·P（反向恰为前向 2 倍）。转录原文："所以总的辅典运算次数就是2加4等于6"、"也就是6倍的数据点数量乘以参数数量"、"这就是你可能在很多地方看到的那个63D的由来"。
- **MFU（模型 FLOPs 利用率）**："MFU的定义其实就是用实际的每秒辅点运算次数"，再除以标称每秒浮点运算次数。"一般来说如果你在现代模型上得到了大约0.5的MFU"就算不错；纯 matmul 或许能到 0.8，若只有 0.1 说明有大问题。
- **算术强度（arithmetic intensity）**：每传输 1 字节数据能完成多少浮点运算。加速器算术强度 = 每秒 FLOPs ÷ 每秒字节数（"你基本上就是用每秒的浮点运算次数"除以每秒字节数；H100 约 295，"所以你脑子里记住这个直观的数字就好"，直觉取 300）；算法算术强度 = 该工作负载 FLOPs ÷ 移动字节数。若算法强度 < 加速器强度则内存受限，反之计算受限（两者代数等价）。
- **内存受限 vs 计算受限**："当通信时间大于计算时间的时候"就是内存受限（大部分时间在等数据）；"因为你的瓶颈实际上是在进行计算本身"时则计算受限。假设通信与计算可重叠，总时间 ≈ 两者最大值。逐元素运算（ReLU 算术强度"实际上这个值大概是四分之一"、GLU≈5、点积≈0.5）都是内存受限，只有大矩阵乘法（算术强度≈N/3）才计算受限——"矩阵乘法基本上主导了整个计算过程"。
- **训练内存四件套**：参数（bf16 每参 2B）+ 梯度（bf16 每参 2B）+ 优化器状态（fp32：Adagrad 每参 4B、Adam 一阶+二阶矩每参 8B）+ 激活值（"内存的使用量是B乘以D再乘以两倍的L"）。这是 H100 80GB 只能放约 530 亿参数、且激活值未计的粗略来源。
- **梯度累积（gradient accumulation）**：在多个微批次上分别算梯度、累加不清零，每隔微批次大小的步数才更新一次参数再清零，用「小批多次」模拟「大批一次」，不增大单批的激活内存。
- **激活检查点（activation checkpointing / 中物化）**："激活检查点也称为T度检查点或中物化"，前向只保留部分层激活值，反向时"再从上一个检查点重新计算出那些缺失的激活值"，以额外计算换内存；极端时不存任何层则内存最优但计算变 O(L²)，平衡点"是在根号L层的位置来存储检查点"（此时"重新计算的开销也是根号L"）。

## 工作机制

1. **估算一次预训练要花多久（总览示例）**：对"在1024个设备上用15万亿个token去训练一个700亿参数的模型"，用公式 6×参数量×token 数得到总 FLOPs，除以单卡 FLOP/s、除以设备数、再乘以 MFU 折算，得到所需天数（课程示例约为 143 天）。这套资源核算思维贯穿全课：目标"就是尽可能提升训练过程中的计算效率"。
2. **前向传播的代价**：一次线性层前向 = 一次矩阵乘法，FLOPs = 2 ×（数据点数量）×（参数量），即三个维度相乘再乘 2（1 次乘法+1 次加法）。
3. **反向传播的代价**：对每层要算两个梯度——"一个是针对每个参数分别计算的t度"和"另一个则是针对输入计算的t度"，二者各是一次矩阵乘法，故"请注意反向传播的辅典运算次数"，恰好是前向的两倍；对深度网络汇总，前向=2·B·P、反向=4·B·P，合计 6·B·P。"这个近似对transformer也同样适用"，上下文太长会出现"你就会得到上下文长度的平方向"项。
4. **优化步**：计算梯度后用优化器更新参数。以 Adagrad（"这个优化器来自2011年"，"你可以把它看作是介于SGD和Adam之间的一种优化方法"）为例，优化器状态存"也就是所有梯度平方的总和"，更新时"所以我们这里是从优化器状态中获取这个值"、用当前梯度更新、存回，再做归一化除法后更新参数。作业一要求"你需要为每个参数组实现Adam算法"。优化器状态不是计算瓶颈（"优化器状态其实并不是计算方面的瓶颈"），但决定能否塞进内存："优化器状态实际上占用了大量的内存"。
5. **内存账本汇总**：参数 + 梯度 + 优化器状态 + 激活值共同决定单卡能训练多大模型；"激活内存会随着批次大小而扩展"，所以"一般来说你希望使用足够大的批次大小来提高稳定性"（临界批次内容在 p09 展开）。
6. **省内存两招**：梯度累积（"先在这些微批次上分别计算T度"、"然后你只是把这些T度累积起来并不清零"，每隔微批步数更新一次参数并清零，"这实际上是一个非常简单的代码改动"）与激活检查点（"是在根号L层的位置来存储检查点"，使激活内存与重算开销都降到 √L、两者平衡）。
7. **测速纪律**：GPU 异步执行，"尤其是在GPU上必须调用CodeSynchronize"，否则"你会发现你的计时结果快得惊人"，因为"这是因为这是一个非阻塞调用"；好做法是多次尝试取平均，再用 FLOPs÷实测时间得实际 FLOP/s。

## 示例或代码

- **einops / einsum 示例**（p02 主体）：3×4 与 4×3 矩阵相乘，把维度命名为 C1、Hidden、C2，输出由 C1、C2 索引、Hidden 被自动求和——"所以基本上你可以把爱因斯坦求和理解成一种广义的矩阵乘法"。einops 库（"所以INOPS是一个用于操作张亮的库"）的维度有名称；rearrange 示例："想象一下我有一个3x8的矩阵"，用括号把 8 拆成 heads×hidden 再做变换、最后再合并回去，这在语言建模中常用于处理 batch/seq/head 等多维度。
- **线性回归微例**（PyTorch 反向传播机制）：向量点积算 MSE 损失，loss.backward() 后计算图里每个变量有对应梯度（转录作「T度」），W 的梯度被设置为 1,2,3，"这个其实就是Pytorch的基本运行机制"。
- **反向传播 FLOPs 推导**：以第 2 层 H2=H1·W 为例，前向是矩阵乘法（三个维度相乘），反向需算 dLoss/dH1（求和输出维）与 dLoss/dW（求和 batch 维），各一次矩阵乘法，故每层反向=2×前向。
- **数值示例**：
  - 4×8 的 fp32 矩阵 = 32 元素 × 4 字节 = 128 字节；GPT-3 前馈层单个矩阵约 2.3GB。
  - 百万维 bf16 向量过 ReLU：移动 2N+2N 字节、N 次比较；通信时间 1e-6 s ≫ 计算时间 1e-9 s → 内存受限；算术强度 ≈ 0.25。
  - 点积：2N 字节×2 读入 + 2 字节写出，FLOPs≈2N−1，算术强度 ≈0.5，仍内存受限。
  - N×N 矩阵乘法：移动 6N² 字节、计算 2N³ FLOPs，算术强度 ≈N/3，是唯一进入计算受限区的操作（课程示例给 340）。
- **MFU 测法**：算模型需要执行的逻辑浮点运算次数，除以实测运行时间，再除以标称峰值。
- **Adagrad 优化器状态**：存"也就是所有梯度平方的总和"，fp32 每参 4B；Adam 需存"你需要存储1阶矩和2阶矩" = 每参 8B。

## 常见误区

- **误区：FP16 就是现代训练默认精度。** 澄清：fp16 只有 5 位指数、动态范围差，"所以如果你用FP16来训练的话"就会遇到下溢上溢甚至 NaN 的不稳定；bf16 才是在位数与动态范围间的折中，现代普遍用「参数/激活/梯度 bf16 + 优化器状态 fp32」的混合精度。
- **误区：MFU 越高越好、0.5 太低。** 澄清：0.5 在现代模型上已经算不错，0.8 只出现在纯 matmul 情形；若只有 0.1 才说明应当采取行动。MFU 偏低常因内存带宽瓶颈（过承诺的 FLOPs 喂不满）。
- **误区：逐元素/点积等小操作算起来便宜。** 澄清：它们虽然 FLOPs 少，但算术强度极低（ReLU 0.25、点积 0.5），是内存受限的；GLU 再复杂"实际上它的开销完全是一样的"，因为瓶颈根本不在计算本身。
- **误区：fp4/fp8 可以直接调用就能训练。** 澄清：低位宽"都是在底层由NVIDIA的软件站自动完成的"，且 fp4 是分块缩放；直接训练低位模型很难，"通常是先用BF46甚至更高的精度训练一个模型"再量化。
- **误区：小矩阵/小批次会更快。** 澄清：内存受限时把东西做小并不会变快，"如果你的算术强度低于加速器强度"，则减小规模无法让速度变快；这就是要用大批次大小或大矩阵的根因——让加速器饱和。
- **误区：GPU 计时直接包一圈就行。** 澄清：GPU 异步执行，不 synchronize 会得到快得惊人的非阻塞结果，必须设同步点、多次取平均。
- **误区：Transformer 的 6ND 是精确公式。** 澄清：它只在矩阵乘法口径下成立（"这只是通过计算前向和反向传播得出的"），上下文太长会出现平方项；也**不包含**优化步与权重更新的 FLOPs，且与内存成本无关。

## 详细章节

### 总览：缩放定律预告与资源核算思维
开场报告 Marin 项目（约 1e23 FLOPs 的 EFlops 曲线、小模型扫描外推），"而且最终结果确实和预测的完全吻合"、"结果损失值在0.05以内"、"如果你外推到GPT5级别的性能"。随后抛出两个贯穿问题：(1) 1024 卡训 70B 模型×15T token 需多久；(2) H100 上最大可训模型多大（约 530 亿参数，"每个参数需要的字节数是2加2加4加4"）。定调："我们主要想做的就是在有限的资源下训练出我们能得到的最好的模型"、目标"就是尽可能提升训练过程中的计算效率"。

### 张量与精度：fp32 / fp16 / bf16 / fp8 / fp4
一切训练数据都是张量（"张亮就是存储所有数据的基本构建块"，转录作「张亮」）；存储 = 元素数 × 每元素字节。fp32 为默认基准（1+8+23 位）；fp16 位砍半但动态范围差、易不稳定；bf16 "它实际上是在2018年开发的"、把尾数位挪给指数位、动态范围与 fp32 相同，是"所以bf16可以说是一个折中的最佳选择刚刚好"。fp8（四年前引入）两个版本、fp4（NVFP4，去年 MDAY 开发）分块缩放；低位宽量化通常先高精度训练后量化。混合精度 = "而对于优化器状态你会使用fp32"，PyTorch AMP 自动处理。

### einops：面向语言建模的张量编程
einsum（转录「INOPS/AnOps」）把维度命名化，爱因斯坦求和=广义矩阵乘法+记账机制；rearrange 用括号拆分/合并维度（如 8 = heads×hidden），在语言建模中常用于处理 batch/seq/head 多维度；reduce 泛化 sum/min/max。好处：免去 transpose 心智负担、可写模块化代码（用省略号 … 忽略多余维度）。

### 计算量核算：FLOPs 与 6ND
FLOPs（次数，小写 s）与 FLOP/s（速度）的歧义；规格表峰值注意稀疏化÷2。线性层前向 = 2·B·D·K；逐元素=矩阵大小；"矩阵乘法基本上主导了整个计算过程"且是设计使然。H100 标称 vs 实测用 MFU 弥合："MFU的定义其实就是用实际的每秒辅点运算次数"，再除以标称每秒浮点运算次数。

### 算术强度与屋顶线：内存受限 vs 计算受限
加速器算术强度 = FLOP/s ÷ 字节/s（H100≈295≈300）；算法算术强度 = FLOPs ÷ 字节。强度小于加速器则内存受限，大于则计算受限。ReLU(0.25)/点积(0.5)/GLU(≈5)/matvec 全内存受限，只有大 matmul（≈N/3）计算受限，能让加速器饱和。推理逐 token 是 matvec→内存受限，训练整序列是 matmul→计算受限（为推理课埋伏笔）。屋顶线图：低强度区域性能受内存带宽封顶、高强度区域受峰值 FLOPs 封顶。

### 反向传播的代价：2×前向
对每层需"一个是针对每个参数分别计算的t度"与"另一个则是针对输入计算的t度"两个梯度，各一次 matmul；"请注意反向传播的辅典运算次数"，恰好是前向传播的两倍。深度网络合计前向 2·B·P、反向 4·B·P、总计 6·B·P="这就是你可能在很多地方看到的那个63D的由来"；"这个近似对transformer也同样适用"，上下文太长则"你就会得到上下文长度的平方向"。

### 训练内存账本与优化器状态
参数（bf16，每参 2B）、梯度（bf16，每参 2B）、优化器状态（fp32：Adagrad 每参 4B、Adam 每参 8B，因为"你需要存储1阶矩和2阶矩"）、激活（"内存的使用量是B乘以D再乘以两倍的L"，随 batch 扩展）。"优化器状态实际上占用了大量的内存"，但"优化器状态其实并不是计算方面的瓶颈"——它决定放得下放不下，而非跑得快不快。优化步以 Adagrad 为例：状态存"也就是所有梯度平方的总和"、更新后做除法。

### 批量大小、梯度累积与激活检查点
"一般来说你希望使用足够大的批次大小来提高稳定性"（临界批次见 p09），但"激活内存会随着批次大小而扩展"。梯度累积：微批次分别算梯度、"然后你只是把这些T度累积起来并不清零"、隔 N 个微批才更新参数并清零，"这实际上是一个非常简单的代码改动"。激活检查点："激活检查点也称为T度检查点或中物化"，只留部分层激活、反向时"再从上一个检查点重新计算出那些缺失的激活值"，平衡点在"是在根号L层的位置来存储检查点"。

### 课程总结
"这个公式我们现在已经揭开了"——"它就是一个训练步骤的FLP次数量"；矩阵乘法计算受限、其余几乎全内存受限；梯度累积与激活检查点两种方法都可以减少内存占用，从而"你就能使用更大的P次大小了"。
