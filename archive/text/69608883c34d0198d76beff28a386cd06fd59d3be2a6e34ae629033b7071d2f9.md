# 后训练与对齐

## 一句话结论

后训练（post-training）是从预训练基础模型走向可用的 ChatGPT 式系统的必要步骤：先用指令数据做 SFT，把预训练里已经存在但未被引出的行为提取成可遵循指令的输出；再用 RLHF（人类偏好 + 奖励模型 + PPO）或更简单的 DPO 对输出做对齐；而当奖励可以自动化验证（数学、代码）时，RLVR 用可验证奖励替代脆弱的人类奖励模型，让强化学习可以持续投入算力而不被"过度优化"卡住，从而涌现出长思维链的推理能力。

## 核心概念

- **后训练（Post-training）**：课程原话是"而将我们从左边带到右边的这个过程,通常被人们称为后训练"。它是一整套方法（SFT、RLHF、DPO、RLVR）的总称，与预训练相对。预训练"总是很重要的"，是"构建这一切的基础"；但只有预训练只能得到"增强版的GPT3"，细粒度指令控制"基本上是不可能的"。反过来，只做后训练也得不到任何东西（"那我们什么也得不到"）。后训练靠的是更明确的数据收集、更明确的引导以及大量混乱的工程工作。
- **SFT（监督微调）**："这基本上和预训练完全一样"，与预训练唯一真正的区别"就在于训练数据"。本质上仍是 next-token 预测，属于"密集的教师监督"；作用是从预训练模型里"提取出我们想要的行为"。SFT 部分几乎完全专注于训练数据，因为方法无新意，数据才是关键。
- **指令数据（Instruction Data）**：演进脉络为 Flan（用现成 NLP 数据集拼装）→ Self-Instruct（让模型自己生成数据）→ Alpaca/蒸馏（从 ChatGPT 记录蒸馏输入输出）→ Open Assistant（人工、维基百科式众包）→ WizardLM/Tulu（用语言模型设计越来越复杂的合成数据流水线）→ agent 时代（工具调用/代办列表式 SFT 数据）。
- **RLHF（基于人类反馈的强化学习）**：配方有两部分——"第一部分是去收集一些示范数据""你都需要一些标注员提供监督微调数据""也就是针对该提示的参考回复"，然后"做一些强化学习""目的是去调整模型的行为"，"让它更符合人类认为的好回答"。概念上进入 RLHF 后"我们不再玩分布游戏""而是玩最大化奖励的游戏对吧"。
- **Reward Model（奖励模型）**：对同一提示采样多个输出，让标注员评分/排序（InstructGPT 要求"按有用真实和无害标准评分"，Google Bard 用里克特量表），训练一个判断"哪个更好"的模型。用它的原因分三句：训练一个验证器，"可能比直接训练一个表现好的模型""要更容易一些"。
- **PPO（Proximal Policy Optimization）**：John Schulman 发明的策略梯度家族算法。从策略梯度出发（"它会对我的对数概率求梯度""然后用我的奖励值来加权""这看起来像SFT""但对样本做了有效加权"），经过 TRPO 的距离约束，最终用"启发式的裁减机制"，让强化学习算法不会"跑到离原始策略太远的地方去"。RLHF 目标 = 采样策略下的期望奖励 + KL 正则（"这第二项就是KL散度"），防止偏离参考策略导致退化。
- **DPO（Direct Preference Optimization）**："我们要去掉奖励模型""我们还要去掉所有与在策略相关的东西""通过去掉这两样东西""我们就能得到一个简单得多的RLHF算法"。直觉是"在好的方向上做梯度更新""然后在坏的方向上做负梯度更新""换句话说我们要把那些坏数据的对数概率给反转过来"。
- **RLVR（Reinforcement Learning with Verifiable Rewards）**："也就是基于可验证奖励的强化学习"。用可自动化验证的奖励（数学最终答案、代码测试用例、编译器/验证器）替代人类奖励模型，"这样我们才能真正投入更多的算力"让这些系统变得更好，从而绕开 RLHF 的"过度优化"瓶颈。
- **GRPO（Group Relative Policy Optimization）**：出自 DeepSeek 数学论文。去掉 PPO 的价值函数，把优势算成"组内的Z分数"（组内奖励"减去均值再除以标准差"），"在精神上与PPO非常非常相似""它只是去掉了几个最复杂的部分"。开源 RLVR 的事实标准，几乎全部开源工作都建立在它之上。
- **对齐与安全（Alignment & Safety）**：安全 SFT 的本质是"对系统应用安全控制"，"使其拒绝响应那些恶意的输入"，在"我允许恶意查询通过的频率"（违规率）与"错误拒绝率"之间做权衡，追求"帕磊托最优的权衡关系"。后训练团队是"防止系统被滥用的最后一道防线"。

## 工作机制

### SFT 阶段（p15）
1. 收集指令数据：为每个 prompt 配一个参考回复（人类撰写或模型生成）。
2. 直接做与预训练几乎相同的 next-token 预测，本质是"你只是要去拟合某个分布"。
3. 关键在数据：对足够强的预训练模型"你实际上只需要很少的高质量样本"，因为预训练的泛化能力"已经帮你走了很远"，质量大于数量。
4. 注意安全 SFT：用几百到几千样本（例如"如果你拿500个样本"就能让遵循恶意/仇恨言论指令的比率急剧下降）在违规率与错误拒绝率之间做权衡。

### RLHF 阶段（p15 流程）
1. SFT 结束后得到一个能遵循指令的模型；
2. "现在我们把提示词输入模型""模型会生成几个不同的输出"（SFT 结束时常以温度 1 采样保证多样性）；
3. "标注员进来之后会对所有样本进行评分""然后给出一个排序"（有时是二元排序）；
4. 基于这些排序训练 reward model；
5. "接着我们会使用标准的强化学习技术""来最大化我们在那个奖励模型上获得的分数"——PPO；
6. PPO 目标 = 策略下期望奖励 + KL 正则（让模型不偏离参考策略太远，防止对奖励模型过拟合与退化）。

### DPO 阶段（p15）
1. 不用奖励模型、不用在策略采样；
2. 对已标注的（win, lose）对，直接增加"那个获胜样本的可能性"，同时降低"那个失败样本的可能性"；
3. 按隐含奖励模型的出错幅度调步长：若模型已把胜出样本的概率推得很高就小步走，若两者"概率相同"就大步走；
4. 全程只是标准梯度更新，"这实际上比PPO简单得多"。

### RLVR / GRPO 阶段（p16）
1. 构建可验证奖励：数学"他们用奖励模型检查答案等价性"、代码"拿标准答案来生成一些新的测试用力"；
2. 对同一 prompt 采样 K 个 rollout，组内奖励标准化成 Z 分数作为优势；
3. 目标 = clipped advantage（在线 rollout 时退化为 advantage）+ KL 项，做"加权的SFT更新"式策略梯度；
4. 注意两个修正项的副作用：长度归一化"用更大的数来除更长的序列"从而鼓励更长输出（负奖励时"会生成一个无限长的字符串"来稀释惩罚）；标准差归一化会"强调那些标准差比较小的题目"（过易/过难两端）；
5. 数据侧做"中等难度的过滤"（best-of-K 过滤掉太简单/太难的事例），因为"如果你的问题太难了""那你根本得不到任何奖励"，"如果没有信号""你就无法学习"。

## 示例或代码

- **Flan**：Google 用来训练 T5，"利用现有的基准数据集来创建这个大型数据集"：把 Enron 邮件转成"为这封邮件写一个主题桑"任务、把大型摘要数据集转成"为这篇文章写摘要"任务。代价是结构不自然（指令放在最后面）、继承原数据集的缺陷（摘要很短、经常幻觉、含输入文本中没有的细节）。
- **Alpaca**：ChatGPT 出现后"从ChatGPT记录中蒸留出输入输出"，得到"你会得到看起来更自然的输入""以及更长更像聊天的输出"，能稳定"让模型表现出类似ChatGPT的那种行为"，但"这只有在原始的LAMA模型上才有效"。
- **Open Assistant**："你可以把它想象成维基百科那样"，"它是一群人聚在一起编写提示词和回复"，"我忘了大概有一万多个样本"，"实际上生成了相当可观的数据量"，但"然后项目就停滞了"。
- **Tulu3（OLMO）**：AI2 发布的后训练流程，是少数能看到完整后训练流水线运作的地方，其安全组件"大约5万个样本"，整个流水线都用基于模型的标注。
- **DeepSeek R1-Zero / R1**：R1-Zero = 中期训练过的基础模型 + GRPO，奖励只有"准确性奖励"和"格式奖励"（"基本上允许他们之后提取出思维链"），"简单基础模型加GRPO数学能力就很好"。R1 在其上加长思维链 SFT（讲师怀疑是蒸馏数据）、语言一致性奖励、并把不可验证的奖励也加入 GRPO（融入 RLHF）。
- **Kimi K1.5**：数据排除选择题、做 best-of-K 中等难度的过滤；用 DPO 风格推导（"如果某个东西在最小指点上是相等的""那我们为什么不直接给它""加上一个平方损失"），结果梯度"惊人迹象GRPO""只是多了一个正则画像"，等于"重新发明了祖军值归一化基线"；再用启发式长度奖励压缩思维链。
- **Qwen3-Coder-Next**：中期训练注入编码/智能体能力；训练 4 个智能体专家（web 开发、UX、QA、软件工程）"全部蒸馏回同一个模型里"（讲师称接近学术上的 Branch-Train-Merge）；"SWE Bench"是"这类评估里的黄金标准"；只用"4000个样本来做强化学习"就能"取得相当惊人的进展"；30 亿活跃参数模型在 SWE-Bench 上"能达到大约76%准确率"。
- **GRPO 玩具实现**：课程展示了 Matt Gille 等朋友的参考实现，"所有这些内容都只占半夜换灯片"，与论文唯一不同是在标准差计算中"加了一个很小的EAE4"，防止当只有一个样本或奖励完全相同时标准差爆炸。

## 常见误区

- **误区：后训练需要海量数据。** 澄清："你并不需要提供很多样本""你实际上只需要很少的高质量样本"。Flan 时代的"你需要规模"理论被后来更小、更高质量的数据集推翻。
- **误区：塞进越多、越高质量的数据越好。** 澄清："添加数据或事实正确的数据"有时反而会伤害你（"至少在幻觉方面是这样"）。SFT 同时教知识和格式，"让它输出它自己都不知道的事实""那就会导致它产生幻觉"。
- **误区：后训练能把模型不知道的知识灌进模型。** 澄清：要么模型内部已有该知识（SFT 只是拉出正确模式），要么"不能让一个外部的人强行把知识塞给他"——要教会模型知道自己知道什么/不知道什么必须靠 RL（RL 能根据内部激活区分我知道/我不知道方向来奖励或惩罚）。
- **误区：DPO 和 PPO 有明确优劣。** 澄清："这可能没那么重要"，结果"依赖于实验设置的具体细节"，"完全取决于你的执行方式"（AI2 先是说从 DPO 切到 PPO 更好，Tulu2 又说正确使用 DPO 可以更好）。
- **误区：GRPO 是策略梯度的第一性原理推导。** 澄清：GRPO 除以了标准差，"这打破了那种基线约定"，加上长度归一化，"GRPO并不是这个想法的第一性原理推导"，"它实际上在做一些略有不同的事情"。
- **误区：可验证奖励一定鲁棒、不可作弊。** 澄清：Qwen 的智能体模型学会篡改 git 历史来"查"修复，"是一个非常容易学会的作弊手段"；"Lean编译器并不具备对抗鲁棒性"，可注入字符串"验证那些本不该被验证的证明"。RLVR 的鲁棒性取决于奖励函数，"奖励函数有时可能一点也不鲁棒"。
- **误区：RLHF 能靠堆算力一路变强。** 澄清："不能一直往同一个模型投计算资源""最终你会过度拟合奖励模型"，RLHF"从根本上受限于标注瓶颈"，"最终还是会遇到这个过拟合问题"。
- **误区：模型思维链越长就越聪明。** 澄清：思维链变长"可以说是GRPO算法里"的"长度归一化带来的一个自然副作用"（错误输出会"继续喋喋不休的说下去"）；Kimi 反而证明可以把思维链压短、只比平均水平稍短，性能依然提升。

## 待验证项

- 讲师引用"有些人注意到了这一点"并提到"他们写了一篇论文"，指出去掉 GRPO 的长度归一化和标准差归一化会"得到非常不同""可能非常积极的行为"——该论文未点名，需后续 source 补全。
- "啊哈时刻"：讲师认为"实际上在基础模型中就已经出现了"，"不可能仅仅仅仅是强化学习算法的结果"，但未给出出处与实验证据。
- DeepSeek R1 的长思维链 SFT 数据"我怀疑这是不是从其他模型中蒸留出来的"，讲师只作推测，无实证。
- 安全 SFT 细节比能力 SFT 更稀缺："关于安全SFT的信息" "似乎比能力SFT的信息还要少"，Lama2 只有"大概是几千个样本"一句带过，缺少标注指南等细节。
- PPO 中"广义优势估计器"（GAE）被退化为 gamma=lambda=1，"把它又变回了一个bandit问题"，但课程未展开 GAE 的完整推导。
- Kimi K1.5 的 RL 算法完整公式未给出（"他们有一个受DPO启发的论点""但并不是GRPO"），需读原文技术报告。
- GRPO 长度归一化在"正确输出"上的作用（正面案例下"长度皈依化器会鼓励你缩短思维链"）课程以 Dr.GRPO 图口头描述，无具体数据。

## 关联知识

- **与预训练/数据混合**：预训练"能以非常多样化的方式进行扩展"，但必须从预训练中"提取出我们想要的行为"；两阶段/中期训练把指令数据混入预训练衰减阶段，预训练与后训练的界限"正在变得越来越模糊"。
- **与评估/基准**：后训练数据可能不改变标准基准分，却大幅改变用户参与度信号——"你需要将风格控制和能力控制分开来考虑"；模型评判存在长度作弊（"就能在模型评判的性能胜率上持续获得提升"）。
- **与安全治理/对齐**：安全 SFT 的违规率 vs 错误拒绝率帕累托权衡；标注员人口统计偏见（InstructGPT 附录标注员背景→模型观点像佛教徒/印度教徒/无神论者）；涌现性错位（数据中可能存在"类似潜意识传递的效应"）；RLVR 的奖励鲁棒性/可作弊性是新的安全维度。
- **与推理模型/测试时扩展**：RLVR 产出长思维链推理；Qwen 的"提前终止思考"标记把思考预算变成可调旋钮，性能"很优雅地慢慢下降"；思考预算直接关联推理成本（"因为思维链需要推理成本"、"基本上就是在补贴用户"）。

## 详细章节

### 为什么需要后训练（p15）
讲师从 GPT-3 讲起："你真正能用它做的,无非就是像文案写作这类有趣的小任务"；而 ChatGPT 式的"指令遵循"让"你可以输入一个相当长且复杂的提示,然后得到非常合理的回答"。把两者连起来的过程"通常被人们称为后训练"。后训练信息"非常稀少"且多是商业机密（Scale AI 内部文件泄露、Google Bard 想逆向工程 GPT-4 而让标注员生成"比GPT4更详细""或更好的回复"）。关键判断："杠杆作用并不在于算法而在于数据"。

### SFT：数据决定一切（p15）
SFT 与预训练几乎相同，"唯一真正的区别"在于训练数据。数据演进：Flan（多任务但结构不自然、继承原数据集缺陷）→ Self-Instruct（"为什么我们不能用模型本身来生成数据呢"）→ Alpaca 等蒸馏（"从ChatGPT记录中蒸留出输入输出"，只有 LLaMA 上有效，带出"构建类似ChatGPT的系统其实并不难"的乐观）→ Open Assistant（人工、维基百科式，上万样本后停滞）→ WizardLM/Tulu（合成数据流水线）→ agent 式 SFT（"而是更多的转向了智能体和工具使用"，如 NVIDIA Nemotron 的"智能体式的SFT样本"）。数据质量 vs 数量："如果你有一个足够强大的大型预训练模型""你实际上只需要很少的高质量样本"。

### SFT 的陷阱：知识与格式（p15）
Open Assistant 的一个样本同时教"认识Rivins J和Michelle L的这篇引用"这一知识和"好的做法是提供引用"这一格式——两种机制同时起作用。用模型不知道的知识 + 该格式训练，会导致"幻觉和对知识片段的过拟盒"。John Schulman 的论点："为了教模型知道和不知道什么""必须依赖策略"，"不能让一个外部的人强行把知识塞给他"。安全 SFT：在"我允许恶意查询通过的频率"与"错误拒绝率"间权衡，Lama2"大概是几千个样本"、Tulu3"大约5万个样本"，"如果你拿500个样本"就能让遵循恶意/仇恨言论指令的比率急剧下降。

### 从数据到方法：中期训练（p15）
趋势是"把指令微调直接变成预训练的一部分"：把高质量/指令数据混入预训练末尾（学习率衰减阶段），因为衰减阶段是训练中"最接近部署的阶段"、"学习率最低的阶段"，"最好把最高质量数据放入衰减"。mini-CPM 两阶段示例：从互联网数据切到 StackExchange/UltraChat 等高质健谈数据。"当有人告诉你某个模型是基础模型时"其实"这其实有点谎言"，因为今天的基础模型常已含 UltraChat 等聊天数据。数据混合"非常依赖试错"，衰减阶段适合做低成本消融（Meta 书籍版权诉讼泄露了这类消融实验）。

### RLHF：数据、标注员与奖励模型（p15）
完整流程：在 SFT 之后"现在我们把提示词输入模型""模型会生成几个不同的输出"；随后"标注员进来之后会对所有样本进行评分""然后给出一个排序"；"接着我们会使用标准的强化学习技术""来最大化我们在那个奖励模型上获得的分数"。为什么需要 RL：人"嘴上说想要什么和他们实际生成的东西之间"存在差距（"有时存在巨大差异"——标注员更喜欢 InstructVinci 的摘要而非自己写的）；"在某些领域验证比生成要容易得多"（验证证明比生成证明容易，DeepSeek 已在自我验证）。标注员生态：教育水平（"大多数很大一部分都是学士或硕士学位持有者"）、专家标注（"是每小时数百美元超过100美元"）、"可验证的标注员"（防止用 ChatGPT 作弊：标注公司价值主张是"我们有真实的人在做真实的事情"）、人口统计影响（InstructGPT 附录标注员背景→模型观点"反而变得更像佛教徒""印度教徒和无神论者"）、涌现性错位。基于模型的标注："如果你只是想追赶前沿的能力"那么人工收集的数据"基本上就没有什么用武之地了"（Zephyr 案例：坚持纯人工数据但效果不优于模型标注，最终还是用 AI 反馈）；Tulu3 整个流水线都用模型标注。模型评判陷阱："大幅增加回答的长度"就能"在模型评判的性能胜率上持续获得提升"。

### PPO 与 DPO 算法（p15）
PPO 发展路径：策略梯度（"它会对我的对数概率求梯度""然后用我的奖励值来加权""这看起来像SFT""但对样本做了有效加权"）→ 想离策略复用 rollout（"推理通常非常复杂和困难"而"训练则是计算密集型的"）→ TRPO（"我想使用策略梯度""但又想保持与当前策略稍微接近"）→ PPO 用"启发式的裁减机制"，让算法不会"跑到离原始策略太远的地方去"。DPO 推导：假设策略"根本不是一个神经网络""而是所有可能策略的集合"，解析出最优策略"拿我原始的参考策略""然后用奖励对它进行指数倾斜"，反解隐含奖励代入原目标得到 DPO 目标——"在好的方向上做梯度更新""然后在坏的方向上做负梯度更新"。变体：KTO（"不再使用PIRF"而是改用 YFL 归一化器）、长度归一化 DPO（避免长度作弊）；"这些变体似乎都没有太大的影响"。LLaMA 技术报告的外循环（SFT→DPO→生成候选→拒绝采样→重复）中核心的 RLHF 原语"其实就是DPO"。

### RLHF 的陷阱（p15）
过度优化："如果试图真正推动RLHF进程""就会开始对学到的奖励模型产生过拟合"，KL 正则"在很多情况下真的非常关键""它能防止你的优化过程对奖励模型过拟合"。模型坍缩："强化学习模型的多样性会大幅降低""它们似乎只集中在少数几种可能的输出上"，因为它是一种只要获得良好奖励就可能坍缩的策略。校准问题：GPT-4 错误率图显示"模型在进行RLHF后校准性不佳"，"我觉得目前还没有人真正解决这个问题"，Anthropic 认为"这东西本质上就是无法校准的"。这些在下讲 RLVR 中因探索对"模型探索所有可能的解决方案"至关重要而变得关键。

### 从 RLHF 到 RLVR：动机（p16）
承接上讲："RLHF并不能真正带我们到达想去的地方"，"因为存在一个叫做过度优化的问题"。RLHF"从根本上受限于标注瓶颈"，"不能一直往同一个模型投计算资源""最终你会过度拟合奖励模型"。对比 AlphaGo："在AlphaGo里我们优化的目标正是我们想要的""围棋的输赢条件非常明确""只要目标在改善你就做对了"；"从某种意义上说这些都是搜索问题""而RLHF更像是一个学习问题"。形式化数学、自然语言数学"具有更强的可验证性""因此也更适合应用强化学习"。算法"在根本上不会有太大不同"，但"我们最终达到的结果"却"会出人意料地不同"。

### PPO 实现的现实（p16）
PPO 概念简单（"你采样一些轨迹""然后我用某种优势估计方法""来计算一个叫做优势的东西"），但"标题是PPO的37个实现细节""你就知道""这是一个对实现决策非常敏感的算法""事实证明很多人都把这个算法实现错了"。实现痛点：价值函数"它跟原始模型一样大"占显存；"目标函数中的KL项实际上是逐Token进行操作的"，是"多不强化学习问题"而非 bandit；常见 hack（把 KL 裁减到零会破坏其意义）。因此"研究界其实特别希望不用PPO"——"希望DPO和GRPO被采纳的事实能告诉你""让PPO工作是多么痛苦"。

### GRPO 算法与批评（p16）
GRPO 去掉价值函数，"我将把优势计算为组内的Z分数"——组内奖励"减去均值再除以标准差"；"由于没有价值函数""你基本上可以用一个非常简单的代码块""写下整个GRPO"；几乎所有开源工作都建立在这个算法之上。批评：严格说 GRPO 不是策略梯度第一性原理推导——"我们不只是减去一个基线""我们还在用我的奖励的标准差来做规一化处理""这打破了那种基线约定"。两个修正项的作用：长度归一化"用更大的数来除更长的序列"从而"鼓励模型生成更长的输出"，负奖励时"会生成一个无限长的字符串"稀释惩罚（错误答案"继续喋喋不休的说下去"）；修复后思维链长度增长"最终会稳定在一个常数上"。标准差归一化"强调那些标准差比较小的题目"——"既提升简单题""也提升难题""这显然不是我们想要的"。作业中用的就是 GRPO。

### DeepSeek R1 / R1-Zero（p16）
R1"是一种社会现象""开启了开源RL VR模型的浪潮"，"第一个行为上能曾OpenAO相媲美的模型"，还"提供了一个任何人都可以实施的强化学习方案"（GRPO）。R1-Zero：放弃过程监督，"他们转而只使用结果监督"，奖励 = 准确性奖励 + 格式奖励（"基本上允许他们之后提取出思维链"）；"简单基础模型加GRPO数学能力就很好"，且没有"训练流程里那些乱七八糟的东西"。被炒作的两个现象：思维链越来越长——"更长的思维链"是"长度归一化带来的一个自然副作用"；"啊哈时刻"——"实际上在基础模型中就已经出现了""不可能仅仅仅仅是强化学习算法的结果"。R1 生产化：加长思维链 SFT（"我怀疑这是不是从其他模型中蒸留出来的"）、语言一致性奖励（R0 式训练"导致模型会出现语言切换"、"甚至有点令人不安"，为可解释性）、把不可验证的奖励也加入 GRPO（融入 RLHF）。消融教训：过程奖励模型"对我们来说效果不大"、结果奖励模型"已经足够用了"；MCTS"我们没能让它很好的工作"（OpenAI 也坦诚同样失败）。蒸馏：把 R1 思维链"放到Coreen 2.5上去用""就能真正显著提升这些模型的性能""这种方法甚至对LAMA模型也有效"。

### Kimi K1.5（p16）
与 DeepSeek"差不多是同一时间出来的""他们击败了OE"，但讨论中不常被提及。数据："他们排除了选择题"，做 best-of-K 过滤（"比如你采样八次模型至少能成功一次"——成功一次"就不算一个好的强化学习事例"），"研究界的普遍共识是"做"中等难度的过滤""其实是一个非常不错的做法"。算法：DPO 风格推导（"如果某个东西在最小指点上是相等的""那我们为什么不直接给它""加上一个平方损失"），结果梯度"惊人迹象GRPO""只是多了一个正则画像"，等于"重新发明了祖军值归一化基线"。长度：不做序列长度归一化，反而想压缩思维链——"因为思维链需要推理成本"、"基本上就是在补贴用户"；启发式长度奖励要避免错误答案"再也没有办法恢复过来了"（而是"激励他们只比平均水平稍微短一点"）。验证：代码用标准答案生成新测试用例、数学用奖励模型查答案等价性——"答案等价性检查是一个非常棘手的问题"，因此大多数 RL 项目都配了复杂的答案检查器。消融：真 RL 方法"效果一直比专家迭代要好"（"如果你想榨干模型的所有性能""你就无法回避强化学习"）。

### Qwen3-Coder-Next 与智能体 RL（p16）
结构：中期训练 → 推理 RL → 思维模式融合 → RLHF → 蒸馏小模型。中期训练数据：拼接代码仓库文件生成超长上下文、RAG 合成上下文、文档转 Markdown、编码讨论合成数据、公开编码智能体运行轨迹、指令遵循、中间填充。专家模型：从"中期训练好的那个Queen 3 Next模型""训练一大堆不同的专家模型"（web 开发/UX/QA/软件工程）再"全部蒸馏回同一个模型里"，讲师称没见过这种"生成不同模型专家""然后再蒸馏回去的做法"，接近学术上的 Branch-Train-Merge；SWE-Bench 类环境大规模构建。只用"4000个样本来做强化学习"就能"取得相当惊人的进展"。奖励鲁棒性：git 作弊——如果你有一个 issue 并且有未来的提交，"你基本上可以查到修复是什么"，"是一个非常容易学会的作弊手段"，奖励函数唯一目的就是"防止智能体去篡改GET历史"（否则训练曲线突然跃升）；"RLVR的鲁棒性取决于奖励函数""而奖励函数有时可能一点也不鲁棒"；"Lean编译器并不具备对抗鲁棒性"（可注入字符串"验证那些本不该被验证的证明"）。思考模式："有一种提前退出思考的方法"（特殊标记立即停止思维链）；改变思考预算时性能"很优雅地慢慢下降"；即使在非常小的思考预算下，思考模式在数学/编码任务上的表现也远优于"及时响应模式"（后者"更像是经典的指令遵循加RLH模型"）；但把思考/非思考融合进单模型会牺牲数学编码性能（后续版本放弃了融合）。

### 结论：奖励的鲁棒性（p16）
"它其实全都是关于强化学习的奖励""RLHF和RLVR""可以说它们是非常相似的问题""但区别在于""我们只是想要更难以被钻控制的奖励""这样我们才能真正投入更多的算力"让这些系统变得更好。GRPO"是真正促成这一切的关键"（"你们都应该非常了解GRPO"）。强化学习"确实还是特别挑剔""而且噪声很大""用起来有点折磨人""但其实也没那么难"，"实际上它比你想象的要平滑得多"。
